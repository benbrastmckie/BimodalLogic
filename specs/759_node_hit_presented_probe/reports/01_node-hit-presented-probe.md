## Findings

### Codebase Patterns

- **`HitPresented` (Trace.lean:343)** is `HitCl M τ t φ k = ↑(hitOf lab step (clNow φ) k)`; `HitCl` is `HitSig` at the closure instance, `{x | ∃ bf : SeqPair F (τ.state t), InFamily … (clTrace M φ t (spliced τ t bf))}` (Closure.lean:245). `spliced τ t bf := ((seamOmegaEquiv t (τ.state t)).symm bf).1` (SeamMulti.lean:188), so `(spliced τ t bf).state t = τ.state t` is the `.2` of the subtype and every history through the seam is a splice (`symm_apply_apply`). **Consequence: `HitCl` depends on `τ` only through `τ.state t`** — the "canonical history through it" in the dispatch is any of the `m + 1`, and the general-`τ` statement with `hτ : τ.state t = .pre m` costs nothing extra (prototype `spliced_state`, `exists_splice_eq`).
- **Seam classification on `Node`** (prototype `through_pre`, transcribed and sharpened from `Probe758.through_pre`): `σ.state z = .pre m` iff `σ = histOf (m - i) (z + 1 + i)` for a unique `i ≤ m`. Conversely each such history passes through `(t, pre m)` (`canon_through`). Hence (prototype `hitCl_pre`, compiled):
  `HitCl M (histOf m (t+1)) t Φ k = ⋃ i ∈ Finset.range (m+1), familyTriples (clSig Φ) k (clTrace M Φ t (histOf (m - i) (t + 1 + i)))`.
  This replaces model A's `path_classify`/`splice_classify` (≈ 230 lines of rigidity) with ≈ 50 lines, because the fixture is in the library and every history is canonical (`hist_canon`).
- **Trace shape at the pre-seam.** Write `c_i := clTrace M Φ t (histOf (m - i) (t + 1 + i))` and `t' := t + 1 + i`. By `Probe758.truth_transfer` (closure truth is a Boolean combination of `s < t'`, `s = t'`, `t' < s`, `s + 1 = t'`, never of the thread index), there are exactly four letter vectors over the 28 closure letters — `ℓ₂` (relative position `t' - s ≥ 2`), `ℓ₁` (`= 1`, the only class reading `Xp`), `ℓ₀` (`= 0`, the only class reading `p`), `ℓ₋` (`< 0`) — plus the `now` bit at `s = t`. Then
  `c_0 = ℓ₂^(ω*) · [ℓ₁ + now] · ℓ₀ · ℓ₋^ω` and, for `1 ≤ i`, `c_i = ℓ₂^(ω*) · [ℓ₂ + now] · ℓ₂^(i-1) · ℓ₁ · ℓ₀ · ℓ₋^ω`.
  The constant run `ℓ₂^(i-1)` on `[t + 1, t + i)` is the exact analogue of model A's `a`-run `ℓ₀^n` on `(t, t + n]`; the four vectors are pairwise distinct (`Fp` separates `ℓ₂`/`ℓ₁` from `ℓ₀`/`ℓ₋`; `Xp` separates `ℓ₂` from `ℓ₁`; `p` separates `ℓ₀` from `ℓ₋`).
- **The model-A truncation machinery is generic in `sig` and applies verbatim.** `kTypeOf_listSeg_replicate_eventually_periodic_bounded (clSig Φ) k ℓ₂` gives `m₀ p`, `0 < p`, `m₀ + p ≤ Nat.card (KType (clSig Φ) k)`; `familyTriples_subset_deleteRun` (Transport.lean:431) needs `hcont` (containment of the run in ONE segment of every factorization), `hconst` (the run reads `ℓ₂`) and `hper`. `deleteRun c_i (t+1) p = c_{i-p}` is a pointwise check exactly like `deleteRun_clTrace_jump` (relative position `t' - (u + p)` on `c_i` equals `(t' - p) - u` on `c_{i-p}`). Shrinking `c_i` with run length `n + p` (`n ≥ m₀`, `n ≥ 1`) to `c_{i-p}` repeats until `i ≤ W + 1` where `W := Nat.card (KType (clSig Φ) k)`; strong induction as in `hitCl_eq_truncated`.
- **The containment is a fixture fact, with one adjustment.** `W0_le_seam` transfers verbatim (positions `< t` read `ℓ₂`; `t` reads `now ∉ ℓ₂`; keystone `segZ_const_of_kTypeOf_eq_replicate`). The `seam_lt_W1` analogue — the run `[t + 1, t + i)` ends before `W 1` — must take its "nonempty positive segment entirely above" ABOVE `t + i + 1`, not above the run's end, because the two positions `t + i` (`ℓ₁`) and `t + i + 1` (`ℓ₀`) between the run and the `ℓ₋^ω` tail are not `ℓ₋`: cover `t + i + 2` to get `z₁`, then cover `W (z₁ + 1)` to get a nonempty segment `z₂ ≥ z₁ + 1` with `W z₂ > t + i + 2`; it reads `ℓ₋` throughout, fixes `τpos`, and the keystone makes the segment holding `t + i - 1` constant `ℓ₋`, contradicting `Fp ∈ ℓ₂` there. Depth `k ≥ 1` is consumed exactly at the keystone, as on model A.
- **Presentation gadget.** One gadget `QN L := Fin (L + 5)` suffices: `A` (`ℓ₂`, self-loop), `N₀` (`ℓ₁ + now`), `N₊` (`ℓ₂ + now`), chain `C_1 … C_(L-1)` (`ℓ₂`), `O` (`ℓ₁`), `Z` (`ℓ₀`), `P` (`ℓ₋`, self-loop); edges `A→A, A→N₀, A→N₊, N₀→Z, N₊→C_1|O, C_j→C_(j+1)|O, C_(L-1)→O, O→Z, Z→P, P→P`. Model A's two-gadget `Fin 3 ⊕ Fin (L + 3)` is also viable; the single gadget is smaller and its run characterization follows the same pattern (predecessor of every `now` state is `A`; the chain has no loop so a run exits to `O` within `L` steps, cf. `inr_post_threshold`).
