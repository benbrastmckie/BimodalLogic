## Key Decisions

- Both proofs were elaborated standalone through the build guard against a scratch probe BEFORE
  being written into the tree, and both compiled first try from the plan's own prescribed tactic
  pipelines. No search tool and no goal-state iteration was needed.
- `drift_lipschitz_two_sided` carries its one-sided `Nat` induction as an inner `have hone`
  rather than as a second named declaration, so the phase adds exactly the two declarations the
  plan's Goals name.
- The pin family is `fun v => if pend (w v) = false ∧ pend (w (v + 1)) = true then some (c (v + 1))
  else none`, passed to `drift_extension_of_pins` directly; `classical` alone sufficed and no
  `DecidablePred` instance was needed.
- The `hn₀` discharge needs `drift_lipschitz_two_sided` in TWO-SIDED form, not one-sided: the
  register value at `0` sits on either side of the pin position `v`.
- Signature fidelity was verified positively, not by eyeballing: a probe restates both
  `## Lean Challenge Statements` signatures verbatim and discharges each with the landed
  declaration applied to its own binders. Both type-check, so binder explicitness and argument
  order match token for token.

## Deviations

- **`longFile` baseline raised to 3100, not the plan's 3400.** Lean's `longFile` linter requires
  the baseline to EQUAL the file's round-up to the next hundred, not a forward-looking ceiling; a
  `3400` baseline at 2,968 lines emits `The current limit is 3400, but it is expected to be 3100`
  and introduces a new build warning into a previously warning-free module. The in-source comment
  records that the baseline now tracks the file across the cascade's phases. **Later phases must
  bump it as they grow** rather than finding it already at its final value.
- **A third file changed: `typst/generated/status.typ`.** The phase commit was refused by
  `git-commit-scoped.sh`'s pre-commit typst-sync gate, because this phase's line-count change
  staled that generated artifact's `formalsystem-line-count` and `tests-line-count` fields. The
  drift is attributable to this commit, so the hook's foreign-writer bypass did not apply and
  `bash scripts/typst-sync-check.sh --fix` plus staging the file was the sanctioned remedy.
  **Every later phase of this plan that edits a `.lean` file will hit this same gate** -- read the
  per-phase `Files to modify` lists as implying it.
