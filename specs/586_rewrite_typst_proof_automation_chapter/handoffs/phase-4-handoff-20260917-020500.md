## Addendum: a second CI-gate blocker, found and fixed after this handoff's first draft

Re-verifying the gate after the `.github/workflows/ci.yml` step landed (via the concurrent
commit noted above) surfaced a second, genuinely CI-breaking issue on the committed tree: a
different concurrent task (`089f35fe0`, "Migrate to lakefile.toml") renamed `lakefile.lean` to
`lakefile.toml` and updated `p4-dataset-pipeline.typ`'s footnote text to cite the new name, but
`` `lakefile.toml` `` does not resolve under Check 1: its path-like-candidate detection recognized
`.lean`/`.md`/`.sh`/`.typ` suffixes but not `.toml`, so the citation fell through to
bare-identifier resolution (grep inside `*.lean` files), which a TOML file can never satisfy --
even though the file plainly exists, tracked, at the repo root, and every other extension's
citations already resolve via exactly that repo-root existence check.

Fixed at the root cause in `scripts/typst-sync-check.sh` (added `.toml` to the path-like suffix
tuple) rather than with a whitelist entry, since a whitelist entry would suppress only this one
string while the underlying gap would resurface for any future `.toml` citation. This is the
same script this phase already extended in the module-map Check 2b sub-check (Phase 1), so the
edit stays within work this task already owns. Re-verified via a third detached worktree at the
new HEAD: `PASS (all 3 checks green)`.
