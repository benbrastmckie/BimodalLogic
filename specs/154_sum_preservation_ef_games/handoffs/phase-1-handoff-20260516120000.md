## Root Cause Analysis (Updated)

Two independent blockers prevent closing the extend_CompData helper:

### Blocker 1: ite in Types After subst
After `cases h : j' = j` (or `subst h`), the goal contains `if j' = j' then cd.sz j' + 1 else cd.sz j'` in TYPE positions (NormalForm arguments). No tactic can reduce this:
- `simp only [ite_true]` only reduces `ite True`, not `ite (j' = j')` — simp doesn't rewrite `j' = j'` to `True` inside types
- `rw [if_pos rfl]` fails with "motive is not type correct" in dependent types
- `dsimp` and `show`/`change` fail because `ite (j' = j') a b` is not definitionally equal to `a`
- `▸` with `if_pos rfl` only rewrites the FIRST occurrence and can't compute motive for complex dependent terms

The `dite` (for eM/eN) CAN be reduced by `dite_true`/`dif_pos rfl`, but the `ite` (for sz) cannot.

### Blocker 2: CompData.bound Too Strict
The CompData.bound field requires `sz j < budget` (strict). After extending, `sz j = cd.sz j + 1`. The bound `cd.sz j + 1 < budget` requires `budget >= cd.sz j + 2`, but only `cd.sz j < budget` (i.e., `budget >= cd.sz j + 1`) is available. The `hdn : d + 1 + n <= budget` in build_bicompat does NOT imply `cd.sz j + 1 < budget` because `cd.sz j` could equal `budget - 1`.
