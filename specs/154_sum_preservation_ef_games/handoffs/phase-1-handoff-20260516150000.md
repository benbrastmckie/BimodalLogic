Neither `dsimp` nor `simp` can reduce it.

## Root Cause Analysis

The CompData structure has this field dependency chain:
```
sz : I → Nat
eM : (j : I) → Fin (sz j) → (ms j).carrier     -- depends on sz
eN : (j : I) → Fin (sz j) → (ms' j).carrier     -- depends on sz
agree : ∀ j, ∀ nf : NormalForm sig (budget - sz j) (sz j), ...   -- depends on sz, eM, eN
bound : ∀ j, sz j < budget                       -- depends on sz
consistent : ... → ∃ q : Fin (sz j), eM j q = ... ∧ eN j q = ...  -- depends on sz, eM, eN
```

When `sz j'` is defined via any form of `j' = j` branching (ite, dite, match, Decidable.rec),
the branch IS OPAQUE in Lean 4. No tactic can reduce `ite (j' = j)` to its then/else branch
when the `Decidable` instance comes from `DecidableEq I` (which is opaque, whether from
`instDecidableEqOfLinearOrder` or any other source).

## Recommended Path Forward

**Option D (most promising): Use `Classical.dec` instead of `instDecidableEq`**

`Classical.dec` is defined as:
```lean
noncomputable def Classical.dec (p : Prop) : Decidable p := Classical.choice ...
```

Unlike `instDecidableEq`, `Classical.dec` might be reducible by `simp`/`dsimp` with the right lemmas. Test whether `simp only [Classical.dec]` or `dsimp [Classical.dec]` can reduce `if (Classical.dec (j' = j)) then X else Y`.

If `Classical.dec` is also opaque, then:

**Option E: Restructure CompData to avoid dependent branching**

Split CompData into:
- `CompData_j`: the j-th component data (sz_j, eM_j, eN_j, agree_j, bound_j)
- `CompData_rest`: the non-j component data (uses cd fields directly)

Then the extension only modifies `CompData_j` (incrementing sz_j, consing to eM_j/eN_j) without any branching. A wrapper function combines `CompData_j` and `CompData_rest` into a full CompData using classical decidability.

**Option F: Change CompData to use non-dependent types**

Replace `eM : (j : I) → Fin (sz j) → ...` with `eM : (j : I) → Nat → Option (ms j).carrier` (partial function). The `agree` field would then only assert agreement for valid indices. This avoids Fin (sz j) entirely.
