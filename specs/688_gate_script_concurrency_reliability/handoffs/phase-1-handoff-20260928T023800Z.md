## What NOT to Try

- Do NOT run a bare `git stash` (or `git stash pop`) on this shared working tree while concurrent
  sibling tasks are dispatched. It stashes the ENTIRE tree, including siblings' uncommitted work
  in unrelated task directories and shared files (TODO.md, state.json, events.jsonl), and a
  `stash pop` can then conflict with a sibling's fresh edit made while the stash was held,
  stranding everything in the stash. If isolation of a single file's baseline is genuinely needed,
  use `git show HEAD:<path>` (read-only) or `git diff <path>` instead of stashing, or restore
  narrowly from the stash via `git show stash@{N}:<path> > <path>` for only the paths this task
  owns — never a blanket pop/apply. See progress file `phase-1-progress.json`'s
  `approaches_tried` entry for the concrete incident.
- Do not add `flock -u` after the C1 builds — it is deliberately omitted so later `.lake`-reading
  checks inherit the lock (see Key Decisions above).
