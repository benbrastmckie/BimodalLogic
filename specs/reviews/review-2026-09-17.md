## Low Priority Issues

### Stale README date stamps across the recently reorganized tree

**File**: 44 files reported `STALE DATE`, 3 reported `MISSING DATE` (full list below); scope is
`FormalSystem/**/README.md` (47 of 60 READMEs total)
**Description**: `scripts/readme-lint.sh`'s date-freshness check compares each README's stamped
date against `git log`'s last-changed date for its directory. The last several days of directory
reorganization (Syntax/Semantics language-family nesting, Metalogic import-cycle repair,
`WorldHistory` retarget, evidence-probe repairs) touched these directories without refreshing
their README date stamps, and three READMEs under recently-created/renamed directories
(`Conservativity/Star/`, `Verified/Termination/MintBound/`, `Syntax/StarLanguage/`) never
received a date stamp at all.
**Impact**: None on build or CI (the check is advisory-only, `RESULT: PASS`). The impact is
purely on developer trust in README freshness as a signal — a reader has no way to tell, from
the stamp alone, whether a given README reflects the directory's current state.
**Recommended fix**: One pass updating each listed README's date stamp to the current date (or
to the actual last-substantive-change date if that is preferred), and adding a date line to the
3 files currently missing one. Purely mechanical; no prose content review implied unless a
stamp update surfaces genuinely stale prose while editing.
