# Repository Sweep Report

**Date**: 2026-09-16
**Scope**: Whole-repository hygiene sweep of the Lean file tree and its supporting apparatus,
following the completion of the `FormalSystem/` directory-organization work. Covers: the gated
invariant harness, every standalone check script, the compiler-warning surface, CI coverage,
git-tracking hygiene, documentation reachability and freshness, and drift against the paper of
record.
**Reviewed by**: Claude

## Summary

The gated invariants are in excellent shape and nothing below contradicts them. Every finding
lives in the space those gates do not cover — which turns out to be a large and consequential
space, because **six of the repository's check scripts are wired into nothing**, and four of
them are currently failing.

**Headline finding, stated first because it explains every other one**: `ci.yml` is 65 lines and
runs `lean-action` (build/test/lint) plus a loop over the `lean_exe` roots. It does not run
`check-module-invariants.sh` — that script appears in the workflow **only inside a comment**
(line 48). Nor does it run `check-copyright-headers.sh`, `check-metalogic-cycles.sh`,
`check-evidence-probes.sh`, `check-paper-definitions.sh`, `readme-lint.sh`, or
`typst-sync-check.sh`. The repository has built a serious, well-documented verification
apparatus and then left almost all of it as a developer command that has to be remembered. Four
of those scripts are red right now, and two of them have been red for over a month.

## Critical Issues

### C1. Four evidence probes left version control entirely when their task was archived

**Files**: `scripts/check-evidence-probes.sh`, `specs/archive/417_semantic_fmp_finite_worldstate_over_z/evidence/`

**Description**: The four wired bi-lasso evidence probes lived under
`specs/417_semantic_fmp_finite_worldstate_over_z/evidence/`. Commit `a6439fcae`
("todo: archive 3 completed tasks") moved that task directory to `specs/archive/`, which
`.gitignore:73` excludes. The four `sorry`-free probe files therefore left git: they existed only
on the local disk and were absent from any fresh clone. `check-evidence-probes.sh` still pointed
at the pre-archive path and failed 4-of-4 on every run with `FAIL (missing: …)`.

**Impact**: This is the exact failure the guard was written to prevent, arriving by a route the
guard did not anticipate. The script's own header says a probe failure means "a recorded design
obstruction no longer compiles" and instructs the reader not to delete or weaken it. Meanwhile
the probes were not merely unchecked but *gone*, and nothing announced either fact because the
script is not in CI. A probe outlives the task that produced it by construction — it records a
design obstruction, not a unit of work — so filing one inside a task directory was the root
cause.

**Fixed during this sweep**: the five probe files (four wired, one deferred) were moved to
`specs/evidence/bi-lasso-decision-layer/`, a task-independent tracked location parallel to
`specs/reviews/`. `check-evidence-probes.sh` was repointed and its header now records why probes
must not live under a task directory.

**Still open** (→ separate task): with the path repaired, all four probes now resolve and **none
compiles**. The drift is from the `FrameClass`/`TemporalOrder` refactor — for example
`FiniteFilteredTaskFrame`'s first argument moved from a `Type` to a `TemporalOrder`, so
`FiniteFilteredTaskFrame ℤ phi` no longer elaborates, and `FormalSystem.Semantics.TaskFrame.step`
no longer exists. Roughly 30 distinct errors across the four files.

## High Priority Issues

### H1. A second directory-level import cycle appeared in `Metalogic/` and has been there 99 commits

**Files**: `FormalSystem/Metalogic/Conservativity/Plus/Corollaries.lean:8`,
`FormalSystem/Metalogic/Deterministic/Soundness.lean:9`, `FormalSystem/Metalogic/README.md:73`

**Description**: `scripts/check-metalogic-cycles.sh` exits 1: it asserts exactly one
directory-level cycle and finds two. The documented one is `BXCanonical ↔ WeakCanonical`
(9 + 5 import lines). The new one is `Conservativity ↔ Deterministic`, created by exactly two
lines:

- `Conservativity/Plus/Corollaries.lean:8` → `FormalSystem.Metalogic.Deterministic.Completeness`
- `Deterministic/Soundness.lean:9` → `FormalSystem.Metalogic.Conservativity.Plus.PlusSoundness`

Both landed in commit `5bd08ce1a` (2026-09-08), 99 commits before this sweep.

**Impact**: `FormalSystem/Metalogic/README.md:73` states "There is exactly one directory-level
cycle in `Metalogic/`" and cites this very script as the thing that establishes it. That claim is
false today. More substantively, `docs/architecture/ADR-006-Metalogic-No-Physical-Regroup.md`
declined a regroup of `Metalogic/` partly *because* of how expensive the one existing cycle makes
any move; a second cycle raises that cost again, and it was acquired without a decision.

**Recommended fix**: This needs a judgment call, not a mechanical edit. Two import lines is a
small enough surface that breaking the cycle is plausibly cheap (the usual move is to lift the
shared dependency into a third directory both can import). The alternative — accepting a second
cycle and re-baselining the script from 1 to 2 — is legitimate but must be a recorded decision
with the same costing ADR-006 applied, not a silent threshold bump. Whichever is chosen,
`Metalogic/README.md:73` and the ADR need updating in the same change.

### H2. The paper of record renamed vocabulary the Lean tree is built on

**Files**: `specs/paper-definitions-of-record.md`, `FormalSystem/Semantics/`, `FormalSystem/Syntax/`,
`FormalSystem/Metalogic/Conservativity/`

**Description**: `scripts/check-paper-definitions.sh` reports 16 of the recorded definitions
drifted in the upstream JPL paper, plus one anchor (`thm:M5-valid`) that no longer resolves at
all. Most of the sixteen are reflow or phrasing, but three are substantive:

| Paper (pinned) | Paper (live) | Live tree still says |
|---|---|---|
| "converse convention" | "**reflection** convention" | 35 prose occurrences; `FrameOver.converse` (9 sites) |
| metarule `\aref{TD}` | metarule `\aref{TR}` | `TD` across ~14 files; "temporal duality" ×77; `swapTemporal` ×925 |
| `\past` "Past" / `\future` "Future" | "Some Past" / "Some Future" | derived-operator naming throughout |

There are zero occurrences of "reflection convention" anywhere in the repository. Several
definitions also moved from "is the smallest extension of X closed under…" to "extends X to
include…", which is a proof-theoretic phrasing change rather than a cosmetic one. And `def:BX`
acquired a long footnote attributing each axiom to Burgess (`TG`, A1a–A7a) or Xu and naming the
six that are the paper's own additions — provenance with no counterpart in
`ProofSystem/Axioms.lean`.

**Impact**: The repository's whole citation apparatus (C15's 58 paper-anchor citations,
`specs/paper-definitions-of-record.md`, the typst `SYNC-MAP.md`) rests on the tree and the paper
speaking the same language. They now do not, on a term that appears ~1,000 times.

**Recommended fix**: A decision on each of the three renames (adopt, or record a deliberate
divergence), then a mechanical rewrite for whichever are adopted, then re-pin the record. The
`swapTemporal` count means the `TD → TR` decision in particular should be made before, not
after, anyone starts editing. `thm:M5-valid` needs re-resolving against the paper's new
structure.

### H3. Six check scripts are wired into nothing, which is why H1, C1 and M1 went unnoticed

**Files**: `.github/workflows/ci.yml`

**Description**: See the headline above. `check-module-invariants.sh` — 26 checks, ~3,300 lines,
the phase gate the whole tree's documentation cites — is referenced in `ci.yml` only as prose
inside a comment on line 48. The other five standalone checks are referenced nowhere outside
their own files and the docs that describe them.

**Impact**: Every structural guarantee the repository documents is, in practice, enforced only
when someone remembers to run a command. The evidence of the cost is in this report: H1 has been
red for 99 commits, C1 for however long since `a6439fcae`, and M1 since the 2026-09-07 tactic
retirement.

**Recommended fix**: Add the scripts to `ci.yml` as separate steps. The build-dependent ones
(`check-module-invariants.sh` full, `check-evidence-probes.sh`) can reuse the cache the
`lean-action` step already populates, exactly as the existing "Compile `lean_exe` roots" step
does. Note that two of the six will fail on the first CI run by design
(`check-paper-definitions.sh` reads a paper in a repository CI cannot see, and must be made
skip-on-absent rather than fail-on-absent), so the wiring needs per-script consideration of what
"red" should mean.

### H4. 316 compiler warnings in the live build, and nothing gates them

**Files**: 47 live `.lean` files

**Description**: `lake build` succeeds with 316 warnings. `env_linter` (C16) does not see Lean
compiler warnings, so no gate covers them.

| Kind | Count |
|---|---|
| Unused `simp` argument | 84 |
| Unused auto-included section variable | 84 |
| `push_neg` deprecated → prefer `push Not` | 71 |
| "tactic does nothing" | 25 |
| Unreferenced variable names | ~20 |
| "this tactic is never executed" | 9 |
| `Try this: intro …` suggestions | 7 |
| `IsTrichotomous`/`IsIrrefl` deprecated → `Std.*` | 4 |

Concentrated in `Decidability/Verified/Termination/SubformulaProperty.lean` (78),
`WeakCanonical/DenseModelSurgery/BadIntervals.lean` (36), `Semantics/TaskFrame.lean` (20),
`DenseModelSurgery/Lemma34.lean` (19), `RealModel/DoetsTheorem.lean` (16).

**Impact**: The 71 `push_neg` and 4 `Std.*` deprecations are forward-compatibility debt against
the next Mathlib bump — they will become errors. The "tactic does nothing" and "never executed"
warnings (34 total) are stronger signals: each marks a tactic whose removal changes nothing,
which usually means a proof has drifted from the shape its author intended.

## Low Priority Issues

### L1. 1,029 declarations have zero occurrences outside their own declaring line

**Description**: C17's dead-declaration scan, approximate and explicitly never gated, reports
1,029 such declarations. It has never been triaged. Sampling suggests real candidates — the
`*_fold` / `*_unfold` cluster in `Automation/Normalization.lean` (`release_unfold`,
`top_fold`, `diamond_fold`, `next_fold`, …) has ten consecutive entries. The scan is textual and
will have false positives (simp-set members, instances, `lean_exe` entry points), so this is a
triage job, not a delete job.

### L2. Build artifacts were tracked in git

**Description**: Six LaTeX `.log` files under `latex/` and `latex/subfiles/`, plus two
`scripts/__pycache__/*.pyc` files, were tracked. `.gitignore` carried `indent.log` — a single
filename, not a pattern — and acquired `__pycache__/` only after the `.pyc` files were already
committed, which does not untrack them. **Fixed during this sweep.**

Two related observations left as-is deliberately: `specs/298_…/logs/c7.log` (3.1 MB) is the
largest tracked file in the repository, but task logs are provenance records and `.gitignore`
already declares that durable provenance stays tracked; and `latex/BimodalReference.pdf` (1.7 MB)
is committed while `typst/.gitignore` excludes the Typst PDFs — an inconsistency, but the LaTeX
edition is now explicitly the frozen one, so committing it is defensible.

### L3. The deployed `.claude/` tree carries a rule with no valid target in this repository

**Files**: `.claude/rules/source-store-deploy-boundary.md`

**Description**: The rule directs every `.claude/**` edit to `agent-system/extensions/**`,
"the source store". No `agent-system/` directory exists in this repository. An agent obeying the
rule has nowhere to write; an agent ignoring it writes into a gitignored tree that the next
deploy overwrites. Either way the instruction cannot be followed as written here.
