## Medium Priority Issues

### Retired `latex/` build artifacts are untracked but not gitignored
**File**: `.gitignore`, affecting `latex/build/` and `latex/subfiles/`
**Description**: The `latex/` edition was deliberately retired and its `.tex` sources removed
from git, with `.gitignore` gaining a `latex/**/*.log` rule at the same time. The remaining build
byproducts in `latex/build/` (`.pdf`, `.aux`, `.fls`, `.fdb_latexmk`, `.out`, `.toc`, `.xdv`) are
untracked yet covered by no `.gitignore` pattern.
**Impact**: Binary build artifacts sit as unignored, untracked cruft; a future `git add` touching
that path risks reintroducing retired build output into history.
**Recommended fix**: Extend `.gitignore` with a single `latex/build/` rule (or the remaining
extensions), matching the intent of the existing `latex/**/*.log` line.

### `FormalSystem/NomicLanguage/` has zero test coverage
**File**: `FormalSystem/NomicLanguage/` (Formula.lean, NomicFour.lean, NomicTenseFree.lean, NomicTruth.lean, NomicValidity.lean)
**Description**: No test file under `Tests/BimodalTest/` references `NomicLanguage`. Every other
language-variant directory (MinusLanguage, PlusLanguage, StarLanguage, SourceLanguage) has at
least one referencing test.
**Impact**: The nomic-modal language extension has no automated regression coverage — a future
refactor to `Formula.lean` or the validity/truth definitions could silently break its definitions
with no test to catch it.
**Recommended fix**: Add a `Tests/BimodalTest/NomicLanguage/` test module, or extend an existing
cross-language test (`LanguageDerivationTest.lean` / `ValidityLayerTest.lean`), exercising
`NomicFormula`, `NomicValidity`, and `NomicTruth`'s basic properties.

### No local entrypoint mirrors CI's 9-check gate
**File**: `CONTRIBUTING.md` (Development Setup, ~lines 18-57)
**Description**: `ci.yml` runs nine distinct checks (`check-evidence-probes.sh`,
`check-module-invariants.sh --no-build`, `check-copyright-headers.sh --strict`, `readme-lint.sh`,
`check-metalogic-cycles.sh`, `typst-sync-check.sh`, `check-paper-definitions.sh`,
`lake exe mk_all --check`, `lake exe lint-style`). CONTRIBUTING.md documents git-hook
installation but not how to run that full list locally.
**Impact**: A contributor can pass `lake build`/`lake test` locally and still push a CI-red
commit, discovering failures only after a long CI run, one check at a time.
**Recommended fix**: Add a thin aggregator script (e.g. `scripts/verify-all.sh`) running the same
nine steps in the same order with the same pass/fail reporting as `ci.yml`'s report step, and
document it in CONTRIBUTING.md.

### README.md's FormalSystem tree omits three real subdirectories
**File**: `README.md:103-138` (Project Structure diagram)
**Description**: The ASCII directory tree under `FormalSystem/` omits `ForMathlib/`,
`NomicLanguage/`, and `Tactic/`, all of which exist. Every other listed entry matches reality.
**Impact**: A new reader using this diagram as a map will not know those three directories exist.
`ForMathlib/` is documented elsewhere (root CLAUDE.md, ORGANISATION.md) as a load-bearing
subsystem, so its absence here is a real gap rather than a stylistic omission.
**Recommended fix**: Add the three directories to the tree with one-line descriptions matching
the existing entries' style.

## Low Priority Issues

### `.pid` at repo root is not gitignored
**File**: `.pid`
**Description**: A stray runtime PID file at the repo root, untracked but absent from
`.gitignore` — unlike `.agent-logs/` and `.playwright-mcp/`, which are both correctly ignored.
**Impact**: Harmless today, but an accidental-staging risk and inconsistent with sibling
runtime-file entries.
**Recommended fix**: Add `/.pid` to `.gitignore`.

### `Challenge.lean` is an undocumented loose root file
**File**: `Challenge.lean`
**Description**: A loose top-level `.lean` scratch file containing a `sorry`'d theorem. It is not
a Lake root (absent from `lakefile.toml`), not built, and not listed in ORGANISATION.md's
"Everything else" table alongside the other top-level paths.
**Impact**: Reduces discoverability of why it exists and whether it is safe to ignore or delete.
**Recommended fix**: Either add one line to ORGANISATION.md's "Everything else" table explaining
its purpose, or relocate it into `Boneyard/` consistent with the repo's archival conventions.

### `FormalSystem/ForMathlib/` has no test coverage
**File**: `FormalSystem/ForMathlib/` (Order/BallSpace.lean, Order/PFilter.lean, Combinatorics/SimpleGraphAcyclic.lean, Combinatorics/InfiniteRamseyPairs.lean, Topology/Sierpinski.lean)
**Description**: No test references `ForMathlib`. These are self-contained Mathlib-shaped
extensions intended for upstreaming, importing nothing from `FormalSystem.*`.
**Impact**: Lower risk than NomicLanguage since downstream changes are unlikely to touch them,
but an upstream-PR candidate with no coverage is a weaker contribution and harder to verify in
isolation.
**Recommended fix**: A lightweight `#check`/`example` smoke test per file suffices; a full test
module is not warranted.

### `FormalSystem/Tactic/` has no test coverage
**File**: `FormalSystem/Tactic/` (Attr.lean, Meta.lean)
**Description**: No test references `Tactic.`. `Tests/BimodalTest/Automation/TacticsTest.lean`
exists but covers `Automation/`'s tactics, not this lower-level support code.
**Impact**: Meta-level tactic infrastructure changes could break silently; impact is low since
the module is small and breakage would likely surface as a build failure elsewhere.
**Recommended fix**: Fold a minimal usage check into an existing Automation test rather than
adding a new file.

### `release.yml`'s publish path has never been exercised
**File**: `.github/workflows/release.yml` (header comment)
**Description**: The workflow's own header records that `actionlint`/`act`/`yamllint` were
unavailable when it was written, and that no real `workflow_dispatch` run has yet certified its
`${{ }}` expressions, `if:` conditions, or publish step.
**Impact**: The release path is unexercised; the first real release attempt may surface a syntax
or logic error that must be debugged live.
**Recommended fix**: Run one `workflow_dispatch` dry run (`publish: false`, the default) to
certify the workflow, then update the header to record that it has been exercised. This requires
a maintainer-initiated dispatch and cannot be performed by an agent.

### `CHANGELOG.md` carries no signal since 1.0.0
**File**: `CHANGELOG.md`
**Description**: Only an empty `[Unreleased]` section and the original `[1.0.0] - 2026-09-07`
entry exist, while the repo has had roughly 3,300 commits since that date and carries no git tags.
**Impact**: Minor, and possibly by design — changelog entries may be intended to be written only
at release time via `/tag`.
**Recommended fix**: No action required unless a release is imminent; otherwise populate
`[Unreleased]` incrementally.
