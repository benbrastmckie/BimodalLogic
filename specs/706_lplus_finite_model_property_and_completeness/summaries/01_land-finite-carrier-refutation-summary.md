## Decisions

- **D-1, the home**: `PlusSlicedCertificate/Limits/FiniteCarrier.lean`, not the inventory's
  reserved `PlusSlicedCertificate/FiniteCarrier.lean`. Both obstruction axes now live in one
  directory under one README, which is what makes the asymmetry readable. The four reserved rows'
  fourth field was edited rather than left naming a path nothing lands at.
- **D-2, `θ'` is reused, not copied**: `FiniteCarrier.lean` imports `Limits.NoFiniteWidth` and
  takes `pa`, `p`, `Fp`, `Pp` from it and builds `θ' := NoFiniteWidth.A'.and NoFiniteWidth.C'`.
  `noFiniteWidth_Φ_eq : NoFiniteWidth.Φ = θ'.and NoFiniteWidth.D := rfl` closes by `rfl`, so the
  agreement between the two landings is a definitional identity the build enforces. The recorded
  fallback (local copies plus a `decide` proof) was not needed.
- **D-3, the rename**: the probe's `S_hist_unique` lands as `shift_hist_unique`, because C23
  rejects an `Uppercase_x` name whose suffix is not a live base identifier. The probe's `mk` lands
  as `histOfStepPath`, avoiding a reader-facing collision with `PlusSlicedCertificate.mk`.
- **The axiom measurement decided its own baseline.** The plan's hypothesis was confirmed exactly:
  seven of the eight landed headline declarations report `[propext, Classical.choice, Quot.sound]`,
  and `θ_eq_ofFormula` (proved by `decide`) depends on no axioms at all. It therefore gets no
  baseline line, no `#print axioms` line, and a literal rather than `pinned:` ledger cell.
- **The finite-width landing's five standing-exception rows were pinned in the same change**, the
  plan's optional Phase 7 item. All five measured `pcq`, as the ledger's prose had claimed, so this
  was a pin of an already-true claim rather than a correction; `Limits/NoFiniteWidth.lean` itself
  was not touched.
- **`#print axioms` was not transcribed.** C27 and the blocking `linter.hashCommand` forbid it in
  library code; the seven probe directives were measured once in a scratch file instead.

## Plan Deviations

- **Phase 1 and Phase 5**, altered: `lake exe mk_all --lib FormalSystem` (planned as a Phase 5
  step) had to run in Phase 1, the moment the new file existed. The repository's pre-commit gate
  runs `typst-sync-check.sh --counts-only`, which compares `FormalSystem.lean`'s import count
  against the live `.lean` file count and refuses the commit on a mismatch — so the plan's
  assumption that Phases 1-4 could commit with the module outside the build graph does not hold in
  this tree. Phase 5 then reduced to the subtree-root import, the `## Submodules` bullet and the
  two READMEs, and its `mk_all` step verified as a no-op (`No update necessary`).
- **`typst/generated/status.typ`**, altered scope: regenerated on every phase commit, for the same
  pre-commit gate. It is a generated surface not named in the plan's `file_scope` or its
  declared-scope-extension list; it is listed here rather than taken quietly.
- **Phase 3**, altered: the probe's two `show M.valuation ...` tactic lines land as `change`,
  because under the shared `NoFiniteWidth.pa` the goal is not syntactically what `show` is allowed
  to assert and `linter.style.show` is blocking at a zero warning budget. Semantically identical.
- **Phase 9**, altered: two further gate-forced edits outside the plan's enumerated scope, each
  stated rather than taken quietly.
  - `scripts/module-invariants-allowlist.txt` — one entry for
    `...PlusSlicedCertificate.FiniteCarrier`. C5 reads the ledger's fully qualified Lean names as
    module-shaped paths, and the chosen namespace deliberately does not mirror the `Limits`
    directory level, so the namespace is not a module. The exact precedent sits immediately above
    the new entry: the finite-width landing added the identical entry for
    `...PlusSlicedCertificate.NoFiniteWidth`, for the identical reason.
  - `scripts/check-module-invariants.sh` — C36a's pinned-set extraction widened from
    `^'([^']+)' depends on axioms` to `^'(.+)' depends on axioms`. The no-apostrophe character
    class stops at the trailing prime of `not_plusValidZTime_neg_θ'`, so the whole baseline line
    failed to match and two rows that the C2 baseline really does pin were reported as "pinned by
    neither C2 nor C14". This is a parser defect of exactly the shape C15's recorded Unicode
    identifier-class fix addressed, and the same one-way-safety argument holds: a greedier
    delimiter can only surface a baseline line that was previously invisible, and each baseline
    line carries exactly one ` depends on axioms`. The plan's contingency C3 confines this file's
    edits to the C2 block; this edit is outside that block, and is taken because it makes the gate
    *see* a landed declaration rather than quieting it. No `ENFORCE_*` flag was touched.
- No other deviation. No phase was skipped, and the recorded D-2 fallback was not taken.
