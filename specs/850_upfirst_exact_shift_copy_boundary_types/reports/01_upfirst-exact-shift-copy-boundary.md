## Findings

### Codebase Patterns

- **Why the landed route pays `budget²`** (`LadderChain.lean:1360-1373`, the `DelNxtIter` section header, and the exact theorem's docstring at L1565-1577): the deletions come first in uncontrolled chunks `d·l` (`1 ≤ d ≤ b`) and the raise last, so the overshoot (fewer than `b` blocks of length `l ≤ b`) must already be covered by slack and gap before it happens. Reversing the order needs the raised run's interior exposed, which the landed `exists_iterSpliced_ladderPath_of_pend_past` (`LadderPump.lean:1379-1481`; type clause L1400-1406) does not give: it exposes `objAt` only below `u + l` (`hobj`), at `u + l` (`hend`), pending in the run (`hpend`) and above the run (`habove`), and `tpOf` only below `u + l` and at `u + l`.
- **The accounting of the up-first ordering**, with `b` the budget, `c₀ := cntAt g z`, `R := m·q` where `l·q = P + 1`:
  1. Pigeonhole block `[u, u + l)` with `u + l ≤ z + b` (the `_within` lemma's `hul`), `l ≤ b`, `l ∣ P + 1`.
  2. Raise by `d := b` copies (register held): `cntAt g₁ z = c₀ + b·l`, `nxtAt` held, run `[u, u + (b+1)·l)`, every `u + i·l` (`i ≤ b`) carries `(objAt g u, tpOf σ u)`.
  3. Slack: `HasForwardSlack g z (R·l) n ⟹ HasForwardSlack g₁ z (R·l + b·l) n` (`hasForwardSlack_raise`). This is exactly the loop's `hslack`.
  4. Loop above the run from `w₀ := u + (b+1)·l`, target `R`: window `w₀ + (R + b)·l ≤ z + c₀ + b·l ⟸ u + l + b·l + R·l ≤ z + c₀ ⟸ (u + l ≤ z + b) ∧ (b·l ≤ b·b) ∧ (b·(b+1) ≤ Tc) ∧ (Tc + R·l ≤ c₀)`; gap `n + R·l + b·l ≤ c₀ + b·l ⟸ n + R·l ≤ c₀`. Output: `t` with `R ≤ t < R + b`, `cntAt g₂ z + t·l = c₀ + b·l`, walk and types agree with `g₁` at every `v ≤ w₀` (the whole run), slack at `(R + b − t)·l`.
  5. Remainder `r := R + b − t`, `1 ≤ r ≤ b`; delete `[u, u + r·l)` of `g₂` with the register exposed (`exists_deleted_ladderPath_of_pend_past_nxt`, anchor clause by `anchor_clause_of_first_region_start` from the slack at exactly `r·l`; lower direction from `n ≤ c₀ − R·l`). `cntAt g₂ z = c₀ − R·l + r·l` (from `cntAt g₂ z + t·l = c₀ + b·l` and `r + t = R + b`), so `cntAt g₃ z = c₀ − R·l`. Type at `z` through `tpOf_eq_delIdx_of_tpOf_eq` with the boundary type equality at `u` and `u + r·l`.
- **The one hypothesis change to the landed loop.** `exists_deleted_ladderPath_step_of_pend_past` (L1390) uses `hwb : w₀ ≤ z + b` and `hroom : b·(b+1) ≤ cntAt g z` only in its first `have hroom'` (L1415-1420), which derives `w₀ + b·l ≤ z + cntAt g z`; the overshoot loop (L1482) uses its `hroom` only to feed the step and to recurse. With the run of `b` copies, `w₀ = u + (b+1)·l` can exceed `z + b`, so the window must be the hypothesis. The prototype's `_win` variants are the landed proofs with `hroom'` replaced by the hypothesis `hwin`; the loop keeps `hlb : l ≤ b` because its base case needs `b ≥ 1` from it (`t < R + b` with `t = R = 0`).
