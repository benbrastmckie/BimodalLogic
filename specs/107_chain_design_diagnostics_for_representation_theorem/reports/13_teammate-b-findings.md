# Teammate B Findings: Additive Closure of limit_dom

**Task**: 107 - Chain design diagnostics for representation theorem
**Focus**: Can we close limit_dom under addition to get AddCommGroup?
**Date**: 2026-04-24

## Executive Summary

**Closing limit_dom under addition FORCES density, invalidating the construction for general BX completeness.** This approach fails for the same mathematical reason as Approach A (dense domain). The additive closure of limit_dom generates a dense subgroup of (Q,+) after omega steps, which makes GGp -> Gp valid in the constructed model.

Furthermore, **no countable linearly ordered abelian group** besides Z (discrete) and subgroups of Q (dense or cyclic) is suitable. Using Z directly is blocked by the need for midpoint insertion in C4 elimination. The AddCommGroup requirement on TaskFrame is fundamentally incompatible with Burgess's sparse-domain chronicle construction.

## Detailed Analysis

### 1. Subgroups of (Q,+): The Dichotomy

Every subgroup G of (Q,+) satisfies exactly one of:
- **Cyclic**: G = r*Z for some r in Q (discrete, order-isomorphic to Z)
- **Dense**: G is dense in Q (no isolated points under the order topology)

There is no intermediate case. This is because Q is Archimedean and torsion-free.

**Proof sketch**: If G is non-cyclic, pick two elements a/b, c/d in G that are not integer multiples of each other. Then G contains all integer linear combinations m*(a/b) + n*(c/d). The set of such combinations is (1/lcm(b,d))*Z if a/b and c/d are rationally dependent, but if they generate a non-cyclic group, then for any epsilon > 0, there exist m, n with 0 < |m*(a/b) + n*(c/d)| < epsilon, making G dense.

### 2. What Points Does the Omega-Chain Actually Insert?

Examining the codebase:

```

```
This inserts midpoints like (0+1)/2 = 1/2, (0+1/2)/2 = 1/4, etc.

### 3. Denominator Growth Under the Omega-Chain

After omega steps, the domain contains:
- Integers: ..., -2, -1, 0, 1, 2, ... (from C5/C5')
- Dyadic rationals: 1/2, 1/4, 1/8, ... (from C4 midpointing)
- Mixed: midpoints between non-integers, e.g., (1/2 + 1)/2 = 3/4, etc.
- C5 witnesses for Until formulas at midpoints: these are max+1 of the current domain, producing values like 3/2 + 1 = 5/2, etc.

The denominators that appear include: 1, 2, 4, 8, 16, ... (powers of 2 from midpointing). But also arbitrary denominators from C5 witnesses at midpoint locations.

### 4. The Additive Closure Forces Density

**Claim**: The additive closure of limit_dom is dense in Q after omega steps.

**Proof**: limit_dom contains 0 and points with unboundedly growing denominators. Specifically:
- 0 is in limit_dom (initial singleton)
- 1 is in limit_dom (C5 witness for Until at 0)
- 1/2 is in limit_dom (C4 midpoint between 0 and 1)
- 1/4 is in limit_dom (C4 midpoint between 0 and 1/2)
- 1/2^n is in limit_dom for all n (iterated C4 midpointing)

The additive closure of {1/2^n : n in N} is the set of **dyadic rationals**: all rationals of the form m/2^n for integer m and natural n. This is the subgroup generated by {1/2^n : n in N}, which equals the union of (1/2^n)*Z over all n.

Is this dense? Yes. For any rational p/q and any epsilon > 0, choose n with 2^n > q/epsilon. Then m/2^n can approximate p/q to within 1/2^n < epsilon/q... Actually, let me be more precise.

The dyadic rationals D = {m/2^n : m in Z, n in N} form a subgroup of (Q,+). For any interval (a,b) with a < b in Q, pick n such that 1/2^n < b - a. Then there exists m in Z with a < m/2^n < b (by the Archimedean property). So D is dense in Q.

**Therefore**: closing limit_dom under addition produces (at minimum) the dyadic rationals, which are dense in Q. The additive closure is dense.

### 5. Density Validates GGp -> Gp

As established in team research report 11, if the model domain is dense in Q (or IS Q), then GGp -> Gp is valid:

Given any t' > t in the domain, if GGp holds at t, pick t1 with t < t1 < t' (possible by density). Then Gp holds at t1 (by GGp at t and t1 > t), and p holds at t' (by Gp at t1 and t' > t1).

Since GGp -> Gp is NOT derivable in BX, a model validating it cannot serve as a general completeness countermodel.

### 6. Alternative: Use Z Directly?

The existing `bx_fmcs` in `CanonicalModel.lean` already constructs an FMCS over Z. This avoids the density problem since Z is discrete. However:

**Problem**: Z has no midpoints. The C4 condition requires inserting a point z with x < z < y for adjacent domain points x, y. In Z with the standard order, adjacent integers x, x+1 have no integer between them. C4 elimination is impossible in Z.

The Int chain in CanonicalModel.lean handles this by NOT having a C4 condition at all -- it only handles G/H/F/P propagation via g_content/h_content, not Until/Since witness structure with guards. The Until/Since guard condition is precisely what the chronicle construction adds, and it requires the dense ambient space Q for midpoint insertion.

### 7. Alternative: Non-Archimedean Ordered Groups?

Could we use a countable linearly ordered abelian group that is neither Z-like (discrete) nor Q-like (dense)?

**Answer: No, for Archimedean groups.** By Holder's theorem, every Archimedean linearly ordered abelian group embeds (as an ordered group) into (R,+). The countable Archimedean ordered groups are exactly the subgroups of (R,+) that are countable, i.e., subgroups of (Q,+) (since countable subgroups of R with the induced order from Q are order-isomorphic to subgroups of Q). And we showed above that subgroups of Q are either cyclic (discrete) or dense.

For **non-Archimedean** groups: Z x Z with lexicographic order is a countable non-Archimedean ordered group. But:
- TaskFrame requires `[IsOrderedAddMonoid D]`, which Z x Z with lex order satisfies
- The order on Z x Z (lex) has the property that (0,n) < (1,0) for ALL n, so the "first coordinate" creates an infinite gap
- This would make the model have disconnected "epochs" -- points in different Z-components are infinitely far apart
- The truth lemma for Until would need to cross these epoch boundaries, which is mathematically unsound for the Burgess construction

**Non-Archimedean groups are not viable** for the chronicle construction because:
1. Burgess's construction relies on midpoint insertion in a dense linear order (Q)
2. Transferring the chronicle truth lemma to a non-Archimedean group would require showing order-isomorphism between limit_dom and a segment of the group, but the group's non-Archimedean gaps would break the Until/Since witness structure

### 8. Alternative: Order-Isomorphism X -> Z?

Could the sparse limit_dom X be order-isomorphic to Z?

**Yes, this is likely!** X = limit_dom starts as {0} and grows by:
- Adding points above all current points (C5: max + 1)
- Adding points below all current points (C5': min - 1)
- Inserting midpoints between adjacent pairs (C4: (x+y)/2)

After omega steps, X is a countable dense-in-itself linear order without endpoints (the C5/C5' insertions ensure unboundedness, the C4 insertions ensure density-within-X in the sense that between any two points of X there are others).

Wait -- is X actually dense-in-itself? Between any two adjacent points in X at some finite stage, a C4 step eventually inserts a midpoint. After omega steps, there are no adjacent pairs left (every potential adjacency is eventually broken by midpoint insertion). So X IS dense-in-itself.

A countable dense linear order without endpoints is order-isomorphic to Q (by Cantor's theorem). So X is order-isomorphic to Q, not Z.

But the FMCS over Z in CanonicalModel.lean works because Z is NOT dense -- it doesn't need C4. It only handles G/H/F/P, not Until/Since guards. The Int chain doesn't produce a ValidChronicle.

**This means**: X ~ Q as an ordered set, which again gives us density, which again validates GGp -> Gp.

### 9. The Fundamental Tension

The mathematical situation is:

1. **Burgess's chronicle domain X is order-isomorphic to Q** (countable, dense, no endpoints)
2. **Any AddCommGroup structure on a Q-like ordered set validates GGp -> Gp** (because density + ordered group => GGp -> Gp)
3. **GGp -> Gp is not derivable in BX**
4. **Therefore: no AddCommGroup structure on X can serve as a general BX countermodel domain**

This is NOT a problem for Burgess's construction itself, because Burgess doesn't need AddCommGroup -- he works directly with the ordered set X and evaluates truth only at X-points. The problem is specific to this project's TaskFrame architecture.

### 10. What About the "Cyclic Subgroup" Escape?

One might hope that limit_dom generates only a cyclic subgroup under addition. Let's check:

- If all C5 witnesses are at integer points and all C4 midpoints are dyadic, then the subgroup is the dyadic rationals (dense, as shown above).
- Even if we modified C5 to insert at x+1 (integer offset) instead of max+1, and C4 inserts (x+y)/2, we still get dyadic rationals.
- To get a cyclic subgroup, ALL denominators would need to divide a single denominator d. But midpointing doubles denominators: if x = a/d and y = b/d, then (x+y)/2 = (a+b)/(2d). So each midpoint step can double the denominator. After omega midpoint steps, d -> infinity, and the subgroup is non-cyclic, hence dense.

**There is no escape via cyclic subgroups.** The midpoint insertion mechanism inherently produces unbounded denominators, forcing the additive closure to be dense.

## Conclusions

### Definitive Result

**Closing limit_dom under addition to obtain AddCommGroup is mathematically equivalent to making the domain dense in Q.** This validates GGp -> Gp and fails for general BX completeness.

### Why This Approach Fails

The root cause is a structural incompatibility:
- **Burgess's construction** needs a dense ambient space (Q) for midpoint insertion but evaluates truth on a sparse subset X
- **This project's FMCS/TaskFrame** requires the domain type D to carry AddCommGroup, which for the domain X forces either discreteness (Z, no midpoints) or density (Q, validates density axiom)
- There is no ordered abelian group between Z and Q that is suitable

### Implications for Other Approaches

1. **Approach A (dense domain)**: Fails (validates GGp -> Gp) -- confirmed
2. **Approach B (additive closure)**: Fails (equivalent to Approach A) -- THIS REPORT
3. **Using Z**: Partially works (no density problem) but cannot handle Until/Since guards via chronicle
4. **Order-isomorphism to Z**: Impossible since X ~ Q (dense), not X ~ Z
5. **Refactoring TaskFrame**: The only viable path -- weaken AddCommGroup to LinearOrder

### Recommendation

The additive closure approach is a dead end. The viable paths forward are:

**Path 1 (recommended)**: Refactor TaskFrame to remove AddCommGroup, as analyzed in report 12. The chronicle naturally produces X ~ Q as an ordered set without group structure. The FMCS should be parameterized by LinearOrder only.

**Path 2 (workaround)**: Accept that the completeness theorem holds for the class of *ordered-group* task frames (where D is an ordered abelian group, hence Archimedean, hence dense-embeddable). In this class, GGp -> Gp IS valid, and the dense-domain approach works. The completeness result would be: "BX + (GGp -> Gp) is complete for ordered-group task frames." This is a weaker result than general completeness but might be sufficient for some applications.

**Path 3 (hybrid)**: Keep TaskFrame as-is with AddCommGroup, but construct the countermodel over Rat using the FULL rationals as the FMCS domain (not just limit_dom). This is what the existing `chronicle_fmcs` in ChronicleToCountermodel.lean attempts with `extended_limit_f`. The sorry'd `forward_G` proof is the obstacle -- it requires showing that G(phi) propagates from domain points to non-domain points, which is exactly the density issue. This path requires resolving the `forward_G` sorry, which may be possible if we accept GGp -> Gp validity (Path 2).
