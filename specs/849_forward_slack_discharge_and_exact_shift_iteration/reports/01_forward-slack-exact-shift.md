## Executive Summary

- **Piece 1, route (a) is closed by a compiled object, not by argument.** The climbing-register path on the two-state object (`prototype/climb-witness.lean`) is an `IsLadderPath`, pending forever into the past at `z = 0`, satisfies the assembly's gap `nxtAt g z + (P + 1) ≤ cntAt g z` (with `P = 0`), and violates `HasForwardSlack g 0 1 (nxtAt g 0)`. No "Drift-level invariant" bounding the register's climb exists to be isolated: `Drift` admits `n' = n + 1` at every step and a pending self-loop realizes any next-region length, so the climb is a genuine path, and `HasForwardSlack` is a genuine regime restriction rather than a missing lemma.
- **Piece 1, route (b) has a finite witness and three compiled entry lemmas.** `HasForwardSlack g z l n` is exactly the one inequality `cntAt g (s₀ + 1) ≤ n + cntAt g z + I − l` at the first region start `s₀ + 1` above `z`'s region (its countdown `N₁` is the witness). Compiled: `hasForwardSlack_of_next_region_cnt_le` (the regime from a bound on `N₁`), `hasForwardSlack_mono` (monotone in `l`), and `hasForwardSlack_del` (slack transports across a deletion inside `z`'s region, decreased by exactly the deleted length). No hypothesis on the STATE `(q, c, n)` can replace the path-level regime: the witness passes through a pending-forever state satisfying every state-level hypothesis the consumer carries.
- **Piece 2 is a reformulation, not an iteration.** Every landed deletion lemma is length-agnostic, so `d` deletions of an `l`-block are ONE deletion of a `d·l`-block; the "d + 1 consecutive copies" framing is unnecessary. The real obstacle is EXACTNESS: a pigeonhole yields a type-respecting block of some uncontrolled multiple length, never a prescribed `m·(P + 1)`. It is solved by combining deletions (whose total may overshoot the target by less than `budget·l`) with the landed, free upward move (the iterated duplication of the same block) — "overshoot-then-up". The two new ingredients, a spaced type pigeonhole (`exists_typeBlock_of_spacing`) and the room bound `budget·(budget + 1) ≤ Tc` (`budget_mul_succ_le_Tc`, from `(K2)` alone), are compiled.
- **The path-versus-state mismatch is resolved by stating the downward inclusion on the witnessing path**, which is the only honest form: for a type realized at `(q, c + m(P + 1), n)` by a path with forward slack, the type lies in the cell at `(q, c, n)`. The gap between this and the reserved obligation `cellLE_zero_const_of_kappa_eq` is exactly the tight (doubling) chain the README's open-core paragraph already names; this report adds that no finite deletion-derivative of the climbing path lifts (argued, not compiled), so the gap is not closable by any finite pumping — the reserved name stays claimed by nothing.
- **Recommended plan**: regime lemmas plus a wired refutation theorem; the spaced pigeonhole, slack transport, and budget bound; a register-held iterated duplication for a given block and arbitrary `d` (a factoring of the regime-A assembly's proof body); the exact-shift theorem by the overshoot-then-up loop; the slack-restricted cell inclusion; README/docstring/status.typ refresh; Challenge snapshot at plan time. ## Findings

### Codebase Patterns

- **The register obstruction is a walk-shape fact, not a register fact.** On a ladder path the pins (region starts) are determined by the object walk: a region of length `L` has start countdown `L − 1`, and the register's value at the idle position before it equals that countdown (`cntAt_eq_nxtAt_of_idle_pend`, `LadderAgree.lean:626`). Between pins the register is any `1`-Lipschitz interpolation (`nxtAt_lipschitz_two_sided`, `LadderAgree.lean:1179`; the lift `exists_ladderPath_of_walk_nxt_at`, `LadderChain.lean:459`). Hence a walk with region lengths `L₁, L₂, …` and idle runs `I₁, I₂, …` above `z` (countdown `c`, register `n` at `z`) lifts iff `L₁ − 1 ≤ n + c + I₁` and `L_{k+1} ≤ 2 L_k + I_{k+1}` for all `k` (the pairwise pin compatibility `pinCompat_of_ladderPath` follows from the consecutive one by the triangle inequality). Deleting `l` from `z`'s region shrinks the first distance by `l` and nothing else, which is why the whole obstruction sits at the first region start — exactly what `anchor_clause_of_first_region_start` (`LadderChain.lean:724`) already collapsed it to.
- **The climbing witness, compiled** (`prototype/climb-witness.lean`, `lean_run_code` success, one `show`-linter warning fixed in the saved file): object `Bool` with `pend = id`, `step` total; `gRaw v = (true, (3 − v).toNat, (max 0 v).toNat)` for `v ≤ 3`, idle with register `4` at `v = 4`, then period `6` (countdowns `4,3,2,1,0`, one idle, register `4`). Proved: `IsLadderPath` (`unfold Rlad Drift Count gRaw; split_ifs <;> simp_all <;> omega`), pending for all `p ≤ 0`, `nxtAt g 0 + (0 + 1) ≤ cntAt g 0`, and `¬ HasForwardSlack g 0 (0 + 1) (nxtAt g 0)` (the witness `I = 1`, `nxtAt g 4 = 4 > 3`). The arithmetic witness recorded by the predecessor's gate (`n = 0, C = 3, I = 1, l = 1, nxtAt g s₀ = 4`) is realized by this path exactly.
- **Why no state-level regime exists**: the same construction applies at every pending-forever state `(q, c, n)` of this object with `n + 1 ≤ c` (register climbing by one from `n` over `c + 1` steps, next region of length `n + c + 2`) — argued, the compiled instance is `c = 3, n = 0`. `ParamsOk` constrains the object, closure, and parameters, never a path; the probe `ladder-cell-obligation-refutation.lean` already discharges `ParamsOk` at the periodicity fixpoint's outputs on the same object, so the assembly's full hypothesis set is satisfiable by a slack-violating path.
- **`exists_iterSpliced_ladderPath_of_pend_past` under-exposes types** (`LadderPump.lean:1379`, type clause at lines 1400–1406): it exposes `tpOf` only at positions `w < u + l` and at `u + l`; the copy boundaries `u + i·l` for `2 ≤ i ≤ d + 1` and every position above the run are exposed only through `objAt`/`cntAt` (`habove₁`). This decides the ordering of the exact-shift construction (see Recommendations): an up-first ordering needs an exact block inside the run at the end and therefore copy-boundary types, which would require re-deriving the iteration in `LadderChain.lean`; a deletions-first ordering needs nothing from the run's interior.
- **The regime-A assembly uses `hTc` only through the budget** (`LadderChain.lean:534`, `have hbud := budget_le_Tc …` feeding the pigeonhole's `(by omega)`), and its proof body (lines 534–647) is already "register-held iterated duplication of a GIVEN block, `d` arbitrary" with `d := m · q` substituted at line 560; factoring that body into a lemma taking the block and `d` as inputs is a mechanical refactor with no new mathematics.
- **The deletion-side lemmas are length-agnostic**: `exists_deleted_ladderPath_of_pend_past_nxt` (`LadderChain.lean:672`) takes any `0 < l` with `l ≤ cntAt g a`, `hrep`, and the anchor clause; `tpOf_eq_delIdx_of_tpOf_eq` (`LadderPump.lean:1214`) takes any `0 < l` with the endpoint type equality. The counter clauses `delObj_step`, `delCnt_idle`, `delCnt_pend_pend`, `delCnt_pend_idle` do not need `hpast`; only the pin clauses do (through `hstart`). So one deletion of a block of length `d·l` IS `d` deletions of an `l`-block, provided `(objAt, tpOf)` agree at `u` and `u + d·l` — the condition the task's "d + 1 consecutive type-equal copies" phrase describes, and which no pigeonhole supplies for a GIVEN `d`.
- **Room is available from `(K2)` alone**: `cascadeBound pend φ = 2 ^ card (ProdState Q φ) * (tIdle pend + 2)` (`CounterQuotient.lean:371`) with `tIdle ≥ 1`, so `budget · (budget + 1) ≤ Tc` (compiled, `budget_mul_succ_le_Tc`, by `b(b+1) ≤ 3·2^b` with the hint `Nat.lt_two_pow_self`). This is the room a `(budget + 1)`-sample window at spacing `l ≤ budget` needs. The analogous room for spacing `P + 1`, `budget · (P + 2) ≤ Tc`, is NOT derivable: `P + 1 = Pof.succ` is an lcm over cycle lengths up to `budget` and is independent of `Tc` in `ParamsOk` (`paramsOkK1`, `paramsOkK2`). Sampling at spacing `P + 1` is therefore not an option; spacing `l` (the found block's own length, `l ∣ P + 1` by `typeBlock_length_dvd_of_paramsOk`) is.
- **The compiled helpers** (`prototype/helpers-compiled.lean`): `hasForwardSlack_mono`, `hasForwardSlack_of_next_region_cnt_le`, `hasForwardSlack_del`, `budget_mul_succ_le_Tc`, `exists_typeBlock_of_spacing` — signatures in the file, each elaborated against the built library (`lean_run_code`), the first two in one run with no diagnostics on them, the other three in a second run with one unused-variable warning (`hs : 0 < s` in the pigeonhole; the saved file drops it).

## Decisions

- **Piece 1 outcome: route (b).** Route (a) is refuted by a compiled path; the deliverable is the regime with its finite witness (`N₁`, the countdown of the first region start above `z`'s region), the three entry lemmas, and a WIRED refutation theorem so the FAIL verdict is a library fact about the named object (precedent: `atomPreservingCountMove_refuted`, `LadderAgree.lean`).
- **Piece 2 ordering: deletions-first (overshoot-then-up), not up-first.** Up-first gives the cleanest hypotheses (`HasForwardSlack g z (m(P+1)) n` and `n + 2 ≤ c`) but needs copy-boundary types the landed iteration does not expose; deletions-first needs only what is exposed, at the cost of `budget²` extra slack in both directions of the anchor. Land deletions-first; tightening to the clean hypotheses is an optional later phase (re-derive the iteration in `LadderChain.lean` from `exists_spliced_ladderPath_of_pend_past` and `tpOf_eq_spliceIdx_of_tpOf_eq`, invariant "`tpOf` at `u + i·l` equals `tpOf` at `u` for all `i ≤ d + 1`").
- **The cell-level statement names the witnessing path.** `cellAt` is existential over histories, so the only sound downward statement under a path-level regime is: for every `(g, τ)` realizing `T` at `(q, c + m(P+1), n)` with `HasForwardSlack g z (m(P+1) + budget²) n` (and the arithmetic gap), `T ∈ cellAt (q, c, n)`. No weakened statement under the reserved name.
- **Spacing `l`, not `P + 1`**, for the spaced pigeonhole (room derivable from `(K2)`; `P + 1` room is not).
