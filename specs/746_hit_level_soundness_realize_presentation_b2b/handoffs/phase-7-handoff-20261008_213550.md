## THE ONE THING PHASE 8 MUST READ FIRST

**`Cons` gained an eleventh field, `nowUnique`, and it was not in the plan's enumeration.**

Phase 7's (⇐) direction is not provable from the ten fields Phase 5 landed. The plan's own task
text instructs building the `Presheaf.StabFibre` element as `⟨σ, hσt⟩` with
`hσt : σ.state t = τ.state t`; `σ` is built from the run as `z ↦ (z, ρ z)`, so `hσt` demands
`ρ t = q₀`, and `IsRun` supplies only `lab (ρ t) (clNow φ) = true`. None of
`serialFwd`, `serialBwd`, `botFalse`, `impEq`, `ucoh`, `ulive`, `scoh`, `slive`, `nowOnce`,
`boxStabFree` forces the `clNow`-labelled state to be unique.

**The counterexample (prose, NOT machine-checked — this is the dispatch's one unverified
claim).** Take `φ = .atom p`, so every closure-letter clause is vacuous, and
`Q = {q₀, q₁, a, b, c, d}` with `step`: `c→c`, `c→q₀`, `q₀→a`, `a→a`, `d→d`, `d→q₁`, `q₁→b`,
`b→b`; the marker on `q₀` and `q₁` only; `lab c p = true`, `lab d p = false`. Bi-seriality holds
in both senses. `nowOnce` holds: the only positive-length `step`-paths out of `q₀` end in `a` and
out of `q₁` end in `b`, neither marked. But the two marked components are mutually unreachable,
so the splices through the seam `(t, q₀)` are forced onto the `c/q₀/a` chain while the run set
contains the `d/q₁/b` run as well — disjoint splice-trace sets, one shared run-trace set, so
`Presented` fails at either seam.

**Why this resolution and not a blocker.** `Cons`'s own Challenge pin is FIELD-FREE
(`structure Cons (φ) (lab) (step) : Prop where` with no fields listed), so adding a field drifts
no pinned signature, and `presented_modelOf` landed at its pin character for character — verified
by a mechanical side-by-side against `## Lean Challenge Statements`. Nothing in the tree
constructs a `Cons` term (Phase 5's witness is `#guard`s on the fixture, explicitly NOT a `Cons`
inhabitant, per that phase's own deviation note (c)), so the addition broke no build;
`cons_localRun` does not read the new field and re-pins unchanged.

## Key Decisions

- **The eleventh `Cons` field rather than a hypothesis on `presented_modelOf`.** Adding
  `ρ t = q₀`'s precondition to the theorem would have weakened a pinned statement, which
  `plan-compliance.md`'s Statement Fidelity section forbids outright. Putting it on `Cons`, whose
  pin carries no fields, keeps the pinned theorem exactly as recorded and puts the condition
  where it belongs: it is a property of the PRESENTATION, decidable over a `Fintype Q` by
  `decide`, and so checkable on a concrete fixture like every other field.
- **`nowOnce` and `nowUnique` are both kept, and neither subsumes the other.** `nowOnce` is
  once-only ALONG a path and is what makes a chain an `IsRun`; `nowUnique` is once-only ACROSS
  the presentation and is what pins the anchor to the seam's own state. `nowOnce` alone permits
  two mutually unreachable marked components; `nowUnique` alone permits the single marked state
  to recur along one path. Both docstrings say so.
- **`FrameOver.worldHistoryOfStepPath`, not `frameOf_mem_HF_iff`'s `←` direction, for (⇐).** The
  plan's bullet offered either. `worldHistoryOfStepPath` gives `σ.path = fun z => (z, ρ z)` by
  `rfl` (its `@[simp]` lemma is `rfl`), so `anchored_runTrace_of_boxStabFree`'s `hσ` argument is
  literally `rfl`; the `←` direction of `frameOf_mem_HF_iff` would have produced an existential
  over the offset `k` that then had to be specialized at `0`. The `→` direction IS used, in the
  (⇒) branch, exactly where the plan says.
- **The splice-exhibition block is `Probe735.not_presented`'s, copied rather than re-derived**,
  including the explicit `show` that spells out the `seamOmegaEquiv` round trip so
  `Equiv.symm_apply_apply` has a syntactic target. The module's `linter.style.show`
  suppression is declaration-scoped with a comment saying the `show` is kept to stay verbatim
  with the probe, following the two precedents already in this file.
- **Trialled standalone before editing, as Phases 3-6 did.** The whole phase was elaborated
  against the built oleans via `lake env lean` in the scratchpad; two diagnostics across two
  passes (an unknown `Bool.true_ne_false`, and the `show` linter), then the real module was
  edited once. Same discipline, same result.
- **One phase commit, not the plan's two.** Both directions went green in the same scratchpad
  pass, so no intermediate tree state existed with one direction green and the other outstanding.
  Splitting the final file afterwards would have manufactured a sub-step that did not happen.
