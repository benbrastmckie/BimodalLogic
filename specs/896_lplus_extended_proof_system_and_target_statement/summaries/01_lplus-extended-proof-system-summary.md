## Decisions

- The two Auxiliary-Atoms constructors' exhaustiveness and disjointness premises are recursive
  `ExtDerivation` premises rather than `PlusValidZTime` hypotheses, so the closure carries no
  semantic hypothesis anywhere; the soundness induction's own inductive hypotheses supply exactly
  the validity the rule's soundness theorem wants.
- `aaBwd`'s conclusion is `φ.reflectTime`, matching `aa_reflectTime_sound_ztime` exactly — zero
  soundness glue. The arbitrary-conclusion mirror form is derived in-module as an `example` from
  `PlusFormula.reflect_time_involution`, which shows the restriction costs no generality.
- `ExtDerivation` keeps its `FrameClass` parameter, because the `tm` base and the `clock` rule
  genuinely are class-generic. The narrow hazard — the two Auxiliary-Atoms rules are
  `.ZTime`-only — is recorded in the module docstring and backed by `ext_sound_validIn`.
- Axiom profiles live in a `Tests/BimodalTest/` evidence module, following
  `AuxiliaryAtomsTest.lean`, because a live `#print axioms` under `FormalSystem/` is allow-listed
  for `MainResults.lean` alone.
- The five definitional theorem-index rows carry a measured `[propext]` Axioms cell rather than
  the `pcq` the plan anticipated: `ExtDerivation`, `ExtComplete` and the three target Props were
  measured at `[propext]`, and a measured value wins over a carried one.

## Plan Deviations

- **Phase 1 import placement** altered: `FormalSystem.lean` is alphabetically sorted, so the new
  import went at its alphabetical position (line 506, between `Independence.ZTimeSharpness` and
  `NamingRules`) rather than beside `Metalogic.AuxiliaryAtoms` as the plan's Files-to-modify note
  anticipated. Placing it beside `AuxiliaryAtoms` would have added a second sort violation to the
  one pre-existing at line 66. `FormalSystem/Metalogic.lean` is dependency-ordered, so there the
  import was appended after `AuxiliaryAtoms` as written.
- **Phase 3 Axioms cells** altered: `[propext]` for the five definitional rows instead of a bare
  `pcq`, on the measured values (see Decisions). The six theorem rows carry `pcq` as planned.
- **Phase 3 scope** altered: one file beyond the five declared,
  `scripts/module-invariants-allowlist.txt`, five entries. `C5` resolves a dotted
  `FormalSystem.*` path against the filesystem, and the five uppercase-initial declaration names
  (`ExtDerivation`, `ExtComplete`, `LCComplete`, `LCRulesComplete`, `LCURulesComplete`) are
  indistinguishable from a module path one level below the file, so C5 failed on all five. The
  allowlist is that check's own documented permanent exemption mechanism and already carries
  exactly this shape for `StarLanguage.StarAxiom`, `OpenLanguage.OpenDerivationTree` and a dozen
  others; each name was `grep`-verified to be a live declaration before being added, as the
  file's charter requires. The module's six theorem rows need no entry, because their names begin
  lowercase and so terminate C5's match at `LCExtension`.
- **Phase 3 gate tier** altered by the dispatch directive, not by choice: this `full`-tier phase
  was discharged against a scoped tier (`verify-deploy.sh --only-gate 1,2`, exit 0) because this
  task is one `implement` dispatch inside a multi-task batch; the complete 27-gate agent-system
  deploy set is deferred to the batch stage. The repository's own gate set, which is what

## Impacts

- `ext_sound_ztime` is now available to any downstream module that wants soundness of an L⁺
  extension by an arbitrary `.ZTime`-valid axiom set under any mix of the three naming rules,
  which is the shape a completeness attempt would consume.
- `ExtComplete` gives the three targets one uniform shape, so a future completeness proof at one
  axiom set is visibly the same obligation at the other.
- `ext_sound_validIn` makes the `FrameClass` parameter's hazard a stated fact rather than a trap:
  anyone instantiating `ExtDerivation` at a class other than `.ZTime` now has a named lemma
  telling them which rules they may use.
