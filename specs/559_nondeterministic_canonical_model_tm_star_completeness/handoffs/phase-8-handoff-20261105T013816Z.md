## Three gate collisions, and how each was resolved

1. **C5** flagged `FormalSystem.Semantics.HistMorphism` / `...TwoWayBounded` as unresolved module
   paths. They are namespaces named after structures (the module is `HistoryMorphism.lean`), so
   they cannot resolve to a file. `scripts/module-invariants-allowlist.txt` exists for exactly
   this case and documents it as a permanent exemption; two entries were added with the
   verification note its header asks for.
2. **C15** requires a row's declaration to appear in its file under its **bare** base name
   (`base = name.split(".")[-1]`, matched against the declaration token). Five declarations were
   written dotted (`theorem HistMorphism.plus_invariance`), so C15 could not find them. Fixed by
   moving them into explicit `namespace HistMorphism` / `namespace TwoWayBounded` /
   `namespace FrameOver` blocks. Note the Lean syntax constraint: `namespace X` must precede the
   `/-- ... -/` doc comment, never sit between it and the declaration.
3. **C23** then saw a new outer-shadows-inner pair, `plus_invariance` in
   `FormalSystem.Semantics` (the translation product's own projection) against the same base name
   in `FormalSystem.Semantics.HistMorphism` (an arbitrary morphism). Recorded in
   `SHADOW_PAIR_ALLOW` with its reason, on the `Tw`/`Presheaf` precedent already in that set —
   the namesake IS the content, the inner being the abstract form of the outer.
