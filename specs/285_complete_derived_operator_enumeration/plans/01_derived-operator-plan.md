## Overview

Add 7 missing derived operators (diamond, always, sometimes, next, prev, weak_future, weak_past) to the formula enumerator in FormulaEnumerator.lean as first-class enumeration targets with pattern-aware complexity of 1 each. This follows the same convention established by tasks 274-276 for F/P/G/H and R/WU/T/WS/M/ST. The operators are already defined in Formula.lean but are never generated by the enumerator. Adding them requires new branches in `enumExactHelper`, corresponding complexity pattern-matching in `Formula.complexity`, recognition in `hasDerivedTemporal`, and recognition in InterestingnessMetrics. The phased approach (high-priority modal first, then medium/low temporal) manages formula count growth.

### Research Integration

The research report (01_gap_analysis.md) identified 7 operators missing from the enumerator, categorized by priority: high (diamond, always, sometimes), medium (next, prev), and low (weak_future, weak_past). The report confirmed all 7 operators are already defined in Formula.lean (lines 376-501) and recommended pattern-aware complexity = 1 to prevent formula count explosion. The expected formula count increase is approximately 2.4x at c6 with all 7 operators, manageable via the existing stratified generation for c6+.

### Phase 1: Add complexity pattern-matching and enumerator branches for all 7 operators [COMPLETED]

**Goal**: Add pattern-aware complexity cases for diamond, always, sometimes, next, prev, weak_future, weak_past in `Formula.complexity`, and add enumeration branches in `enumExactHelper`.

**Tasks**:
- [x] Add diamond complexity pattern in `Formula.complexity` (Formula.lean ~line 186): `| imp (box (imp φ bot)) bot => 1 + φ.complexity` -- diamond = neg(box(neg(phi))) = imp (box (imp phi bot)) bot. Must be placed BEFORE the generic `| imp φ ψ` catch-all (line 185). Note: this pattern is identical to the existing generic imp case but returns `1 + φ.complexity` instead of `1 + box_complexity + inner_complexity`. Insert after the T pattern (line 184) and before the generic imp case (line 185).
- [x] Add always complexity pattern: `always φ = H(φ) ∧ φ ∧ G(φ)` expands to `imp (imp (all_past φ) bot) (imp (imp φ (imp (all_future φ) bot)) bot)` via the `and` definition. This is complex -- the expanded form is `imp (imp (snce (imp φ bot) (imp bot bot)) bot) (imp (imp φ (imp (imp (untl (imp φ bot) (imp bot bot)) bot) bot)) bot)`. Add a pattern match returning `1 + φ.complexity`.
- [x] Add sometimes complexity pattern: `sometimes φ = neg(always(neg φ))` = `imp (always(neg φ)) bot`. Once always is matched, sometimes reduces to `imp (always_pattern) bot => 1 + φ.complexity`.
- [x] Add next complexity pattern: `next φ = untl φ bot` = `untl φ bot`. Add before the F pattern (line 188): `| untl φ .bot => 1 + φ.complexity` -- must be placed before `| untl φ (imp bot bot)` (the F pattern).
- [x] Add prev complexity pattern: `prev φ = snce φ bot` = `snce φ bot`. Add before the P pattern (line 192): `| snce φ .bot => 1 + φ.complexity`.
- [x] Add weak_future complexity pattern: `weak_future φ = φ ∧ G(φ)` = `imp (imp φ bot) (imp (imp (untl (imp φ bot) (imp bot bot)) bot) bot)` (via the `and` definition). This needs careful structural matching. Return `1 + φ.complexity`.
- [x] Add weak_past complexity pattern: `weak_past φ = φ ∧ H(φ)` = `imp (imp φ bot) (imp (snce (imp φ bot) (imp bot bot)) bot)` (via the `and` definition). Return `1 + φ.complexity`.
- [x] Add `#eval` verification tests for all 7 new patterns confirming complexity = 2 for `operator(atom)` (analogous to existing tests at lines 198-220)
- [x] Add diamond enumeration branch in `enumExactHelper` (FormulaEnumerator.lean): after the box block (~line 179), add diamond generation gated by `modalBudget > 0` with overhead 1, applying `Formula.diamond` to children. Filter `structurallyTrivial` as done for box.
- [x] Add always and sometimes enumeration branches: after the F/P/G/H block (~line 213), gated by `temporalBudget > 0` with overhead 1, applying `Formula.always` and `Formula.sometimes` to children
- [x] Add next and prev enumeration branches: after always/sometimes, gated by `temporalBudget > 0` with overhead 1, applying `Formula.next` and `Formula.prev` to children
- [x] Add weak_future and weak_past enumeration branches: after next/prev, gated by `temporalBudget > 0` with overhead 1, applying `Formula.weak_future` and `Formula.weak_past` to children
