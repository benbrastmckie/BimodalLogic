## Blocker: neg_2var_vec_ea_indep_backward is unprovable

### Root cause
The codebase's `neg_interval_formula_indep` construction (NegationIndep.lean:61-84) produces
a VBracketFormula that is NOT disjoint from the original BracketFormula. Specifically:

**Case B.2** (`inf_bracket_formula P`) only encodes "alpha_0 exists with alpha_0.neg before it"
but does NOT encode "beta_0 fails before the first occurrence of alpha_0". This makes the
INF bracket formula compatible with the original bracket holding simultaneously.

### Concrete counterexample
- bf: 2 witnesses, pt(0)=P, pt(1)=Q, all segments=top
- Model: interval (0,10), P holds only at 5, Q at 8
- bf.holds on (0,10): witnesses w(0)=5, w(1)=8 -- YES
- inf_bracket_formula(P).holds on (0,10): witness 5, P.neg on (0,5) -- YES
- Both hold simultaneously, so backward direction `inf_bracket_formula(P).holds -> not bf.holds` is FALSE

### Implications for Phases 2-4
The VecEA_m.neg correctness proof (Phase 2, Task 2.6) requires the backward direction of Prop 4.2
to show that interval negation disjuncts imply failure of the corresponding interval component.
Without this, the biconditional `neg_v.holds <-> not v.holds` cannot be proved.

This blocks Phase 2 (VecEA_m negation), Phase 3 (Prop 4.3 negation case), and Phase 4 (KampPrior rewiring).

### Resolution paths
1. **Fix inf_bracket_formula construction**: Modify case B.2 to encode beta_0 failure (not just alpha_0 existence). Requires rewriting ~100 lines of the sorry-free forward proof in neg_interval_formula_indep_correct plus ~100 lines new backward proof. Risk: touching working sorry-free code.

2. **Alternative proof architecture**: Prove Prop 4.3 without VecEA_m.neg biconditional. Possibilities:
   - Use the mutual induction approach (maintain both v_pos and v_neg) -- still needs negation for the `.all`/`.ex` cases
   - Use arity-2 specialized proof that avoids general VecEA_m -- may be sufficient for KampPrior

3. **Semantic biconditional**: Prove `neg_2var_vec_ea_indep_backward` only on Prior structures (with HasAttainedINF). The current counterexample doesn't use the Prior structure, so the backward direction might be provable in the restricted setting. However, initial analysis suggests HasAttainedINF doesn't help with case B.2.
