## What NOT to Try

- Do not trust `update-phase-status.sh`'s `sed -i "${line_number}s/\[.*\]/[...]/"` replacement
  (around its own line 240) when a phase title embeds a bracket-wrapped literal, as this plan's
  Phase 1 title deliberately does (`` `[file-scope]` ``). The greedy, unanchored `\[.*\]` pattern
  spans from the title's own `[file-scope]` bracket to the trailing status bracket and overwrites
  everything in between. Observed twice already (NOT STARTED -> IN PROGRESS, then IN PROGRESS ->
  COMPLETED), both times fixed by a follow-up `Edit` restoring the full heading text with the
  correct status. This is a genuine latent tooling defect (recorded in the issue log) but is OUT
  OF SCOPE for this plan -- do not attempt to fix `update-phase-status.sh` itself here. Continue
  the same pattern (call the script for its heartbeat side effect, then manually repair the
  heading) for Phase 2's and Phase 3's own status transitions, since their titles do not embed a
  bracket literal and so are NOT expected to hit this bug -- verify the heading after each call
  regardless.
- Do not run `bash .claude/scripts/tests/run-all.sh` (deployed path) expecting it to exercise the
  `core` extension's own shell suites -- it is always skipped for this repo. Use the source-store
  invocation shown above.
