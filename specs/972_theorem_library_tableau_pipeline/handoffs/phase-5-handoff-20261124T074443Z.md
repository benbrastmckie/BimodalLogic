## Two facts a successor needs

1. **`Json.mkObj` renders alphabetically.** It stores fields in a search tree, so a rendered
   record is in alphabetical key order and NOT in the order its source list builds. Key order is
   observable only on the pre-render association list, which is why every record here exposes
   `toJsonFields` and `keys` beside `toJson`. The golden strings are alphabetical for the same
   reason. `ReproveRecord.toJson` in the schema module has the same property.
2. **A multi-line Lean structure instance must be indented past its own opening brace.** A
   continuation line indented less fails with `unexpected identifier; expected '}'` reported at
   the end of the FIRST line, which points away from the cause. Bind such an instance to a named
   `def` at indent 2 with one field per line.
