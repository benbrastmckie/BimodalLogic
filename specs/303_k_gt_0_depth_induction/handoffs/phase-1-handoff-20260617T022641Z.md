## Critical Finding: NfCompose is FALSE

### The Counterexample (from NfComposition.lean:20-36)

M = (Z, <) with no predicates, env1 = (0, 2), env2 = (0, 1), k = 1.

All integers have the **same depth-k 1-var NF** for all k (by translation symmetry). And 0 < 2 iff 0 < 1 (both true). But the **depth-1 2-var NFs differ**: the zone "strictly between the two points" is nonempty for (0, 2) (element 1) but empty for (0, 1).

Z IS a Prior structure (UZ/SZ hold trivially since all integers have successors/predecessors), so this counterexample refutes any composition-based approach on Prior structures.

### Why This Kills the Plan

The plan proposes ExistPart_r: "given parent NF types at r elements, characterize the existential." But ExistPart_r at r=2 with parent_nfs = [nf_x, nf_t] would need: for ALL M, if x has NF type nf_x and t has NF type nf_t, then the formula A characterizes `exists y, nf_eval [y, x, t]`.

On Z: if nf_x = nf_t = (the universal NF type of all integers), and sub_nf says "there exists a point between the two parents," then:
- For [0, 2]: the existential is TRUE (element 1 exists between them)
- For [0, 1]: the existential is FALSE (no element between consecutive integers)

Both pairs have the SAME parent NF types and the SAME order (x > t). So no temporal formula A can distinguish them. ExistPart_r is FALSE.

### Why the Current Approach (constant parent) Works at k=0

At depth 0, NFs are purely atomic. The quantifier conditions disappear. There are no sub-NFs, so there's no "between-zone" issue. The depth-0 2-var NF IS determined by individual atom types + order.

At depth k+1, the 2-var NF includes quantifier conditions about 3-element tuples. These conditions depend on the INTERIOR structure between the two elements, which is NOT determined by the individual NF types.

## Analysis of the Fundamental Problem

### What the Backward Direction Actually Needs

The sorry at KampBypass.lean:356 requires:

```
temporal_truth M atomMap t (compat_disj.untl Formula.top) →
  ∃ x, nf_eval_nf M (k'+1+1) (1+1) (Fin.cons x (fun _ => t)) sub_nf
```

From `Until(compat_disj, top)`, we get x > t with some compatible nf_x type at x. To reconstruct `nf_eval_nf M [x, t] sub_nf`, we need:
1. **Atom part**: follows from nf_x compatibility + h_atoms (WORKS)
2. **Quantifier part**: for each ssn at depth k'+1 arity 3, `(exists y, nf_eval [y, x, t] ssn) <-> sub_nf.2 ssn` (BLOCKED)

The quantifier part requires knowing whether there exist elements with specific NF types in the "zones" relative to x and t (e.g., between x and t, above x, below t). This is NOT determined by the individual NF types of x and t.

### Why nf_extend_fwd Has a Depth Gap

`nf_extend_fwd` trades depth for arity: depth-(K+1) arity-r -> depth-K arity-(r+1). Starting from depth-(k'+2) arity-1 at t, we get depth-(k'+1) arity-2 at [c, t] (for SOME c, not our specific x). But sub_nf is depth-(k'+2) arity-2, requiring depth-(k'+1) arity-3 for the quantifier transfer. This needs depth-(k'+2) arity-2 as input — circular.

### Why ih_exist Cannot Handle Non-Constant Environments

`ih_exist` at depth k'+1 produces formulas for `exists y, nf_eval [y, t, t, ...]` (constant parent env). The Until zone needs `exists y, nf_eval [y, x, t]` with x != t. There is no instantiation of ih_exist that gives a non-constant environment.

## Candidate Approaches for Next Research Cycle

### Approach A: Zone-Explicit Formula Encoding (Rabinovich Section 5)

Instead of using the M₀ witness for transfer, encode the quantifier conditions EXPLICITLY in the temporal formula using zone decomposition.

For each ssn at depth k'+1 arity 3, decompose the existential `exists y, nf_eval [y, x, t]` by y's position relative to x and t:
- Zone 1: y > x > t (future of x)
- Zone 2: t < y < x (between t and x)
- Zone 3: y < t < x (past of t)
- Zone 4: y = x
- Zone 5: y = t

For each zone, encode the condition as a temporal formula evaluated at t and/or x, using nested Until/Since and ih_exist at depth k'+1 with appropriate constant parents.

**Key insight**: In Zone 1 (y > x), the condition `exists y > x, nf_eval [y, x, t]` can be expressed from x's perspective as `Until(zone1_formula, top)` where zone1_formula encodes y's type. In Zone 2 (t < y < x), it can be expressed from x's perspective as `Since(zone2_formula, char_kp1(nf_t))`. Etc.

**Feasibility**: This mirrors Rabinovich's interval-splitting argument. It requires:
1. Zone decomposition for 3-var NFs (which zones contain compatible elements)
2. For each zone, a temporal encoding using ih_exist with constant parent
3. Correct handling of the boundary conditions

**Risk**: High complexity (~500-1000 lines per zone). But mathematically sound for discrete Prior structures.

### Approach B: Ordered Sum Decomposition via NEquivalence

Prior structures can be viewed as ordered sums of components (each interval between boundary points is a component). The NEquivalence.lean CompData infrastructure already handles this.

**Key idea**: Decompose the Prior structure M around t and x into zones: (-inf, t), {t}, (t, x), {x}, (x, +inf). Each zone is a component in an ordered sum. Then use the CompData approach to transfer NF types between components.

**Feasibility**: The CompData infrastructure exists but handles DIFFERENT ordered sums (ms vs ms'). Here we'd need it for the SAME structure decomposed differently. Adaptation is non-trivial.

**Risk**: The CompData budget mechanism assumes fresh environments on each component, which may not match our situation.

### Approach C: Direct Induction on Formula Quantifier Rank

Instead of working at the NF level, work at the FORMULA level. Prove that for each FOMLO formula phi(x, y, z) of quantifier rank k'+1, the set of Prior structures satisfying `exists y, phi(y, x, t)` is definable by a temporal formula.

This is essentially proving a fragment of Kamp's theorem directly, by induction on quantifier rank. At each step, the temporal formula uses ih_char for the atomic cases and ih_exist for the existential cases.

**Feasibility**: This is the most mathematically natural approach (it's what Rabinovich does). But it requires restructuring the entire bypass away from NF-based reasoning toward formula-based reasoning.

**Risk**: Major architectural change. The current NF-based approach may not support this.

### Approach D: Weaken the Goal — Use CharPart Only

If we can prove `completeness_discrete` using only CharPart (without ExistPart at k>0), the sorries might be avoidable. Check whether the completeness chain goes through NfCharFormula.lean's direct backward proof (nf_exist_backward_prior, currently sorry at line 542) or through the bypass.

**Feasibility**: The bypass WAS introduced to avoid nf_exist_backward_prior. But both have the same mathematical content. One or the other must be proved.

## Key Architectural Insight

The constant-parent constraint in ExistPart (`fun _ => t`) is a **fundamental information gap**, not a fixable limitation. The 2-var NF at [x, t] with x != t depends on the ZONE STRUCTURE between x and t, which:
1. Is NOT determined by individual NF types (NfCompose counterexample)
2. Is NOT expressible via ih_exist's constant-parent formulas
3. IS expressible via temporal formulas (Rabinovich Section 5) using zone decomposition

The correct approach must encode zone structure in the temporal formula itself, not try to derive it from NF composition.
