**F6. Phase 2's mathematical structure, and where the case split lives.**
- *General over `sig`* (any `c`, any factorization `F`, `k ≥ 1`): if a *nonempty* segment at index `z ≠ 0` lies entirely inside a maximal constant run `[s, s+n)` of letter `ℓ`, then by `F.neg_type`/`F.pos_type` its side's common type is that of a nonempty `ℓ`-block, and by the keystone *every* segment on that side is a nonempty `ℓ`-block; since `W z → ∓∞` (from `cover`), the position just outside the run (`s - 1` or `s + n`) then lies in one of them and carries `ℓ`, contradicting maximality. So at most three segments meet the run: the one containing `s - 1`, the one containing `s + n`, and the middle one. A run of length `n ≥ 3·(m₀ + p)` therefore has a piece of length `≥ m₀ + p` inside one segment, and the surgery applies. **This is the case split the dispatch names, and it is bounded, not open** — but the threshold is `3·(m₀ + p)`, not phase 1's `m₀`; a general lemma stated with threshold `m₀` is not what the surgery proves.
- *On model A at `k ≥ 1`* (the record's actual need): far-below segments are nonempty pure-`ℓ₀`, far-above are nonempty pure-`ℓ₁` (nonemptiness of every negative/positive segment follows from `strict_neg`/`strict_pos` plus the keystone's first conjunct applied to `τneg`/`τpos`); the letter at `t` is `ℓ_now ∉ {ℓ₀, ℓ₁}`, so `t ∈ [W 0, W 1)`; the run positions `t+1 … t+n` carry `ℓ₀`, lie above `W 0 ≤ t`, and cannot be in a positive (pure-`ℓ₁`) segment. **The whole run is inside the middle segment.** One piece; threshold `m₀ + p` for the shrink direction; no re-cutting ever needed.
- *The surgery* (general over `sig`, no distinguishing needed): given `F` for `c` with `[s, s+j) ⊆ [W z₀, W (z₀+1))`, `c` constantly `ℓ` on `[s, s+j)`, `j ≥ m₀ + p`, let `c'` delete `[s, s+p)` (`c' P u = c P u` for `u < s`, `c' P u = c P (u + p)` for `u ≥ s`) and `W' z = W z` for `z ≤ z₀`, `W z - p` for `z > z₀`. Then: `mono` (the one cross case needs `W (z₀+1) ≥ s + j ≥ W z₀ + p`), `cover` (three ranges), `strict_pos`/`strict_neg` (translation or unchanged; the `z₀ ∈ {1, -2}` cases use `j > p`), and the type equations: untouched segments have literally equal `labels`; translated segments have equal `labels` (pointwise, via `labels_getElem`); the modified segment's labels are `u ++ ℓ^(j-p) ++ v` against `u ++ ℓ^j ++ v`, closed by `kTypeOf_segZ_eq_listSeg` twice and `kTypeOf_listSeg_append_congr` twice with phase 1 at `m := j - p ≥ m₀`. The triple is preserved by construction (`τneg, τzero, τpos` copied).
