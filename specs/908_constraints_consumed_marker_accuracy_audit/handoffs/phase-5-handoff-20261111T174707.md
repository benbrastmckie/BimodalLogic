## Key Decisions

- **The `id_comp` twin proves its germ-inverse step inline.** `Beh.ofGerm_germ` is the only
  germ-inverse form in `Behavior.lean` and it carries `[F.IsRegular]`; a C34a delegate's span may
  name no bundling class, so the twin could not use it. Rather than add a declaration to
  `Behavior.lean` (outside this phase's file territory), the twin carries a local
  `have hgerm : ∀ τ : Beh F 0, Beh.ofGermOfSerialLimit F hser hlim (Beh.germ τ) = τ`, which is
  `Behavior.lean`'s `ofGerm_germ` proof translated verbatim. `comp_id` needed no analogue: its
  `hR` already proved the corresponding fact by `Beh.ext` directly.
- **Both `PathCat` `def` twins are `@[reducible]`.** Without it,
  `PathCat.len_isDiscreteConduche_of_constraints` fails with four application type mismatches:
  `fac : Factorization ((lenOfConstraints …).map e)` no longer unifies with the
  `Factorization e.len` that `PathHom.cutState`/`factorLeft`/`factorRight`/`factor_comp` expect,
  because the extra `def` layer does not unfold at reducible transparency. Reducibility restores
  the projection-of-constructor reduction the originals relied on.
- **`PathCat.lenOfConstraints` needs a `letI` in its body.** With the type written as
  `@CategoryTheory.Functor (PathCat F) (PathCat.categoryOfConstraints …) (BObj F.Duration)
  (BObj.instCategory F.Duration)`, a `where`/`{ }` structure instance still fails with
  `failed to synthesize Category.{0,0} (PathCat F)`. Installing the twin category as a local
  instance first (`letI : Category (PathCat F) := PathCat.categoryOfConstraints F hcomp hser hlim`)
  fixes it; the local instance is the same term the expected type pins, so nothing is weakened.
- **`PathCat.len_map_of_constraints` spells `@CategoryTheory.Functor.map` in full.** Dot notation
  (`(PathCat.lenOfConstraints …).map f`) fails on the same instance synthesis even though the
  term's type names both instances.
- **No inversion needed anywhere.** All eight corollaries close by a bare positional application
  of their twin; the four `rfl`-proved originals (`id_len`, `len_map`, the two functoriality
  fields) still hold, and the full 2974-job library build was green on the first attempt after
  the elaboration fixes.
- `@[simp]` was kept on the corollary `PathHom.id_len` only, not duplicated onto its twin, to
  avoid a second `simp` lemma for the same equation.
- The module docstring needed no constraint-paragraph rewrite: unlike `Behavior.lean`, `Path.lean`
  makes no claim anywhere in its header about reaching the constraints "only through" the bundle.
