### Ordering resolution: (H) vs (I)

The task description says (I) `/todo` "MUST run LAST", and separately says (I) must run after
(H)'s counter fix. Those two instructions conflict once research's mechanism finding is applied:
`archive-task.sh` (which `/todo` invokes) does not touch the counter fields, so a counter write
performed before `/todo` is guaranteed stale the moment `/todo` removes seven tasks from
`active_projects`.

**Decision: `/todo` (Phase 6) runs after every tree-changing edit, and the counter recomputation
(Phase 7) runs after `/todo` as the terminal write.**

Justification. "Run `/todo` last" binds over the operations that change the *content* of the task
tree — (A)'s, (B)'s, (F)'s, and (G)'s field edits — because `/todo` copies task records into
`specs/archive/state.json`, and an archived record must carry the corrected text. Phases 1-4 all
precede Phase 6, so that requirement is met in full. (H)'s counter write is not a tree change: it
is a *derived* value, a pure function of the post-archive `active_projects` array. Computing it
before `/todo` would require computing it twice; computing it after `/todo` requires computing it
once, against the final tree. None of the seven tasks `/todo` archives is touched by Phases 1-4,
so there is no interaction in the other direction. This is also the resolution research reached
independently ("running `/todo` last ... is still correct because it changes which tasks are
counted, just not via the same code path that would fix the stale counter fields").

## Rollback/Contingency

- Every phase is one or two `state-write.sh` calls plus a verification command, and each phase
  commits separately (`task 470 phase {P}: {name}`). Reverting one phase is a single `git revert`
  of its commit.

  file untouched), so a filter typo cannot corrupt `specs/state.json` — it fails closed.
- Before Phase 6 (`/todo`, the only phase that moves records between files), run
  `bash .claude/scripts/git-snapshot.sh 470` so the archival is reversible without a dirty-tree
  destructive-git operation.
- If Phase 7's `/task --sync` makes an unwanted status change, revert that one field with a
  targeted `state-write.sh` call rather than reverting the whole sync — the sync's other effects
  (artifact backfill, TODO regeneration) are wanted.
- If any phase discovers its premise no longer holds (e.g. 428's edge absent, 468 no longer
  `not_started`, a third null description), **stop and report** rather than improvising. A changed
  premise means the tree moved since research and the remaining phases need re-checking.
