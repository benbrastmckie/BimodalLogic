## Decisions

- `operatorArgs?` takes the formula type as an `Expr`, and callers pass `language.formulaType`. The proof mode's `Judgment` still carries a `Language`, which selects rule names; recognition no longer depends on it.
- Recognition tries `Sig.<op>` first and the class projection `Has<Op>.<op>` second, so a primitive (`imp`, `box`, `untl`, `snce`, `stab`, `bot`) and a derived operator go through one path. The class name is formed from the operator's spelling.
- The probe is built by instantiating the signature declaration's binders and synthesizing each instance, not by `mkAppM`, which cannot fix the carrier type of a nullary operator such as `top` or `bot`.
- `formulaApp` resolves the per-language constant by namespace (`operatorConst`). A renamed source declaration is now caught by the test module and the proof-mode tests, not by a double-backtick name in a table.

- `HasStab` stays the operator-carrying class. `docs/development/stability-operator-family.md` files `⊡` under Modal, which rules out a stability bundle or family class; it does not make `stab` a non-primitive.
- The classes are universe-polymorphic (`Type u`), as in the prototype. The clause classes take `L : Type`, which a `Type u` class accepts.
- `Sig.next` and `Sig.prev` are stated over `HasBot` and one temporal class only, without `HasImp`, matching `TemporalRules.next`/`prev`.
- `Sig.dstab` is filed in the Modal section beside `Sig.diamond`, following the stability-family record.
- `sig%` replaces `Sig.op` by `T.op` only when the two are definitionally equal on the arguments at hand. A language whose `T.op` is something else is rejected by name; the prototype would have substituted it silently.
- `sig%` accepts only a term whose head is a `Sig` operator, so it cannot be used to unfold an arbitrary definition.
- The three primed operators are tested on a second toy type. A type with both `untl` and a primitive `allFuture` constructor would give `Sig.allFuture` (derived from Until) and the constructor the same per-type name.
- The module-invariants gate is read as a delta against its two Phase 1 baseline failures.
