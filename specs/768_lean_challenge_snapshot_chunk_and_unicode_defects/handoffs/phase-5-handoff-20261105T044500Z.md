## Key Decisions Made

- New exit code 74, distinct from 0/64/65/71/73, documented as FATAL (unlike `--check`'s
  advisory 65).
- Detection requires BOTH conditions (toolchain AND Lake project) -- neither alone suffices.
- The scratch file lives in a fresh `mktemp -d` directory, never under `project_root`, so the
  compile step cannot write a stray `.lean` file into the target project. (Lake's own
  `lake-manifest.json` bootstrap write, if the target project has never been built, is inherent
  Lake behavior for any Lake project and not something this step introduces or can avoid; a real
  target project that can build at all will already have a committed manifest.)
- A bare unbound identifier in a theorem's TYPE SIGNATURE does not force a real compile failure
  -- Lean 4's `autoImplicit` silently auto-binds it. An unbound identifier in FUNCTION
  APPLICATION position (`nonexistentFunctionXyz n m`) cannot be rescued this way and genuinely
  fails; this is the fixture shape R15-REAL's failure sub-case uses.
- `extract_r1()` always force-rewrites a theorem's body to `:= sorry`, so corrupting a plan's
  Lean Challenge Statement BODY has no effect on the assembled module; only a SIGNATURE
  corruption reaches the real compiler.
