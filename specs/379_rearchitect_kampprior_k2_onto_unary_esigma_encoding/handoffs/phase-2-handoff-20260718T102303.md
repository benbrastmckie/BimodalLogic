## DESIGN FINDING (escalate — blocks Phase 3 as written)

Rabinovich Def 3.1 (PDF p.4) makes the point/interval types `αⱼ, βⱼ` **quantifier-free FORMULAS**
(partial types), freely conjoinable — including *contradictory* conjunctions that force an interval
empty (paper footnote 2, p.5). The landed Lean encoding `UnaryType = NormalForm (sigE sig F) 0 1`
is a **complete** type (`nf_eval_nf` depth 0 = exact atom match; `nf_eval_unique`; never
contradictory). Therefore:
- There is no faithful conjunction on `UnaryType`.
- A **full-consistency** `conjInterleave_iff` is FALSE. Counterexample: two sentences (r=0), each
  with points a<b; a,b order-adjacent in a 2-point model (between-interval empty → both interval
  constraints vacuous → both satisfied); ψ₁, ψ₂ carry DIFFERENT complete between-interval types
  τ_A ≠ τ_B. The unique rank-merge is interval-inconsistent, so a full-consistency `conjInterleave`
  has no satisfied disjunct → `veeSat` FALSE while `efSat ψ₁ ∧ efSat ψ₂` TRUE.
- **Forward** is fine with point-consistency-only (proved-true skeleton here).
- **Backward/iff (Phase 3)** genuinely needs partial (conjoinable, possibly-contradictory) interval
  types. Options: change `ExistsForallFormula.pointType/intervalType` to `Fin _ → List (UnaryType)`
  (a disjunction-of-complete-types = partial formula; conjunction = list product / intersection) or
  `Finset (UnaryType)` (set of admissible completions; conjunction = intersection; empty = ⊥). This
  changes a LANDED, depended-upon type (`Prop42*`, `Prop35*`, `ExistsForallLemmas` consume it), so
  it is an orchestrator/user design decision, not a unilateral Phase-3 rewrite.
