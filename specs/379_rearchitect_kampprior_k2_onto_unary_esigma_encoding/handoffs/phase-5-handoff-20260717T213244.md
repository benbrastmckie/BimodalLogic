4. **Witness-matching layer** (the anticipated "genuinely fiddly" piece — turned out simpler than

   needed for the `castSucc`/`succ` conversions themselves (verified via `lean_run_code` before
   committing to the approach). `Fin.ext`+`omega` was still needed, but only for the
   `min`/Nat-subtraction index-value collapses (e.g. `min (k.val+1+i) ψ.n = k.val+1+i` given
   `i < d`), proved via the reliable `have e : rawA = rawB := by omega; simp only [e]` pattern
   (direct `Fin.ext (by omega)` in term mode does NOT work — `omega`'s tactic-block goal isn't
   pre-reduced past the `Fin.mk`/`.val` projection without an explicit `show`, confirmed by a
   failed `lean_run_code` probe). `mpr` (the reverse direction, gluing two `Nat`-chains into a
   single `Fin (ψ.n+1)`-indexed witness) uses
   `x := fun j => if j.val ≤ k.val then x'' (k.val - j.val) else x' (j.val - k.val)` — the `≤`
   (not `<`) convention on the `if` was chosen deliberately: it makes both boundary facts
   (`x 0 = x'' k.val`, `x (Fin.last ψ.n) = x' (ψ.n - k.val)`) hold **unconditionally**, without a
   further case split on whether `k.val = 0` or `k.val = ψ.n`.

**Proof-engineering lessons for future `Fin`-index-bridging work in this codebase** (load-bearing
for anyone re-deriving similar coordinate bridges):
- `Fin.castSucc`/`Fin.succ` compose with `Fin.mk` **definitionally** (`rfl`), so prefer stating
  the target goal in terms of `x i.castSucc`/`x i.succ` directly (matching what hypotheses like
  `efSat`'s `hbetween` actually provide) rather than pre-converting to `⟨i.val, _⟩` form — the
  conversion is free via `exact`'s defeq check, but only if you don't also need `rw` (which is
  syntactic) to see through it.
- For value-level arithmetic equalities involving `min`/Nat truncated subtraction inside a
  `Fin.mk`'s first component, use `have e : rawA = rawB := by omega; simp only [e]` — NOT
  `Fin.ext (by omega)` in term mode (the latter's `omega` block sees the un-reduced
  `(⟨_,_⟩ : Fin n).val` goal and fails; a `show`-qualified tactic block fixes it if you want the
  `Fin.ext` route, but the `have`+`simp only` route is more robust and was used throughout).
- `rw` requires exact syntactic (Fin-literal) match; when a hypothesis or goal uses the library's
  `(0 : Fin (n+1))`/`Fin.last n` notation, restate lemmas using that same notation rather than an
  explicit `⟨0, proof⟩`/`⟨n, proof⟩` anonymous constructor — otherwise `rw` silently fails to find
  the pattern even though the two forms are defeq (caught this via a `rewrite ... did not find an
  occurrence` compiler error, not a manual review).
