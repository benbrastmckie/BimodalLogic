   merged point has no single complete point type. `mergedPointType` selects the pinning chain's

## DESIGN FINDING (must adjudicate before backward)

Plan Task 1's "keep point-consistency as the point filter" is necessary but **NOT sufficient** for
the backward direction. A chain-2 existential point interior to a chain-1 open interval must, under
`efSat ψ₁`, satisfy `ψ₁`'s interval type there; but the merged formula records only its complete
point type (`mergedPointType = ψ₂.pointType i`), NOT that this type ∈ `ψ₁.intervalType (covering
slot)`. Without an extra filter, the backward direction is UNSOUND.

**Micro-counterexample:** `ψ₁` = "point `α`; everything after `α` is `β`" (interval-after set `{β}`),
`ψ₂` = "point `γ`" with `γ ∉ {β}`. The size-2 merge with `γ` placed after `α` is valid and
point-consistent, but a model of that merged disjunct puts `γ` (not in `{β}`) after `α`, so `ψ₁`
fails ⇒ backward broken.

**Fix (recommended):** add a decidable **cross-consistency** conjunct to the `conjInterleave` filter:
for every merged existential point pinned by chain `k` and interior to chain `(3-k)` (`∀ i', e_{3-k} i' ≠ e_k i`),
require `ψ_k.pointType i ∈ ψ_{3-k}.intervalType (intervalSlot e_{3-k} (e_k i))` (a `Finset`
membership; `intervalSlot`/`belowCount` already defined). The forward direction stays TRUE (a
realized merge from two actually-satisfied chains is automatically cross-consistent: the interior
point realizes the other chain's interval set, and its complete type equals `ψ_k.pointType i` by
`nf_eval_unique`). This is the point-vs-interval analog of the Phase-2 interval-vs-interval finding.
