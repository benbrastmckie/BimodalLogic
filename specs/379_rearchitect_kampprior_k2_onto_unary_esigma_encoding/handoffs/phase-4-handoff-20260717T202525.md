### The gluing construction (§8 building blocks, all sorry-free)

- `pinnedPositions ψ := univ.image ψ.pin` — the set of existential positions pinned by some free
  variable; `mem_pinnedPositions`, `pinnedPositions_nonempty` (for `0 < r`).
- `idxOf ψ hr s` — a free-variable index pinning a pinned position `s` (junk off the pinned set);
  `pin_idxOf`.
- `loPos ψ hr j` / `hiPos ψ hr j` — nearest pinned position `≤ j` / `≥ j`, clamped to the least /
  greatest pin at the ends (via `Finset.filter` + `max'`/`min'`). Key lemmas: `loPos_of_mem` /
  `hiPos_of_mem` (at a pinned position both brackets equal the position), `loPos_succ_eq_castSucc`
  / `hiPos_castSucc_eq_succ` (brackets are constant across a gap step — proved via `Finset.filter`
  equality + `dite_max'_congr`/`dite_min'_congr`), `loPos_mem`/`hiPos_mem`.
- `chainOf N env ψ hconj k l` — the pairwise-projection witness chain of the pair `(k,l)`, from
  `pairProject_pins ∘ pairwiseProjections_sat`; `chainOf_spec` (StrictMono + env-at-pins + the six
  clause families). `chainOf_at_pin_left`/`_right` (reading a bracket chain at a position it pins
  gives the env value).
- `gluedChain N env ψ hconj hr j := chainOf … (idxOf (loPos j)) (idxOf (hiPos j)) j` — **uniform
  definition, no pinned/gap case split**: at a pinned position both brackets are the position
  itself, so the diagonal bracket chain reads back the env value automatically.
- `gluedChain_pin` (clause 2), `gluedChain_pointType` (clause 3), `gluedChain_before` (clause 4),
  `gluedChain_after` (clause 6): each reads directly off the responsible bracket chain's own clause
  at the same position — no reconciliation.
- `consecChain` (the one lemma with case analysis, 4 cases on pinned-ness of the two endpoints):
  for each edge there is a **single** bracket chain `(k,l)` computing the glued chain at BOTH
  endpoints — the uniform witness is `k = idxOf(loPos castSucc)`, `l = idxOf(hiPos succ)`, and a
  pinned endpoint's value is that chain's value there regardless of the other slot. From it,
  `gluedChain_strictMono` (via `Fin.strictMono_iff_lt_succ` + `Fin.castSucc_lt_succ`) and
  `gluedChain_between` (clause 5) follow with the interval matching EXACTLY (no sub-interval
  monotonicity needed, because `consecChain`'s shared chain has identical endpoints).

Design note: because consecutive positions share one bracket chain, the between-interval type
matches the bracket chain's interval verbatim — so `unaryHolds_subinterval` (landed the prior
dispatch as anticipated infrastructure) turned out NOT to be needed. It remains available.
