The prior handoff (`phase-5-handoff-20260717T204500.md`) pointed at `VVecEA2.translateRight`/
`translateLeft` + `bracketBuildRight`/`chainHolds` (`NfToVecEA.lean`/`VecEATranslation.lean`) as

a match for `efSat`'s unbounded-tail, interior-pinned shape.

Investigating `Translation.lean` (imported transitively but not previously connected to the
Phase-3 object) found the actual match: **`Kamp.translateEF1` / `Kamp.translateEF1_correct`**,
pre-existing, signature-generic, sorry-free, and already unbounded-cap-native:

```
translateEF1 n k alpha beta :=
  Formula.and (alpha k).formula (Formula.and (buildRight rightPairs (beta (n+1)))
                                              (buildLeft  leftPairs  (beta 0)))
```

`buildRight [] rightmost = G(rightmost)` (the `[]`-base-case IS the unbounded "henceforth" cap —
already proved correct by `buildRight_correct` in `Translation.lean`) and symmetrically
`buildLeft [] leftmost = H(leftmost)`. This is *exactly* Def 3.1's `(∀y)_{>xₙ} β_{n+1}(y)` /
`(∀y)^{<x₀} β₀(y)` unbounded clauses. **The "new unbounded terminal cap" work the prior handoff
anticipated was therefore already done** (by whichever earlier task built `Translation.lean` for
the legacy `VEF1`/`translateEF1` — likely as part of the original `nf_nvar_exist_all_depths`
machinery this whole re-architecture is replacing). What was NOT already done, and IS the genuine
new content, is the bridge between `translateEF1`'s `List.finRange`-indexed recursive chain
specification (`buildRight_spec`/`buildLeft_spec`) and `efSat`'s `StrictMono`-witness-function
formulation (`x : Fin (ψ.n+1) → carrier`).

## What landed this dispatch — `Prop35Chain.lean`

Two generic, `Nat`-indexed bridging lemmas (the hard combinatorial core of Prop 3.5's chain):

- **`buildRight_spec_iff_chain`**: `buildRight_spec M atomMap ((List.finRange d).map fun i =>
  (alpha_ i.val, beta_ i.val)) rightmost t0` holds iff there is a chain `x : Nat → M.carrier` with
  `x 0 = t0`, strictly increasing on `[0,d]`, `alpha_ i` at `x(i+1)`, `beta_ i` on `(x i, x(i+1))`,
  and `rightmost` holding everywhere past `x d`.
- **`buildLeft_spec_iff_chain`**: the `Since` mirror (`x` strictly *decreasing*, cap holds
  everywhere *before* `x d`).

**Proof technique** (both, by induction on `d`, with `alpha_`/`beta_`/`rightmost` (or `leftmost`)
universally quantified *inside* the induction — required so the induction hypothesis can be
applied to the *shifted* functions `fun n => alpha_ (n+1)` at each recursive step; quantifying
them *outside* the induction, as a first draft did, produces an unfixable index mismatch between
the induction hypothesis's unshifted conclusion and the shifted list the `succ` case actually
needs — this is the one real pitfall in this proof and cost one full failed iteration before the
fix): `List.finRange_succ` peels the list head; the two directions of the `iff` are proved
together; the witness/extraction chain is glued via a `match`-based combinator `fun m => match m
with | 0 => t0 | m' + 1 => x' m'` (chosen over `Fin.cons` specifically to avoid `Fin.succ`/
`Fin.castSucc` coercion-lemma bookkeeping — `X (m+1) = x' m` holds by `rfl`, no simp needed).

## The remaining Phase-5 work (5.3-5.6) — precise next steps

This is now bookkeeping, not new mathematics. Three index-translation layers, each via the same
`Fin.ext` + `omega` technique (proof-irrelevance means `Fin.mk` values with the same `.val` are
definitionally equal once the `.val` equality is established):

1. **`efPointTP`/`efIntervalTP`** (trivial): render `ψ.pointType j` / `ψ.intervalType i`
   (`UnaryType`s) as `TemporalPred`s via `⟨unaryToFormula atomMap h_surj …⟩`, with the eval
   correctness lemma following directly from `unaryToFormula_correct` (Prop 3.5 atomic layer,
   already landed in `Prop35ExistsForall.lean`).
2. **`translateProp35 ψ := translateEF1 ψ.n (ψ.pin 0) efPointTP efIntervalTP`** — the definition
   itself is immediate given (1).
3. **The correctness proof's list-equality step** (layer 1 of 2 remaining): `rw
   [translateProp35, translateEF1_correct]` produces a goal whose right/left components are
   `buildRight_spec`/`buildLeft_spec` applied to `translateEF1`'s literal `let idx := k.val+1+i.val;
   (alpha ⟨idx,_⟩, beta ⟨idx,_⟩)`-style maps. To apply `buildRight_spec_iff_chain`/
   `buildLeft_spec_iff_chain` (which expect `Nat`-domain `alpha_`/`beta_`), define **clamped**
   totalizations, e.g. `alphaR i := efPointTP atomMap h_surj ψ ⟨min (k.val+1+i) ψ.n, by omega⟩`
   (the `min`-clamp makes the function total over all of `Nat`, not just the in-range indices),
   then prove the list equality `(List.finRange d).map (translateEF1's literal map) =
   (List.finRange d).map (fun i => (alphaR i.val, betaR i.val))` via **`List.map_congr_left`**
   (`{f g} (h : ∀ a ∈ l, f a = g a) : l.map f = l.map g`) — the pointwise proof uses `i.isLt : i.val
   < d` (automatic for `i : Fin d`) to show `min (k.val+1+i.val) ψ.n = k.val+1+i.val` via `omega`,
   then `Fin.ext` to convert the `Fin`-value equality into application equality. `rw` this list
   equality into the goal, then apply `buildRight_spec_iff_chain`/`buildLeft_spec_iff_chain`.
4. **The witness-matching step** (layer 2 of 2 remaining, the one genuinely fiddly part left):
   `efSat`'s segment clause is stated as `∀ (i : Fin ψ.n) (y), x i.castSucc < y → y < x i.succ →
   unaryHolds N (ψ.intervalType i.succ.castSucc) y` — i.e. indexed via `Fin.succ`/`Fin.castSucc`
   on `Fin ψ.n`/`Fin (ψ.n+1)` — while the generic chain lemma's conclusion is indexed by plain
   `Nat` (`beta_ i` for `i : Nat`, `i < d`). Bridge via a **clamped `Nat`-indexed view of `ψ`'s own
   `x`** (`xR i := x ⟨min (k.val + i) ψ.n, by omega⟩` for the right side, mirrored for left), and
   match `i.succ.val = i.val + 1` / `i.castSucc.val = i.val` (defeq or one-line `simp`/`omega`) to
   align `ψ`'s `Fin`-indexed hypotheses (`hpt`, the three `efSat` interval clauses) with the
   generic lemma's `Nat`-indexed existential slots. This is symmetric for the two directions (mp:
   extract the `Nat`-chain from `ψ`'s `x`; mpr: extract a `Fin`-indexed `x` by gluing the two
   `Nat`-chains, using `hpin 0 : env 0 = x k` as the shared basepoint) and is the same technique as
   step 3, applied at one more index-translation layer.
5. **Assemble** the full biconditional `efSat N env ψ ↔ temporal_truth N atomMap (env 0)
   (translateProp35 atomMap h_surj ψ)` from: point type at the pin (direct via
   `efPointTP_eval`/`hpin 0`) `∧` right chain (step 4) `∧` left chain (step 4, mirrored).
6. **Lift to `VeeExistsForall`**: `translateVeeProp35 Ψ := translateVEF1 (Ψ.map (translateProp35
   …))`, correctness via `translateVEF1_correct` (`ExistsForallNF.lean`, pre-existing) — this part
   is a direct mirror of `VVecEA2.translateRight`'s own `translateVEF1` wrapper
   (`NfToVecEA.lean:447-451`) and should be mechanical once (5) lands.

**Why this dispatch stopped here rather than pushing through (5.3-5.6):** the two generic bridging
lemmas (the combinatorial core, ~230 lines, two inductive proofs with a real pitfall already hit
and fixed once) were the highest-risk content and are now a solid, verified green foundation. The
remaining work is real but mechanical index bookkeeping across three coordinate systems (`ψ`'s
own `Fin (ψ.n+1)`-indexed `x`, `translateEF1`'s `Fin`-indexed `alpha`/`beta` with `List.finRange`-
computed indices, and the generic lemma's `Nat`-indexed `alpha_`/`beta_`) — attempting it in the
same dispatch risked either an incomplete/sorry-containing proof (prohibited) or an unreviewable
wall of index arithmetic with no green checkpoint. Landing the bridge as its own verified,
committed milestone is the safer decomposition.
