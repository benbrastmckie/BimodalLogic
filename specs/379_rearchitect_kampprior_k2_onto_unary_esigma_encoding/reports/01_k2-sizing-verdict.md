## 1. Sizing Verdict

### (a) is REFUTED

**(a) requires**: the arity-4 obligation is generated by the *arms*, so re-architecting the arms
removes it while `nf_eval_nf` stays in the statements.

**Machine-checked refutation.** The live entry is
`nf_nvar_exist_all_depths ... k 1 _ (sub_nf : NormalForm sig k (1+1))`, i.e. `NormalForm sig k 2`.
Unfolding that **type** — no proof, no arm, no tactic — reaches arity 4 at exactly k=2. All of
the following are `rfl`, EXIT 0:

```lean

example : NormalForm sig 0 2 = (AtomKind sig 2 → Bool) := rfl

-- k = 1: one descent. Max arity 3. Arity 4 NEVER arises.
example : NormalForm sig 1 2 = ((AtomKind sig 2 → Bool) × (NormalForm sig 0 3 → Bool)) := rfl

-- k = 2: TWO descents. Arity 4 arises.
example : NormalForm sig 2 2 = ((AtomKind sig 2 → Bool) × (NormalForm sig 1 3 → Bool)) := rfl
example : NormalForm sig 1 3 = ((AtomKind sig 3 → Bool) × (NormalForm sig 0 4 → Bool)) := rfl
```

**The k>=2 arm boundary and the arity-4 emergence are the same event.** This is not a
coincidence to be explained; it is one fact. k=0 and k=1 landed *because* arity 4 is
unreachable below k=2. The arm boundary is a *consequence* of the type's arity arithmetic.

The same growth is present in the **statement's meaning**, also by `rfl`:

```lean

    (a2 : AtomKind sig 2 → Bool) (q2 : NormalForm sig 1 3 → Bool) :
    nf_eval_nf M 2 2 env (a2, q2) =
      ((∀ (a : AtomKind sig 2), atom_eval M env a ↔ (a2 a = true)) ∧
```

One further descent produces the arity-4 environment `Fin.cons y (Fin.cons x env) : Fin 4 → M.carrier`

**(a) is dead.** No re-architecture of the arms can remove an obligation that the arms' own

### The verdict: (b), amended — and larger than (b) as written

**Why Rabinovich never grows arity** (Def 4.1, PDF p.5, verbatim):

> "Let M be a Sigma chain. We denote by E[Sigma] the set of unary predicate names
> **Sigma ∪ {A | A is an TL(Until, Since)-formula over Sigma}**. The canonical TL(Until,Since)-expansion
> of M is an expansion of M to an E[Sigma]-chain, where each predicate name A ∈ E[Sigma]
> is interpreted as {a ∈ M | M, a |= A}."

E[Sigma] is a **signature expansion**. Each already-processed TL formula becomes a **new unary
predicate name** — hence an **atom**, of quantifier depth **zero**, in a **larger alphabet**.
PDF p.6 states the collapse step that keeps depth from accumulating:

> "Note that if A is a TL(Until,Since) formula over E[Sigma] predicates, then it is equivalent
> to a TL(Until,Since) formula over Sigma, and hence to **an atomic formula in the canonical
> TL(Until,Since)-expansions**."

Prop 4.3 (p.6) then inducts over **formula structure**, and at each step already-processed
content is an **atom**. **The signature grows; the depth does not; the arity does not.**

**The repo's mis-transcription.** `EAtomDom sig k n := ZoneSpec n × NormalForm sig k 1` keeps
**depth k** in the atom over the **same signature `sig`**. That is a *projection* of a depth-k
object onto arity 1 — and projections are lossy, correctly refuted by task 327/F2. NfEFold's own
header docstring states the correct mechanism — *"all already-processed quantifier depth is folded
into the **signature** as a unary E[Sigma]-atom"* — but `EAtomDom` **does not fold into the
signature**. It folds into an arity-1 NF **at the same sig and the same depth k**. That gap
between the docstring and the type is the defect.

**Repo-wide search confirms no signature expansion exists**:
- `MonadicSignature` (`MonadicFO.lean:41`) is a bare `structure` with `preds : Type` and **no
  expansion operation**.
- No live declaration varies the signature (`sig -> sig'`). The single hit,
  `ExpressiveCompleteness/Theorem.lean:63`, is in **bit-rotted dead code** (see §3).

**So the true scope is**: build an E[Sigma] alphabet-expansion layer, re-transcribe Def 3.1 /
Prop 3.5 / Prop 4.3 onto it, migrate four chain statements, and re-check `no_gaps_discrete_model_surgery`.
This is **strictly larger than both (a) and (b)-as-written**.

## 2. The `nf_eval_nf` Arity-Growth Adjudication

**Task 376's claim, verbatim**: *"nf_eval_nf grows arity n->n+1 per depth descent, whereas
Rabinovich never grows arity; the repo's NormalForm sig k n is a Hintikka n-type, not Def 3.1's
object (no ordered existential prefix, no alpha/beta interval layer), making Lemma 3.2(2) a
theorem about the former and a NON-theorem about the latter."*

### Verdict: CONFIRMED, and the root is one level DEEPER than 376 stated.

376 located the growth in **the evaluator**. The growth is in **the type**. `rfl`:

```lean
example : NormalForm sig (k + 1) n
        = ((AtomKind sig n → Bool) × (NormalForm sig k (n + 1) → Bool)) := rfl
```

The quant-assignment component of `NormalForm sig (k+1) n` has **domain `NormalForm sig k (n+1)`**.
An evaluator for that component *must* evaluate inhabitants of an arity-`(n+1)` type. `nf_eval_nf`
is not gratuitously growing arity — **it is forced to by the type it eliminates**. Witness, `rfl`:

```lean
example (nf : NormalForm sig (k + 1) n) : NormalForm sig k (n + 1) → Bool := nf.quant_assgn
```

**Why this distinction decides the sizing.** If the growth were the evaluator's free choice, an
arity-preserving evaluator for the *same* `NormalForm` type could be written and swapped in —
statements would keep their types and (a) might survive. It is not. **`nf_eval_nf` cannot be
fixed without changing `NormalForm`**, and changing `NormalForm` changes the *type of every
object in every statement on the chain*. That is what makes this a statement migration and
kills (a).

**376's Def 3.1 characterization is also confirmed against the PDF** (p.4): Def 3.1's object is
`∃x_n...∃x_0 [ordering ∧ ⋀ alpha_j(x_j) ∧ ⋀ (∀y)^{<x_j}_{>x_{j-1}} beta_j(y) ∧ ...]` — an
**ordered existential prefix**, **unary quantifier-free** point types `alpha_j`, and an
**interval (beta) layer**. `NormalForm sig k n` has none of these three. It is a Hintikka
n-type. **376 was right.**

**The one correction to 376**: 376 said Rabinovich "never grows arity" as if it were a design
choice to be imitated. It is a **consequence** of Def 4.1's alphabet expansion (p.5). You cannot
imitate the cap without the expansion — which is exactly what NfEFold attempted, and exactly why
its own note records that it fails at k>=1.

### The `Fintype` obstruction (shapes the gate — verify before ANY proof work)

`MonadicSignature` (`MonadicFO.lean:41-44`) **requires `Fintype`**:

```lean
structure MonadicSignature where
  preds : Type
  [fintypePreds : Fintype preds]
  [decEqPreds : DecidableEq preds]
```

Rabinovich's `E[Sigma] := Sigma ∪ {A | A a TL formula over Sigma}` is **countably infinite** — it
is **not a `Fintype`**, so a literal E[Sigma] **cannot be a `MonadicSignature`**. And the
`Fintype` instance is load-bearing: `normalForm_fintype` (`NormalForm.lean:166-183`) derives
`Fintype`/`DecidableEq` for `NormalForm` by induction on k, and the whole NF apparatus rests on it.

This is **not necessarily fatal** — Rabinovich's Prop 4.3 induction adds only **finitely many**
new atoms per stage, so a **stage-indexed finite expansion** is the plausible design. But it is
**unbuilt, unproven, and the single highest-risk unknown in the re-scoped program.** It is the
right thing to gate on (§6).
