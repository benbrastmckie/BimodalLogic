## The 2 Remaining Sorries

### Sorry at line 1307: `extendPoint b' <= a' k` (in b <= a_k case)

**Goal**: Given `hba : extendPoint b <= a k`, prove `extendPoint b' <= a' k`.

**Context**: b comes from `decomp_point_challenge_NM h_base b' hb'` (base decomposition on [x,y]/[x',y']). The base WC gives ordering between b and x/y. But it does NOT give ordering between b and individual selections a_k.

**The fundamental problem**: The base decomposition on [x,y] gives a matching b for b' with WC relating b to x and y. But the ordering between b and each selection element a_k is NOT determined by the base WC alone. The ordering between b and x/y doesn't determine the ordering between b and a_k (both b and a_k are in [x,y] but their relative order is unknown).

**Correct approach** (not yet implemented): Instead of getting b from the base decomposition on [x,y], get b from a SUB-INTERVAL decomposition that's compatible with the sorted selection:
1. Find which sorted sub-interval `[a o sigma(i), a o sigma(i+1)]` (or boundary intervals `[x, a o sigma(0)]`, `[a o sigma(n-1), y]`) contains b' on the N side.
2. Use `h_univ` on that sub-interval to get a decomposition.
3. Match b' from that decomposition to get b in the corresponding M-side sub-interval.
4. The WC gives ordering between b and the sub-interval boundaries (consecutive sorted elements).
5. For other elements: chain through monotonicity (b is between consecutive sorted elements, so b < a_j for j > i+1 and a_j < b for j < i).

This avoids the fundamental problem because b and b' are matched in a sub-interval that has the selections as boundaries, so the ordering is determined.

## Key Architectural Insight

The current proof structure gets b from `decomp_point_challenge_NM h_base`, which uses the FULL interval [x,y]/[x',y']. This is wrong because the full-interval matching doesn't provide ordering between b and individual selections.

The fix requires restructuring the point challenge section: instead of one call to `decomp_point_challenge_NM h_base`, the proof should:
1. Determine which sub-interval of the sorted selection b' falls into
2. Get the sub-interval decomposition from `h_univ`  
3. Match b' using the sub-interval decomposition
4. Extract ordering from the sub-interval WC

This is a significant restructuring of the point challenge section (lines ~1191-1340).
