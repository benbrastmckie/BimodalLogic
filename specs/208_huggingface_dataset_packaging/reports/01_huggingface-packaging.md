## Executive Summary

- HuggingFace Hub supports JSONL natively; Parquet is recommended but auto-converted anyway — uploading JSONL directly with `push_to_hub()` is the lowest-friction path and fully supported.
- Use **4 configs** in the YAML frontmatter: `bmlogic-bench` (default), `bmlogic-c5`, `bmlogic-c7`, `proof-steps`; each with a single split matching its natural role (test/train/train/train).
- NeurIPS 2026 requires a public HuggingFace dataset, a Croissant metadata file (auto-generated by HF once uploaded), and manually-added Responsible AI (RAI) fields — all achievable in one publishing workflow.
- Recommended license for NeurIPS submission: **CC BY 4.0** (maximally open, preferred by NeurIPS; current MIT license is also accepted but CC BY is the community standard for datasets).
- Total size is ~68 MB across all files; no LFS complications for the Hub since the largest file (bmlogic-c7, ~52 MB) is well under the 200 GB limit.

## Findings

### 1. HuggingFace Dataset Format Requirements

**Repository structure** (minimal viable):
```
logos-labs/bmlogic-bench/
├── README.md                   # dataset card with YAML frontmatter
├── data/
│   ├── bmlogic-bench.jsonl     # or Parquet equivalent
│   ├── bmlogic-c5.jsonl
│   ├── bmlogic-c7.jsonl
│   └── proof_steps.jsonl
```

**YAML frontmatter** is the primary configuration mechanism. It lives at the top of `README.md` between `---` delimiters. Key fields:
- `configs` — list of named configurations, each with `config_name`, `data_files` (with `split` and `path`), and optionally `default: true`
- `language`, `license`, `task_categories`, `tags`, `size_categories` — discovery metadata
- `pretty_name` — display name on Hub

`config_name` is **required** even if there is only one configuration.

**Automatic Parquet conversion**: HF Hub auto-converts every dataset to Parquet for the Dataset Viewer (the first 5 GB per config). This means JSONL can be uploaded directly — Parquet conversion happens server-side for browsing, while the original JSONL files remain available for download.

### 2. Recommended Directory Structure

```
logos-labs/bmlogic-bench/
├── README.md                              # dataset card (YAML + prose)
├── data/
│   ├── bmlogic-bench.jsonl               # test split for bmlogic-bench config
│   ├── bmlogic-c5.jsonl                  # train split for bmlogic-c5 config
│   ├── bmlogic-c7.jsonl                  # train split for bmlogic-c7 config
│   └── proof_steps.jsonl                 # train split for proof-steps config
```

Files can live at the repo root or in a `data/` subdirectory — both work. Using `data/` is cleaner for multi-config datasets.

### 3. Split Strategy Recommendation

The four datasets serve distinct roles and should be **separate configs** (not splits of a single dataset), because their schemas differ:

| Config name | File | Split | Rationale |
|---|---|---|---|
| `bmlogic-bench` | `bmlogic-bench.jsonl` | `test` | This IS the benchmark — held-out evaluation |
| `bmlogic-c5` | `bmlogic-c5.jsonl` | `train` | Small exhaustive training set |
| `bmlogic-c7` | `bmlogic-c7.jsonl` | `train` | Large primary training corpus |
| `proof-steps` | `proof_steps.jsonl` | `train` | Proof supervision data, different schema |

**Why not a train/val/test split within a single config?**
- The schemas differ (13 fields vs 14 fields vs 8 fields) — a single config requires uniform schema.
- bmlogic-bench was curated separately with stratified sampling; it is not a random split of c5/c7.
- Users loading just the benchmark (the most common case) should not download 52 MB of training data.

**Making `bmlogic-bench` the default config** means `load_dataset("logos-labs/bmlogic-bench")` returns the 727-record benchmark, which is the natural entry point for evaluation users.

**Optional**: A thin validation split (e.g., 10% random holdout from c5) could be carved out during the Python upload script, but this adds complexity without clear benefit since c5 is an exhaustive enumeration and random holdout is less meaningful than the curated bench.

### 4. Parquet vs JSONL Recommendation

**Recommendation: Upload as JSONL, let HF convert to Parquet automatically.**

Rationale:
- All four files are well under 5 GB (total ~68 MB): the auto-converter handles everything.
- JSONL is the source-of-truth format already in use in the project.
- Complex nested fields (`formula_ast`, `proof_trace`, `countermodel`) are JSON objects — these map cleanly to `Value('string')` or `dict` features in Parquet, but JSONL avoids needing to flatten or pre-specify schemas.
- If explicit Parquet is desired for performance, the Python upload script can use `Dataset.from_generator()` with `push_to_hub(..., max_shard_size="100MB")` which handles conversion.

**When to prefer Parquet explicitly**: Only if the dataset were >5 GB or if the nested JSON structure caused schema-inference failures (unlikely here since the schemas are clean and well-documented).

### 6. Citation Format

For NeurIPS 2026 submission, the citation should use `@inproceedings` once the paper is accepted, but for the initial upload a preprint-style citation is standard:

```bibtex

  title     = {{BMLogic-Bench}: A Formal Reasoning Benchmark for Decidable Bimodal Logic},
  author    = {Brastmckie, Benjamin},
  journal   = {Advances in Neural Information Processing Systems},
  year      = {2026},
  note      = {Datasets and Benchmarks Track},
  url       = {https://huggingface.co/datasets/logos-labs/bmlogic-bench}
}
```

Before paper acceptance, use:

```bibtex
@software{brastmckie2026bimodallogic,
  title     = {{BimodalLogic}: {Lean 4} Formalization of Bimodal Logic {TM}},
  author    = {Brastmckie, Benjamin},
  year      = {2026},
  url       = {https://github.com/benbrastmckie/BimodalLogic}

```

The dataset card should include both (pre-print style citation and software citation) and update to `@inproceedings` post-acceptance.

The HF Hub also supports linking an arXiv paper via tag `arxiv:XXXX.XXXXX` in the YAML frontmatter, which creates a Paper page link and enables filtered search.

### 7. License Recommendation

**Recommended: CC BY 4.0** (`cc-by-4.0` in HF YAML)

Rationale:
- NeurIPS 2026 Evaluations & Datasets Track explicitly recommends "open licenses enabling reuse"; CC BY 4.0 is the dominant choice among NeurIPS dataset papers.
- The current MIT license covers the code but datasets conventionally use CC licenses.
- CC BY 4.0 requires attribution but allows commercial use, modification, and redistribution — appropriate for a research benchmark.
- Alternative: CC BY-NC 4.0 (`cc-by-nc-4.0`) if commercial restriction is desired, but this reduces adoption.
- The underlying code (Lean 4 formalization) can remain MIT; the dataset files get CC BY 4.0.

### 8. Python Dependencies and Upload Script

Required packages:
```
datasets>=2.19.0
huggingface_hub>=0.23.0
pyarrow>=14.0.0      # for Parquet; included with datasets
```

Minimal upload workflow:
```python
from datasets import load_dataset, DatasetDict
from huggingface_hub import HfApi

# Load each JSONL into a dataset with explicit split name
bench = load_dataset("json", data_files={"test": "data/bmlogic-bench.jsonl"})
c5    = load_dataset("json", data_files={"train": "data/bmlogic-c5.jsonl"})
c7    = load_dataset("json", data_files={"train": "data/bmlogic-c7.jsonl"})
steps = load_dataset("json", data_files={"train": "data/proof_steps.jsonl"})

# Push each config separately
bench["test"].push_to_hub("logos-labs/bmlogic-bench", config_name="bmlogic-bench", split="test")
c5["train"].push_to_hub("logos-labs/bmlogic-bench", config_name="bmlogic-c5", split="train")
c7["train"].push_to_hub("logos-labs/bmlogic-bench", config_name="bmlogic-c7", split="train")
steps["train"].push_to_hub("logos-labs/bmlogic-bench", config_name="proof-steps", split="train")
```

This approach:
1. Infers column types automatically from JSON
2. Converts to Parquet internally via `push_to_hub`
3. Creates a DatasetDict per config with proper split naming
4. No need to explicitly define `Features` unless the auto-inference fails for nested dicts

**Verification** after upload:
```python
from datasets import load_dataset

# One-line load (default config = bmlogic-bench)
bench = load_dataset("logos-labs/bmlogic-bench")
print(bench)  # DatasetDict with 'test' split, 727 rows

# Load a specific config
c7 = load_dataset("logos-labs/bmlogic-bench", "bmlogic-c7")
print(c7)  # DatasetDict with 'train' split, 49904 rows
```

### 9. NeurIPS 2026 Croissant and RAI Requirements

Once the dataset is uploaded to HuggingFace:

1. **Core Croissant** is auto-generated. Download it from `https://huggingface.co/api/datasets/logos-labs/bmlogic-bench/croissant`
2. **RAI fields** must be manually added to the Croissant file before OpenReview submission. Required RAI additions:
   - Data limitations (e.g., only Base frame class; no Reflexive, Transitive variants)
   - Known biases (class imbalance: ~4% valid in training vs ~47% in benchmark)
   - Personal/sensitive information: None (synthetic data from formal proofs)
   - Intended use cases: LLM reasoning evaluation, fine-tuning
   - Potential social impacts: Low (formal logic reasoning research)
   - Synthetic data disclosure: Yes, generated by Lean 4 decision procedures
   - Source: BimodalLogic GitHub repository, Lean 4 formalization
3. Use the NeurIPS/HF online RAI editing tool to augment the file, then validate with the Croissant validator before submission.

The dataset must be **publicly visible at time of submission** (not private). Large datasets (>4 GB) require sample data — the full 68 MB is well under the 4 GB threshold, so no sampling is needed.

## Decisions

1. **4 separate configs** rather than a monolithic DatasetDict with splits — mandated by differing schemas across the four files.
2. **JSONL upload with automatic Parquet conversion** — avoids custom conversion code, preserves original file format, sufficient for all sizes involved.
3. **`bmlogic-bench` as default config** — the evaluation benchmark is the primary artifact for external users; training data is secondary.
4. **CC BY 4.0 license** for the dataset files (MIT remains for the Lean source code).
5. **`test` split for the benchmark, `train` for everything else** — reflects the actual intended use; there is no natural validation split given exhaustive enumeration.

## Risks & Mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| Nested JSON columns (`formula_ast`, `proof_trace`) cause schema inference failure | Low | Define explicit `Features` in upload script with `Value('string')` for complex dicts, or use JSON string serialization |
| `push_to_hub` timeout for 52 MB c7 file | Very low | Use `max_shard_size="100MB"` parameter; 52 MB well under threshold |
| HF Dataset Viewer can't render complex nested structs | Medium | Viewer shows JSON; acceptable for formal logic data. Add usage examples in card. |
| NeurIPS 2026 RAI fields not completed before deadline | Medium | Document the RAI fields needed now; complete them when submitting to OpenReview |
| `logos-labs` organization not yet created on HuggingFace | Unknown | Verify org exists or use personal namespace `benbrastmckie/bmlogic-bench` as fallback |
| c7 LFS conflict (tracked in Git LFS locally) | Low | HF Hub handles LFS transparently; upload via Python script bypasses local LFS |
