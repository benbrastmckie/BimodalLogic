## The Fundamental Blocker

### Root Cause

Every path to sorry-free `completeness_discrete` requires a **truth correspondence**:

```
temporal_truth M atomMap t phi  <->  phi in MCS(t)
```

The backward direction (MCS membership implies semantic truth) for **Until subformulas** requires the **C5 coherence property**:

```
U(phi, psi) in MCS(t)  ->  exists s > t, phi in MCS(s)  AND  forall t < r < s, psi in MCS(r)
```

This property requires extracting the C5 witness from the **limit domain** back to an **integer**. The witness `y` from `limit_satisfies_c5_strong` is a domain point in `LimitDomSubtype`. To map it to an integer `s` with `y = succ_embed(s)`, one needs `succ_embed_surjective`, which depends on `succ_cofinal` (the sorry).

### Why `succ_embed_squeeze_strict` Cannot Help

`succ_embed_squeeze_strict` (sorry-free) proves: if a domain point `w` is strictly between `succ_embed(a)` and `succ_embed(b)`, then `w = succ_embed(k)` for some `a < k < b`. This works for C4 (where the witness is between two known image points) but NOT for C5 (where the witness `y` might be above ALL image points).

### The Gap Scenario (Genuine Mathematical Difficulty)

`succ_embed_no_gap` proves there are no domain points between `succ_embed(n)` and `succ_embed(n+1)`. This partitions domain points into:
1. **Image points**: `{succ_embed(n) : n in Int}`
2. **Above-image points**: above `succ_embed(n)` for all `n`
3. **Below-image points**: below `succ_embed(n)` for all `n`

The C5 witness could be in category 2 or 3. In that case:
- phi never holds at any integer-indexed point
- U(phi, psi) propagates through all integer indices indefinitely
- F(phi) in MCS(t) says phi holds somewhere in the limit domain (category 2/3 point)
- No contradiction arises from the temporal axioms (Prior-UZ, Z1, BX5 self-accumulation)

This is the "constant-MCS case" documented in ChronicleToCountermodel.lean lines 1819-1885.

## Approaches Analyzed and Why Each Fails

### Approach 1: Build ChronicleAsPriorModel on Int

**Idea**: Use `succ_discrete_f` to build an MCS chain directly on Int, avoiding `LimitDomSubtype`.

**Why it fails**: C5 for `succ_discrete_f` on Int requires the same `succ_embed_surjective` (to map limit domain witnesses to integers). Int has `IsSuccArchimedean` trivially, but the MCS chain is defined THROUGH the limit domain (`succ_discrete_f(n) = limit_f(succ_embed(n))`), so the limit domain gap scenario persists.

### Approach 2: Build OrderedMonadicStructure on Int + prove good via very_good

**Idea**: 
1. Build `OrderedMonadicStructure` on Int using `succ_discrete_f` for predicates
2. Prove `very_good` (every subinterval is good) using `finite_structures_good`
3. `very_good_implies_good` gives `good` (k-equiv to Z-interval)
4. Use `truth_transfer` with k-equiv

**Why it fails at step 4**: `truth_transfer` requires `temporal_truth M atomMap t (neg phi)`, which requires the truth correspondence, which requires C5.

### Approach 3: Game-to-k_equiv bridge (Fraisse's theorem)

**Idea**: Prove that `ghr93_duplicator_wins` implies `k_equiv`, then use `ghr93_forward_to_backward_discrete` to get k_equiv between the chronicle and a Z-interval WITHOUT using `orderIsoIntOfLinearSuccPredArch`.

**Why it fails**: The bridge theorem requires the game to operate on the CHRONICLE STRUCTURE. To set up the game, we need `decomposition_agreement` between the chronicle (on `LimitDomSubtype`) and a Z-interval. Proving `decomposition_agreement` requires showing the chronicle is `very_good`, which requires `IsSuccArchimedean` for proving subintervals are finite. (The `very_good_implies_good` chain uses `exists_cofinal_sequence` which requires `Countable` and `PredOrder` -- both available -- but the piece-wise goodness from `hoSubinterval_good_of_very_good` requires `very_good`, which requires `LocallyFiniteOrder`, which requires `IsSuccArchimedean`.)

### Approach 4: Chronicle on LimitDomSubtype without IsSuccArchimedean

**Idea**: Build a "weak chronicle" without requiring `IsSuccArchimedean`, then use `chronicle_is_good` for k-equiv.

**Why it fails**: `chronicle_is_good` uses `orderIsoIntOfLinearSuccPredArch` which requires `IsSuccArchimedean`. No alternative proof of `good` exists that avoids this.

### Approach 5: Bypass truth correspondence entirely

**Idea**: Construct the countermodel directly without proving truth correspondence.

**Why it fails**: The countermodel needs `truth_at TM Omega tau t phi` to evaluate correctly. This requires either (a) a truth correspondence between the TaskModel and MCS membership, or (b) constructing the TaskModel in a way that truth_at is definitionally correct. Option (b) would essentially re-derive the truth correspondence inside the TaskModel construction.

## What Would Unblock

### Option A: Close `succ_cofinal` (~1000+ lines, genuine mathematical gap)

Prove that succ-iteration from any point reaches all higher points in `LimitDomSubtype`. This is mathematically true but resists formalization due to the "constant-MCS case" (see ChronicleToCountermodel.lean lines 1819-1885). Requires either:

### Option B: Task 129 Henkin model approach

Build a completeness proof through weak/reflexive completeness + conservative extension. The Henkin canonical model avoids the gap entirely by construction. This is a different task (129) and would provide `IsSuccArchimedean` for a Henkin-constructed domain.

### Option C: Direct Int-based chronicle with Int-native C5

Prove C5 for the succ_discrete_f chain DIRECTLY on Int, without going through the limit domain. This would require:
1. Showing that `U(phi, psi) in MCS(t)` implies phi holds at SOME integer-indexed point (not just some domain point)
2. This is equivalent to showing that F(psi) in MCS(t) implies psi holds at some MCS(s) for s > t
3. This is equivalent to... `succ_cofinal`

So Option C reduces to Option A.

### Option D: Redefine succ_discrete_f without going through limit domain

Instead of `succ_discrete_f(n) = limit_f(succ_embed(n))`, define the MCS chain directly on Int using the axioms to construct successive MCS's. This would require reproving all the coherence properties (C4, C5, Prior-UZ/SZ validity) from scratch on Int, without using the limit domain machinery. The C5 proof would use well-founded induction on the formula structure and the Prior-UZ axiom.

This is POTENTIALLY viable but requires significant new infrastructure (~500-1000 lines). The key insight: if the MCS chain is defined by `MCS(n+1) = successor_MCS(MCS(n))` (using the discrete axioms to construct the next MCS), then C5 might be provable by induction on the formula depth, without reference to the limit domain.
