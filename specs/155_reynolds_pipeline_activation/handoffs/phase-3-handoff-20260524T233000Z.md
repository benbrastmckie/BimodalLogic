### Why `(d < p_n <-> c < e_n)` Cannot Be Derived

The forward game gives: `(c < e_n <-> a_N(n) < p_n)` where `a_N(n)` is the N-response to M-challenge `c` at position n.

We need: `(d < p_n <-> c < e_n)`, which requires `(d < p_n <-> a_N(n) < p_n)`, i.e., `a_N(n) = d`.

**Case x' = d**: From sigma + forward game orderings, `(x' = d <-> x' = a_N(n))`. Since `x' = d`, we get `a_N(n) = x' = d`. SOLVED.

**Case x' < d**: We can show `d` and `a_N(n)` are indistinguishable from `x'` and `y'`:
- `(x' < d <-> x' < a_N(n))` -- True <-> True (both > x')
- `(d < y' <-> a_N(n) < y')` -- derived from tau + forward games
But two distinct points in an interval CAN be indistinguishable from both endpoints. Without the full infimum characterization, we cannot conclude `d = a_N(n)`.

### The Fix

`SplitPointProps` needs an additional field, such as:
```lean
h_fwd_d_pn : (d < a_bwd ⟨n, by omega⟩ <-> c < e_n_candidate) /\ 
             (d = a_bwd ⟨n, by omega⟩ <-> c = e_n_candidate)
```

Or more practically: modify `obtain_split_point_props` to export the property that the forward game N-response at position n equals d. This would come from the infimum construction, which already computes d as `inf(S_C)`.

The infimum's GLB property (`hd_is_inf`) combined with the forward game's ordering should give `a_N(n) = d`:
1. `a_N(n) >= d` because `d` is the infimum and `a_N(n)` should be in S_C (by the cont_holds transfer)
2. `a_N(n) <= d` because anything with the same ordering as d relative to all game points cannot be above d (by the infimum being the GLB)

However, step 2 requires showing that `a_N(n)` has the same continuation property as d, which is circular without additional infrastructure.

### Alternative: Restructure e_n Construction

Instead of fixing `SplitPointProps`, restructure `ghr93_case_II` to construct `e_n` via U(B,A) transfer (GHR93's actual approach). This guarantees `c < e_n` by construction since `e_n > resp_tau(n-1) >= c`. This is the approach described in the Phase 3 plan.
