## Key Analysis Results

### Why the Sorries Are Hard

Both sorries in h_d_unique (lines 1821 and 1845) require the same proof technique: constructing a depth-(r+2) formula that separates d from t' (or showing d = t' via the rank-(r+2) game). The proof technique is the GHR93 K⁻(¬D) argument:

1. **Pigeonhole formula D**: A single formula of depth ≤ r that holds on (a_n, y') but fails cofinally below d. Obtained from `pigeonhole_definable_formula` (line 625).

2. **K⁻(¬D) = neg(std_snce(neg(base .bot), D))**: depth = max(0, stavi_depth D) + 2 ≤ r + 2. TRUE at d (Since(⊤, D) false at d because D fails cofinally below d). FALSE at t' when d < t' (Since(⊤, D) true at t' with witness d as mu-point and D holding on (d, t') from cont_holds).

3. **Game transfer**: K⁻(¬D) has depth ≤ r+2, within the rank-(r+2) game budget.

### Obstacles to Invoking pigeonhole_definable_formula

`pigeonhole_definable_formula` requires `h_cofinal_failure`: for ALL p in inf_carrier_cut(S_C) with x' ≤ extendPoint p ≤ y', there exists u ≥ p also in the cut with a failure formula at u.

**Problem**: When d is a carrier point (Case 1 of infimum construction) and cont_holds holds at d, the point p₀ (with extendPoint p₀ = d) is the maximum of the cut, and no u ≥ p₀ has a failure. So h_cofinal_failure FAILS for p = p₀.

**However**: The pigeonhole CHAIN never reaches p₀ in this case! When cont_holds holds at d, all failure points from h_cofinal_failure_below_d are strictly below d (because failure at d would mean ¬cont_holds at d). So the chain stays at u < p₀ and h_cofinal_failure holds for all chain elements. The issue is only with the UNIVERSAL quantifier in pigeonhole_definable_formula's precondition.

### Three Possible Solutions

**Solution A: Weaken pigeonhole_definable_formula's precondition** (~20 lines)
Change h_cofinal_failure to only require failure for p with extendPoint p < d (not ≤). This requires modifying `pigeonhole_definable_formula` or creating a variant. The chain argument goes through unchanged since it starts below d and stays below d.

**Solution B: Case-split h_d_unique on whether d is a carrier point** (~80 lines)
When d is a carrier point with cont_holds at d: all depth-r formulas from (a_n, y') hold at d. Use a different argument (possibly direct game play without the Since formula). When d is a gap or cont_holds fails at d: invoke pigeonhole_definable_formula with the standard preconditions.

**Solution C: Add a weaker cofinal failure property to obtain block** (~40 lines)
Extend the `obtain ⟨d, ...⟩` to also produce D and its properties. In Case 1 (point minimum), construct D via a custom pigeonhole argument. In Case 3 (gap), use existing infrastructure. Thread D to h_d_unique.

## Critical Finding: h_d_unique May Be False for Discrete Orders

Further analysis revealed a potential issue with h_d_unique when d is a carrier-point minimum in a discrete order with few predecessors:

1. The pigeonhole chain requires K+1 failure points (K = NormalForm cardinality at depth 2r).
2. If d is a carrier point in a discrete order with < K+1 carrier predecessors, the chain cannot complete.
3. In this case, there might not be a single formula D that fails cofinally below d.
4. Without cofinal failure, the Since formula argument cannot separate d from t'.

**However**: GHR93 assumes dense orders (Section 8 setup). In a dense order, the carrier below any interior point d is infinite, so the chain always completes. The h_d_unique lemma should hold for dense orders but might fail for discrete orders.

**Resolution options**:
(a) Add a density hypothesis to obtain_split_point_props (matching GHR93's assumption).
(b) Prove h_d_unique only for the gap case (where d is NOT a carrier point, so the chain trivially stays below d).
(c) Case-split: when d is a carrier-point minimum, handle separately (possibly no separation needed if the game constrains the response).
