## Blocker Analysis

### Root Cause

The Henkin chain (`int_chain_fc`) preserves formulas under `G` (all_future) via `g_content` propagation, but does NOT preserve formulas under `F` (some_future). At each Lindenbaum extension step, the extension is maximal and consistent, so it contains either `F(phi)` or `G(neg(phi))` -- but there is no mechanism to ensure `F(phi)` is chosen. Once `G(neg(phi))` enters the chain at step j, `neg(phi)` propagates to all subsequent steps via `temp_4 + g_content`, permanently preventing phi from appearing.

### Failed Approach

The plan assumed `F(phi) -> G(F(phi))` ("all_future_of_some_future") is derivable, which would propagate F-formulas forward through the chain. This formula is:
1. Not a BX axiom
2. Not derivable from BX axioms
3. Not semantically valid on integers under strict/irreflexive semantics (counterexample: phi holds only at time 5, F(phi) holds at times 3,4 but not at times 5+ under strict semantics)

## Viable Alternative Approaches

### Option A: Modified Chain with F-Preservation

Define a new forward step that includes F-formulas from `deferralClosure(root)` in the Lindenbaum seed:
```
seed = g_content(M) ∪ {chi | F(chi) in M, chi in deferralClosure(root)}
```
Challenge: proving this seed is consistent. The conjunction of eventualities is NOT the eventuality of the conjunction, so `forward_temporal_witness_seed_consistent` doesn't generalize directly. However, a compactness-based argument might work since `deferralClosure(root)` is finite.

### Option B: Prove IsSuccArchimedean for Specific Chronicle

The Z+Z counterexample blocks `IsSuccArchimedean` for ABSTRACT discrete orders. But the chronicle's limit domain is CONSTRUCTIVELY built from a single root point -- every domain point is added via succ/pred operations from the root. If all points are provably in the succ/pred orbit of 0, then `IsSuccArchimedean` holds for THIS specific domain, giving `succ_embed_surjective` and closing restricted_tc/fuc for the chronicle.

### Option C: Close Reynolds Model Surgery

The `gap_prior_UZ_contradiction` sorry in `GoodStructuresModelSurgery.lean` is the remaining sorry for `no_gaps_discrete_model_surgery`. Closing this would provide an alternative path to sorry-free discrete completeness via the Reynolds pipeline (tasks 202/256).

### Option D: Hybrid BFMCS

Use `cantor_bfmcs_discrete` (chronicle-based) for restricted_buc (already sorry-free) and prove restricted_tc/fuc via a modified mechanism (e.g., Option A chain or Option B IsSuccArchimedean). The three conditions must be for the SAME BFMCS, so this requires either modifying the chronicle's BFMCS to satisfy tc/fuc or building a new BFMCS that satisfies all three.
