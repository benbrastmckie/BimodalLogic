## Key Finding: Pigeonhole Precondition Gap

### The Problem

`pigeonhole_definable_formula_cross` requires `h_cofinal_failure` to work at ALL cut points including those with `extendPoint p = c_inf`. When c_inf is a carrier point (extendPoint p_c) and `cont_holds_cross(c_inf)` is TRUE:

1. The cut has a maximum element p_c (since all q in cut have extendPoint q <= c_inf = extendPoint p_c, hence q <= p_c).
2. `h_cofinal_failure` at p_c needs `u >= p_c` in cut with formula failure. The only such u is p_c itself.
3. But `cont_holds_cross(c_inf)` = TRUE means ALL continuation formulas hold at c_inf.
4. So no formula A can fail at p_c = c_inf. h_cofinal_failure can't produce the output.

### Why This Case Is Reachable

The pigeonhole internally builds a chain f_0 <= u_1 <= nf_1 <= u_2 <= ... The failure points u_i are always strictly below c_inf (when cont_holds_cross(c_inf) is true, because c_inf in S_C_M means failures above c_inf are impossible, and cont_holds_cross at c_inf means failure at c_inf is impossible). BUT the "floor" t_i from the by_contra assumption can have extendPoint(t_i) = c_inf, making nf_i = max(u_i, t_i) = p_c. The next iteration then calls h_cofinal_failure at p_c. Stuck.

### Why inf_carrier_cut_no_sup Cannot Resolve This

`inf_carrier_cut_no_sup` requires `h_not_point_glb` (no carrier-point GLB of S_C_M). When c_inf IS a carrier point, `h_not_point_glb` is FALSE, so `inf_carrier_cut_no_sup` cannot be applied.

### The GHR93 Proof's Approach

GHR93 uses C' = not-C or K-(not-C) as a SINGLE formula. C is the continuation predicate (conjunction of finitely many formulas). The finiteness comes from rank-r NF types being finite. GHR93 has conjunction in their logic. Our StaviFormula lacks finite conjunction over an arbitrary finite type, so we use the pigeonhole as a substitute.

The GHR93 proof handles c in S_C by showing K-(not-C)(c) = TRUE: not-C holds cofinally below c. Critically, "not-C at u" means u not-in S_C (tail failure above u), NOT "some formula fails at u". When c in S_C: failures below c ARE strictly below c because any failure v with v >= c would satisfy cont_holds (from c in S_C), contradicting the failure. So GHR93's argument works because "not-C" = "not in S_C" which is about the tail, not about a single formula at the point.

## Proposed Solutions

### Solution A: Modify Pigeonhole to Track Floor Bound

Modify `pigeonhole_definable_formula_cross` to accept a bound parameter `c_bound` and only iterate from floors with `extendPoint(floor) < c_bound`. The one_step function would cap the floor: `nf = min(max(u, t), some_point_below_c_bound)`. This requires showing that the chain can always find enough distinct NF types below c_bound.

**Difficulty**: High. The pigeonhole argument's correctness depends on the chain visiting K+1 distinct NF-type points. Capping the floor might prevent visiting enough points.

### Solution B: Finite Conjunction for StaviFormula

Add a `StaviFormula.conj_fin (fs : Fin n -> StaviFormula)` constructor, or encode finite conjunction via binary `conj`. Then materialize C' directly as the conjunction of all continuation formulas (finite by NF type count). This matches GHR93's approach exactly.

**Difficulty**: Medium-High. Requires extending StaviFormula, stavi_depth, stavi_temporal_truth_mu, and rank_embed_stavi_truth_mu. But the conjunction is over a finite set (NF types at depth 2*r), so it's well-defined.

### Solution C: Direct Case Split on c_inf Point vs Gap

Handle the two cases separately:
- **c_inf is a gap**: pigeonhole works (h_not_point_glb holds, inf_carrier_cut_no_sup applies, all cut points are strictly below c_inf).
- **c_inf is a carrier point**: Use a direct argument without the pigeonhole. Since c_inf = extendPoint(p_c), transfer individual continuation formulas via the game. Show that r2_resp must equal rank_embed(d) by showing that the rank-(r+2) game response at rank_embed(c_inf) = extendPoint(p_c) forces r2_resp to match rank_embed(d).

**Difficulty**: Medium. The carrier-point case may allow a simpler argument because c_inf is a concrete point in M, not a gap.

### Solution D: Strengthen h_cofinal_failure_below_c_inf

Show that when cont_holds_cross(c_inf) is TRUE, all failures from h_cofinal_failure_below_c_inf are STRICTLY below c_inf. Then modify h_cof to only require `extendPoint(p) < c_inf` (not <=). Since the pigeonhole only visits points below c_inf in this case, the precondition is satisfied.

**Difficulty**: Low-Medium. The proof that failures are strict is already shown in this analysis. The modification to h_cof replaces `extendPoint(p) <= y` with `extendPoint(p) < c_inf` as a precondition, and the pigeonhole iteration stays below c_inf.

## Recommended Approach

**Solution D** is the most promising:

1. Define a strengthened cofinal failure that always gives u STRICTLY below c_inf when cont_holds_cross(c_inf) is true.
2. The pigeonhole precondition `h_cof` only needs to work at cut points with `extendPoint(p) < c_inf` (which is guaranteed).
3. The pigeonhole internally caps its chain at points below c_inf. Since all failures are strict, the chain stays below c_inf.
4. The pigeonhole's by_contra "floor" issue: if the floor t has `extendPoint(t) = c_inf`, we can replace t with some cut point strictly below c_inf (from the downward-closed cut, there are always cut points below c_inf since x < c_inf and h_cut_start gives a point above x in the cut).

**Key Lemma Needed**: When cont_holds_cross(c_inf) is true, for any s < c_inf, the failure v from s not-in S_C_M satisfies v < c_inf (strictly). This follows from: if v >= c_inf, then v > c_inf (strict, since v is a mu-point above s and s < c_inf), and c_inf in S_C_M gives cont_holds_cross(v). If v = c_inf: cont_holds_cross(c_inf) true gives contradiction. So v < c_inf.
