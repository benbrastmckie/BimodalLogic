### Task 7.4: Rewire countermodel_discrete

The `countermodel_discrete` theorem still delegates to `dd_countermodel_chronicle_discrete` (Chronicle pipeline with sorryAx via succ_cofinal). To complete the rewiring, a **backward-game-to-k-equiv bridge** is needed:

```
ghr93_duplicator_wins N M atomMap n r x' y' x y
  --> k_equiv sig k (Z_interval) (chronicle_monadic)
  --> good sig k (chronicle_monadic)
  --> truth_transfer + z_interval_countermodel
  --> countermodel on Int
```

The missing theorem would look like:
```lean
theorem backward_game_implies_k_equiv (sig : MonadicSignature) (k : Nat)
    (M N : OrderedMonadicStructure sig) (atomMap : Formula -> sig.preds)
    (h_bwd : ghr93_duplicator_wins N M atomMap k r x' y' x y) :
    k_equiv sig k M N
```

This is a form of Fraisse's theorem adapted to the GHR93 game structure. It's non-trivial (~200-500 lines) but follows from the game-to-FO-agreement translation.

### Alternative: Direct Chronicle-to-Int without k-equiv

Instead of building the k-equiv bridge, one could:
1. Prove `IsSuccArchimedean` for `LimitDomSubtype` without `succ_cofinal` (this would make `extract_chronicle_as_prior` sorry-free)
2. Then `chronicle_is_good` + existing Transfer.lean infrastructure gives sorry-free `countermodel_discrete`

The `succ_cofinal` sorry is about proving that succ-iteration from any element reaches any larger element in the limit domain. A proof could use the well-ordering principle on Nat + the monotonicity/boundedness of the succ sequence.
