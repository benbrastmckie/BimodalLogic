## What Was Attempted

Phase 3 requires closing 6 grid dispatch sorries in CaseAnalysis.lean (5 in Case II + 1 in Case B2) plus the Cases III/IV assembly sorry. The grid dispatch sorries are `same_order_type` obligations requiring ordering proofs between all pairs of positions in an (n+1)-element game tuple.

### Grid Dispatch Structure

The `same_order_type_grid` macro expands to `intro i j; simp only [game_tuple]; split_ifs`, which creates N*N goals from the 4-category position grid: {x=0, sel(1..n+1), b=n+2, y=n+3} x {x, sel, b, y}. The existing `first | ... | sorry` block handles ~80% of goals (endpoint vs endpoint, endpoint vs sel, sel vs sel direct). The remaining ~8-10 goals per block involve inner indices where Fin index conversion is needed.

### Why It's Blocked

After `split_ifs`, the introduced variables `i` and `j` become **inaccessible** (marked with `✝` in Lean4). This makes them impossible to reference in the `first` combinator alternatives without `rename_i`. However:

1. **`rename_i` count varies per goal**: Different goals have different numbers of inaccessible variables (4-6 `h✝` hypotheses depending on which index categories matched). Since `rename_i` requires an exact count, it cannot work uniformly across all remaining goals when used inside a `first` alternative.

2. **Core issue**: The `first | ... | sorry` pattern means each `|` alternative must handle ALL remaining goals independently. A single alternative with `rename_i` that works for one goal will fail for another because the variable count differs.

3. **Attempted approaches**:
   - `rename_i ii jj _ _ _ _` (6 names): fails when goal has fewer inaccessible vars
   - `rename_i ii jj` (2 names): `ii` binds to the wrong inaccessible (a `h✝` Prop, not the `Fin` var)
   - `rename_i ii jj ..` (ellipsis): not valid Lean4 syntax

### What Would Fix It

The correct fix is one of:
1. **Custom tactic**: Write a `grid_inner_dispatch` tactic in `EFGameTactics.lean` that introspects the goal, identifies the `Fin` variables (by type), case-splits on their `.val - 1 < n`, and applies ordering lemmas. This is ~100-150 lines of tactic code.
2. **Restructure the proof**: Instead of `same_order_type_grid <;> first | ... | sorry`, use separate `intro i j` followed by `rcases` on each category, creating 16 named goals. Handle each explicitly.
3. **Named variables throughout**: Modify `same_order_type_grid` to name the variables accessibly (don't use `split_ifs`, use manual `rcases` instead).

### Key Discovery: CaseAnalysis Sorries NOT on completeness_discrete Critical Path

`completeness_discrete` uses `countermodel_discrete_enriched` which goes through the parametric canonical model (BXCanonical), NOT through CaseAnalysis.lean. The `sorryAx` in `completeness_discrete` comes from `ChronicleToCountermodel.lean` (the chronicle pipeline), not the game-theoretic pipeline.

CaseAnalysis.lean is part of the WeakCanonical/EFGames pipeline. For it to contribute to `completeness_discrete`, Transfer.lean would need to be rewired from `dd_countermodel_chronicle_discrete` to the game pipeline. This is Phase 5.2 of the plan but requires Phases 3-4 to be complete first.
