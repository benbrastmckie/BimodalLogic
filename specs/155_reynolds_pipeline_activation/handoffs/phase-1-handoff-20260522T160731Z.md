### Task 1.7 (IH h_fwd_r1) [BLOCKED - ARCHITECTURAL ISSUE]

**THE CORE BLOCKER**: This requires research and plan revision.

#### Problem Statement

At line 3836, the sorry provides:
```
ghr93_duplicator_wins M N atomMap (1 + 3 * n) (r + 1) 
  (rank_embed ... x₀) (rank_embed ... y₀) (rank_embed ... x₀') (rank_embed ... y₀')
```

This is the rank r+1 forward strategy on a SUB-INTERVAL [x₀,y₀] vs [x₀',y₀']. Only the FULL-interval rank r+1 strategy `h_r1` is available (line 3764-3766 in the outer theorem).

#### Root Cause

In `ghr93_forward_to_backward` (line 3755), ALL hypothesis variables including `h_r1` are reverted before induction (line 3770):
```lean
revert x y x' y' hxy hx'y' h_pt h_pt_M h h_r1
induction n with
```

This makes the IH `ih_gen` universally quantified over `h_r1`, meaning EVERY recursive call must provide rank r+1 on its specific sub-interval.

#### Why This Is Hard

The lambda wrapper at line 3830 calls `ih_gen` to satisfy `ghr93_inductive_step`'s `ih` parameter:
```lean
fun {x₀ y₀ x₀' y₀'} hle hle' hpt' hfwd =>
  ih_gen hle hle' hpt' (by ...) hfwd sorry
```

`ih_gen` needs 6 arguments: hle, hle', hpt', h_pt_M, h_fwd, h_fwd_r1. The `sorry` is for h_fwd_r1.

Deriving sub-interval rank r+1 from full-interval rank r+1 requires:
1. `ghr93_duplicator_wins_round_mono` (reduces rounds) -- can get from 4+3n to 1+3n rounds
2. Strategy restriction to sub-interval -- requires d_consistency at rank r+1
3. d_consistency at rank r+1 -- requires Claim 1 at rank r+2
4. Claim 1 at rank r+2 -- requires rank r+2 on the sub-interval
5. This creates a RECURSIVE TOWER of rank requirements

#### Key Observation

`ghr93_inductive_step`'s `ih` parameter (lines 3709-3714) does NOT include rank r+1:
```lean
ih : ∀ {x₀ y₀ x₀' y₀'}, x₀ ≤ y₀ → x₀' ≤ y₀' →
  (∃ p, inClosedInterval x₀' y₀' (extendPoint p)) →
  ghr93_duplicator_wins M N atomMap (1 + 3 * n) r x₀ y₀ x₀' y₀' →
  ghr93_duplicator_wins N M atomMap n r x₀' y₀' x₀ y₀
```

The rank r+1 comes separately as `h_fwd_r1` (line 3716-3718). So `ghr93_inductive_step` gets its rank r+1 from the OUTER theorem, not from the IH.

But `ih_gen` requires rank r+1 because the outer induction universally quantified it.

#### Proposed Solutions (Require Research)

**Option A**: Restructure the induction to NOT universally quantify `h_r1`. This would require `h_r1` to NOT depend on `x, y, x', y'`, which is impossible since its type contains `rank_embed ... x`.

**Option B**: Prove a helper lemma `ghr93_forward_to_backward_core` that doesn't take `h_r1` and uses it purely for `ghr93_inductive_step`'s `h_fwd_r1` parameter (not in the IH). Then `ghr93_forward_to_backward` wraps this.

**Option C**: Change the induction to use strong induction on a PAIR (n, rank_budget), where rank_budget tracks how much rank headroom is available. At each level, consume 1 rank unit for d_consistency (via Claim 1), and the rank budget decreases. Since we start with rank budget r+1 and consume 1 per level, we need r+1 ≥ n. The outer theorem can provide this.

**Option D**: Prove that `ghr93_inductive_step` can be modified to NOT use `h_fwd_r1` at ALL (by finding an alternative d_consistency proof). This would eliminate the entire h_fwd_r1 chain.

**Option E**: Show that at the IH level, d_consistency is vacuously true or can be proved without rank r+1. The IH call is for the sub-interval with n-1 rounds; at the base case n=0, d_consistency is not needed. Maybe the induction terminates before rank exhaustion.

**Recommended next step**: Run `/research` on Options B and E, which seem most promising.
