## Three things a successor touching this component should know

1. **The axiom profile of `openDerivable_ofPlus_iff` is `[propext, Quot.sound]`** — no
   `Classical.choice`, unlike every other headline declaration in the task. That is the mechanical
   signature of the TM⁺ conservativity row being genuinely syntactic: it never passes through a
   canonical model or a completeness engine. It is pinned by C14, so a future edit that routes it
   through validity will fail the gate rather than quietly widen the profile.
2. **`OpenAxiomValidity.lean` carries `set_option linter.style.longFile 2600`** at 2,587 lines.
   The linter accepts `N` only when `N - 200 ≤ lines < N`, so any edit that moves the file out of
   that window must re-tighten `N` in the same change. Per
   `docs/development/LEAN_STYLE_GUIDE.md`, long files here are baselined, not split.
3. **The reflection-helper shape is load-bearing.** Stating each as
   `OpenValid (<the literal schema>).reflectTime` is what makes all 142 dispatch arms a bare
   `exact`, and what means no reflection lemma for `IsPureFutureOpen` / `IsPurePastOpen` is owed.
   Restating a helper as the mirror schema at reflected parameters — the shape
   `StarAxiomValidity.lean` uses — would reintroduce a per-arm `simp only` at 71 sites and a
   purity-reflection obligation at both pasting arms.
