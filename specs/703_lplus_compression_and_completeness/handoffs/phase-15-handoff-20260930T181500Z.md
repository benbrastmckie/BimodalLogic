## The blocker, measured against the landed tree

The plan asserts that a spliced forward/backward walk's "five `LabRun` fields are exactly the eight
readouts 6b landed". **Four of the five, not five.**

`LabRun.coherent` (`Live.lean:225`) demands `PlusLocalCoherentSeqLab Γ Del G.bx lab`, whose **box
clause** is

```
PlusFormula.box χ ∈ lab t ↔ G.bx χ = true          -- Compression/Types.lean:234
```

Nothing supplies it, and this is not an oversight in 6b:

- `Position.lean`'s `LabCoherent` **deliberately omits** the box clause — its own docstring says
  "the `□`-clause (global) … deliberately absent".
- `AgreesOnState` gives only `box χ ∈ lab t ↔ box χ ∈ G.slab t (st t)`, because `box` is a state
  shape. So what is needed is `PlusFormula.box χ ∈ G.slab t w ↔ G.bx χ = true`.
- **No clause in the condition set says that.** (C3) `BoxFaithful` (`Basic.lean:521`) relates
  `G.bx χ = true` to `∀ t w, χ ∈ G.slab t w` — the **subformula** `χ`, not the boxed formula
  `box χ`. The complete inventory of `Prop`-valued certificate conditions in the subtree is
  `BiSerial`, `BiSerialWindow`, `BoxFaithful`, `Target` (plus `AgreesOnState` and the two `Fold`
  relations), and none of them closes it. Verified by grep over
  `FormalSystem/Metalogic/Decidability/PlusSlicedCertificate/`, not reasoned from the plan.
- `Position.lean:243 mem_posAt_of_path` runs the **other** way — it derives `posAt` membership
  *from* `PlusLocalCoherentSeqLab`, dropping the box clause on the way in. The information is
  genuinely lost, not merely unstated.

### The two resolutions, with the recommendation

- **(a), RECOMMENDED.** Add a (C3b) box-**label** clause to the condition set:
  `∀ χ, PlusFormula.box χ ∈ plusClosureOf (Γ ++ Del) →`
  `∀ (t : ℤ) (w : Fin G.n), (PlusFormula.box χ ∈ G.slab t w ↔ G.bx χ = true)`,
  and thread it as a hypothesis through 6d's `LabRun` construction. It is decided on the window by
  `exists_window_eq` exactly as `BoxFaithful` is, so it costs the checker one more bounded
  quantifier and nothing else.
- **(b), REJECTED as written.** Fold the box clause into `LabCoherent` so `posAt` carries it. Since
  `AgreesOnState` already pins `box χ ∈ lab t ↔ box χ ∈ G.slab t w`, this *silently* forces
  `box χ ∈ G.slab t w ↔ G.bx χ = true` on the certificate: a condition smuggled into the position
  space, making `posAt t` empty for a violating certificate with no stated clause saying why. It
  also perturbs `succP` / `predP` / `verts` and the landed `mem_posAt_of_path`.

This is recorded as a **non-blocking** `user_decision` on `.return-meta.json`: it does not block
anything dispatch 33 delivered, and it does block 6d's first line.

## The two findings this dispatch recorded, both corrections to instructions it was given

1. **The prescribed inner test was insufficient, in the same way route (β) was.** The handoff
   prescribed `EUFix.lfp X G.succT (G.atPosT e) (G.atPosT g)`. `EUFix`'s path puts every
   *intermediate* vertex in the vertex set and says **nothing about the endpoint**, so the
   discharging segment can end outside `X` and strand the walk exactly as route (β) does — one level
   further in. The event must be relativized too: `Fair.inSet X (G.atPosT e)`. That in turn is why
   `EUFix.lfp_mono_V` was **not** enough and `lfp_mono_all` had to be written: an event predicate
   carrying a `w ∈ X` conjunct varies with `X`, so without monotonicity in the event the outer
   contraction is not monotone and `Nu` does not apply at all.
2. **The plan's "five `LabRun` fields are exactly the eight readouts" claim is four of five.** See
   the blocker section; the missing field is `coherent`'s box clause.
