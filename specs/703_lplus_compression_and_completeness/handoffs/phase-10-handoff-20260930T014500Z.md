## Environment finding a successor must not repeat

`lake-build-guard.sh` shares its lock, result and log files **by hardlink** between the main tree
and every `.orchestrate-worktrees/*` worktree (same inode for `.lake/build-guard.log`). A plain
`lake-build-guard.sh build` in this worktree therefore **replayed a stale result from the main
tree** and reported `exit_status=0` for a module that had never been compiled — a false pass, with
no `.olean` written. **Always pass `--no-share`** when building inside a dispatch worktree, and
confirm the verdict against the `.olean` timestamps, not against the exit code alone.
