## The three findings this dispatch recorded, all corrections to the plan

1. **The bridge cannot be stated at a general time.** `FoldF a b` holds only when `a = b` or both
   `a, b ≥ NM`; `FoldB a b` only when `a = b` or both `a, b < 0` (`Fold.lean`). A biconditional at a
   general `t` needs one window time carrying both, and away from the diagonal the relations are
   disjoint. `live_iff_mem_liveT` is therefore quantified over `s ∈ G.winTimes`, where both folds hold
   reflexively — which is exactly the set a checker iterates. **`exists_foldF` / `exists_foldB` are
   not consumed by the bridge**, contrary to the plan's instruction.
2. **The soundness direction does not factor into halves; the completeness direction does.**
   `G.FwdLive s p` demands a bi-infinite `LabRun`, `fwdLiveT` membership yields a forward walk and
   constrains the past not at all, and `succP`-totality is false. So there is deliberately **no**
   `fwdLive_iff_mem_fwdLiveT`; it would be false as stated. Completeness's two halves *are* landed
   separately and need no box clause.
3. **15.3's gate is not reachable by evaluation, and this was established before the attempt.**
   `liveT` is `Nu.gfp` over `verts` iterated `verts.card + 1` times, every iteration running an inner
   `EUFix.lfp` of the same height over a vertex set of size `n * 2 ^ |Cl| * |winTimes|`. The landed
   route uses the bridge in **both** directions, so passing the gate is evidence about the bridge and
   not only about the fixture.
