## Two things a successor must know before touching anything

1. **`lake-build-guard.sh` shares its lock, result and log by HARDLINK** between the main tree and
   every `.orchestrate-worktrees/*` worktree (same inode for `.lake/build-guard.log`). A bare
   `lake-build-guard.sh build` in a worktree **replayed a stale main-tree result and reported
   `exit_status=0` for a module that had never compiled**, with no `.olean` written. **Always pass
   `--no-share`** inside a dispatch worktree, and confirm the verdict against `.olean` timestamps,
   not the exit code alone. This is a live false-pass hazard for every worktree dispatch in this
   repository.
2. **`.claude/scripts/git-commit-scoped.sh` resolves the MAIN tree, not the cwd**, so it silently
   commits nothing when invoked from a dispatch worktree ("NOTE: Nothing to commit ... non-blocking").
   Commit with plain `git add -- <files> && git commit` inside the worktree. The repo's pre-commit
   hook is `scripts/typst-sync-check.sh --counts-only`; run
   `bash scripts/typst-sync-check.sh --fix` and stage `typst/generated/status.typ` with every commit
   that changes `FormalSystem.lean`.
