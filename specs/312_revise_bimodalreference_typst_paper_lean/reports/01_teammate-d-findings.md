# Teammate D (Horizons/Strategy) Findings — Task 312

## Key Findings

1. **This is not a one-off drift — it is a structural, recurring problem, and the drift is already severe.** `Theories/Bimodal/typst/` has only 27 commits (2026-01-27 to 2026-06-16) against 319 live `.lean` files and 109 commits to the parallel `latex/` tree. The typst implementation-status chapter (`chapters/06-notes.typ`) still discusses "Task 658", "Task 991", "Task 29" and a reflexive-vs-strict-semantics debate that the ROADMAP shows was resolved by task 93 (the irreflexive-semantics switch) long ago. Meanwhile the ROADMAP's "current state" section (updated by task 301, referencing tasks up through 311) describes the Chronicle/Reynolds architecture, the k=1 gate closure, Prior-UZ/SZ, `discrete_box_necessity`, etc. — none of which appears in the typst notes chapter. The doc isn't slightly stale; it reflects an earlier era of the project.

2. **There is already a project-recognized "sync docs to Lean" task pattern**, and task 312 risks either duplicating or conflicting with it:
   - Task 177 `[NOT STARTED]` — "Update all documentation to match final codebase state after refactor" — blocked by Task 131 (file-hierarchy restructure), topic `publication-quality`.
   - Task 131's own description explicitly asks whether `docs/`, `latex/`, and `typst/` should even remain under `Theories/Bimodal/` or move to project root — i.e., the roadmap already anticipates that the *location and multiplicity* of these parallel documentation trees is an open architectural question, not just their content accuracy.
   - Task 158 (archived, completed) did a full README-accuracy overhaul with the same failure mode this task is hitting: stale statistics, missing operators (U/S), overclaimed completeness. That task's plan explicitly tied itself to "Phase 5 — Publication quality" roadmap alignment — the same phase task 312 sits in.
   - This is the **third** independent "our docs drifted behind Lean" task in this project's history (158 for README.md, 177 planned for full docs, now 312 for typst specifically). That is a pattern, not a coincidence — it's evidence the current model (hand-maintained parallel prose trees) does not scale against a Lean tree that "changes substantially."

3. **There are THREE parallel documents to keep in sync, not two**: `latex/BimodalReference.tex` (marked in its own README as authoritative/`typst/` is described as "a parallel port of latex/... Both versions should produce visually similar output with identical mathematical content"), `typst/BimodalReference.typ`, and now the external JPL paper (`/home/benjamin/Philosophy/Papers/PossibleWorlds/JPL/possible_worlds.tex`, 3473 lines, actively edited — modified today). Task 312 as scoped only touches one of the three. If typst is revised to match Lean + the JPL paper but latex/ is left untouched, the project **re-creates the exact drift it's trying to fix**, just between latex and typst instead of between typst and Lean.

4. **The JPL paper is external to the repo and independently evolving** — it lives under `~/Philosophy/Papers/`, is a real journal submission (Springer Nature `sn-jnl` class, math-phys style), and was edited today (2026-07-06). It is not under version control alongside `Theories/Bimodal/`. Treating it as a one-time alignment target is risky: it will keep changing through review/revision cycles independent of this repo's commit history, so a "revise once" task produces another point-in-time snapshot that starts drifting again immediately.

5. **Adjacent roadmap items this task could advance simultaneously**: Phase 5 "Publication quality" explicitly lists "Verification audit (task 95)" and "genuine truth_at completeness (task 8)" as siblings. Task 178 (publication examples/demo, blocked by 131+193) and tasks 292/293 (copyright headers, linter compliance) are in the same publication-quality topic cluster. `docs/reference/` (axiom-reference.md, operators.md, tactic-reference.md) is a fourth documentation surface with the identical staleness risk, currently untouched by this task's scope.

## Recommended Approach

**Reframe task 312 from "patch the file" to "establish and execute a synchronization protocol," applied once now and left in place for reuse.** Concretely:

1. **Build a mapping table as a first-class deliverable, not a byproduct.** Add an appendix (or a tracked file, e.g. `Theories/Bimodal/typst/SYNC-MAP.md` or a table inside `06-notes.typ`) that maps: Typst chapter/section → Lean module(s)/declaration(s) it describes → JPL paper section it corresponds to → last-verified commit hash or task number. This is the artifact that makes future re-sync tractable — the next drift-fix task starts from "here's what maps to what" instead of re-discovering it from scratch (which is presumably most of the effort in *this* research phase).

2. **Anchor the sync to the ROADMAP, not to a manual reread of 319 files.** The ROADMAP.md is already the project's living single source of truth for "current state" (updated incrementally by tasks 301, 311, etc.). The typst `06-notes.typ` implementation-status chapter should be rewritten to *derive* its claims from ROADMAP.md's current-state section rather than independently re-describing Lean internals — reducing two sync problems (Lean→Roadmap, already maintained; Roadmap→Typst, new) instead of one brittle one (Lean→Typst directly).

3. **Decide and document the authority relationship between latex/, typst/, and the JPL paper explicitly, as part of this task**, even if the mechanical migration of latex/ is deferred to a follow-up task. At minimum, update both READMEs so they don't contradict each other (typst/README.md currently claims parity with latex/, which this task will likely break). Recommend either: (a) declare typst/ the new authoritative reference and latex/ deprecated/archived (matches the direction of Typst adoption seen elsewhere in the project), or (b) explicitly scope 312 to update both in lockstep. Silently leaving latex/ stale while "fixing" typst/ just relocates the drift.

4. **Spawn or flag a follow-up task for `docs/reference/*.md`** (axiom-reference.md, operators.md, tactic-reference.md) if those are found to have the same staleness during this task's research — don't silently expand scope, but don't ignore the sibling risk either.

5. **Introduce a lightweight drift-detection mechanism** rather than relying on periodic manual audit tasks. Options, roughly in order of cost/benefit:
   - **Cheapest, highest leverage**: a `.claude/scripts/typst-sync-check.sh` (or a `/review`-style check) that greps Lean source for axiom/theorem names referenced in `typst/chapters/*.typ` and flags typst-cited names that no longer resolve (renamed/removed axioms), plus flags axiom-layer counts in typst against `Axioms.lean` layer counts (e.g., typst currently would need updating from an old count to "42 axiom constructors in six layers"). This can run as part of `/review` or a git pre-commit-adjacent CI-style check, catching drift incrementally rather than accumulating it for another big-bang task.
   - **Doc-comment breadcrumbs in Lean**: on key axiom/theorem declarations that the reference manual describes (e.g., in `Axioms.lean`, `Completeness.lean`), add a doc-comment tag like `-- @typst-ref: 03-proof-theory.typ#bx5` that a script can grep to build/verify the mapping table automatically. Low friction (one-line comment), reusable by any future doc (including docs/reference/*.md).
   - **Process convention**: add a line to the git-workflow or state-management rules (or a new `.claude/rules/`) requiring that any task which changes axiom names, layer structure, or top-level theorem names in Lean also touch a checklist item "Update typst reference? Y/N + reason" — similar to how `--lit` and other flags are already surfaced as explicit per-invocation decisions in this codebase's conventions. This is cheap to add and matches the project's existing style of explicit, non-silent decision points (see the `--lit` "no silent fallback" pattern in CLAUDE.md).
   - **More ambitious (not recommended as part of 312 itself, but worth a spawned task)**: partially generate the axiom/theorem tables in the Typst reference from `Axioms.lean` structure (e.g., a script that parses axiom names/statements/layers and emits a Typst table fragment to `#include`). This directly eliminates an entire class of drift (the axiom inventory) at the cost of build tooling. Given the project already has `.claude/scripts/generate-todo.sh` as a precedent for "generate a human-facing doc from a machine source of truth," this fits the existing engineering culture. Scope as a follow-up task, not as scope creep on 312.

6. **Do not restructure typst chapters to exactly mirror Lean module boundaries.** The reference manual's chapter structure (syntax/semantics/proof-theory/metalogic/theorems) is pedagogically organized and mirrors the JPL paper's likely structure (a math paper is not organized like a codebase's directory tree, and forcing 1:1 chapter-per-Lean-module would fragment the exposition — e.g., "Metalogic" chapter reasonably covers soundness+completeness+decidability which live in 7 different Lean subdirectories per task 131's own description). The mapping table (point 1) gives the traceability benefit without this cost.

## Confidence Level

**High** on the factual claims (git history, file contents, ROADMAP/TODO state — all directly inspected). **Medium** on the specific tooling recommendations (doc-comment breadcrumbs, generation script) — these are design proposals informed by the project's existing conventions (e.g., `generate-todo.sh`, the `--lit` no-silent-fallback pattern) but have not been validated against Typst's actual templating capabilities or the team's appetite for added build tooling.
