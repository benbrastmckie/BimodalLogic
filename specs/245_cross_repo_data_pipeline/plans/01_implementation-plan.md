## Overview

Build the BimodalLogic side of a one-way data sync pipeline to BimodalHarness. This involves creating an export script (`scripts/export-training-data.sh`) that runs both `dataset_generator` and `proof_extractor` executables, validates output, writes a `data/VERSION` file, and documents the sync protocol. The BimodalHarness side (Python adapter, enhanced Makefile targets) is documented as follow-up work but not implemented here, since it lives in a separate repository.

### Research Integration

Key findings from the research report (01_cross-repo-pipeline-research.md):
- Both `dataset_generator` and `proof_extractor` executables are fully operational; `proof_steps.jsonl` has 10,063 validated steps.
- Critical schema gap: Lean emits 8 fields but harness `load_proof_steps()` expects 12 (missing: `step_id`, `goal_json` rename, `goal_pretty`, `action_index`, `depth`, `proof_height`). Recommended resolution is a Python-side adapter in BimodalHarness.
- The 49-action space (42 axiom + 7 inference) is fully aligned between repos.
- `scripts/run_dataset_generation.sh` provides a strong model for the export script (validation patterns, dry-run support, signal handling).
- BimodalHarness `data/VERSION` already exists with `SCHEMA_VERSION=1` and `SYNC_DATE=not-yet-synced`.

### Roadmap Alignment

This plan advances the training data pipeline infrastructure for the BimodalHarness ML system. While not directly on the BX completeness critical path, it enables downstream training runs that depend on fresh, validated exports from BimodalLogic.

## Goals & Non-Goals

**Goals**:
- Create `scripts/export-training-data.sh` that runs both executables with validation and VERSION output
- Create `data/VERSION` file establishing schema version, git commit, and export timestamp
- Document the sync protocol for operators of both repositories
- Document the schema gap and BimodalHarness follow-up work needed

**Non-Goals**:
- Modifying BimodalHarness code (separate repository)
- Modifying Lean ProofStep struct to add missing fields (recommended as Python adapter instead)
- Implementing CI/CD automation for the sync pipeline
- Running the actual dataset generation (the script makes it possible; running is an operator action)

## Risks & Mitigations

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| `proof_extractor` output format changes break downstream consumers | H | L | VERSION file includes SCHEMA_VERSION; document bump protocol |
| Export script fails on large datasets (c9/c11 take hours) | M | L | Default to c5 tier; support tier selection like `run_dataset_generation.sh` |
| BimodalHarness adapter never built, data sits unused | M | M | Document follow-up clearly; keep BimodalLogic side self-contained |
| `data/VERSION` format diverges between repos | L | L | Use same field names; document format in SYNC_PROTOCOL.md |
