## Overview

Dispatch 3 implemented Phase 1 only (B3a): the compiled research probe
`probes/b3a-computable-ktype.lean` was transcribed into the library as
`FormalSystem/Metalogic/WeakCanonical/KTypeSummary/KTypeFin.lean`, with the probe's `FinDec`
class replaced by the four explicit instance binders the plan's Challenge statements pin. The
module decides `NfEvalNf` on a finite decidable structure by induction on depth, reads off a
computable `kTypeOfFin` equal to the classical `kTypeOf` pointwise, decides Tarski `eval` by

instances. Nothing about `⊡` or `Hit` is decided; B1, B2a, B3b, the B2b verdict probe and the
per-model bridge are Phases 2-10 and remain `[NOT STARTED]`.

## Decisions

- Instance binders are explicit on every declaration rather than section `variable`s: under
  `variable`, Lean omitted the unused `[DecidableEq M.carrier]` from `kTypeOfFin`'s signature,
  which would have drifted from the pinned Challenge statement.
- `@decidable_of_iff` takes the target proposition FIRST
  (`@decidable_of_iff (x = y) (x.1 = y.1) ⟨Subtype.ext, congrArg Subtype.val⟩ (Int.decEq _ _)`);
  the first build failed on the reversed order. Recorded in the module header.
- `decAtomEval`/`decEval` name the binders (`dlt`, `dint`) and use them directly for order and
  predicate atoms, never the generic `LinearOrder M.carrier` decidability (the `ℤ`-instance
  hazard: that route is noncomputable on `ℤ`-subtypes).
