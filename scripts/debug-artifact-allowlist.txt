# Live debug directives that C27 must not treat as unreviewed debug output.
#
# A `#check`, `#eval`, `#print`, `#reduce`, `dbg_trace` or `dbgTrace` in library code prints
# at every build and asserts nothing: a changed value scrolls past in the log with the build
# still green. Executable probes belong in `Tests/BimodalTest/`, where a `#guard`, a
# `#guard_msgs` or a throwing `IO` test turns the same observation into an assertion. cslib's
# `scripts/pre-pr-check.sh` rejects these directives in library code outright.
#
# ADMISSION BAR. An entry here is a documented exemption with its reason written on the `#`
# line directly above it. A page whose whole purpose is to print -- an axiom-audit page read by
# humans -- is admissible. "It is a quick smoke test" is not; move it to the test suite. A
# temporary entry must say what it is pending, so the ratchet toward the permanent set is
# visible at every gate.
#
# FORMAT: one entry per file, `<repo-relative path> <exact live line count>`, immediately
# preceded by a `#` reason line. The count is of LIVE lines only: C27 masks comments,
# docstrings, strings and character literals before matching, so a usage example inside a
# docstring code block needs no entry. C27 fails on a live directive in an unlisted file, on a
# count that differs from the tree in EITHER direction (so a removal must lower the entry in
# the same change), on an entry with no reason line, and on a stale entry whose file is gone
# or has no live directives left -- so this file cannot quietly rot into a dumping ground.
