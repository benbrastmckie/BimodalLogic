# scripts/header-attribution-baseline.txt -- reviewed attribution waivers
#
# One row per reviewed-and-declined candidate: `<path>|<identity>|<stamp>`, three
# `|`-separated fields, where <stamp> is the file's `Authors:` block at review time: line 4
# verbatim, plus any continuation lines up to the closing `-/`, joined with single spaces.
# That span is exactly the one the gate reads the name set from, so a stamp cannot match
# while the names it was reviewed against have changed. A pipe separator rather than a
# space because two of the three fields contain spaces (a display name, and the whole
# `Authors:` block).
#
# WHAT A ROW MEANS: scripts/check-header-attribution.sh reported `<identity>` as a
# candidate on `<path>`, a human judged that candidate against the threshold in
# docs/development/LEAN_STYLE_GUIDE.md section 4 ("Copyright-Header Authorship"), and the
# judgment was that the change does not earn an `Authors:` entry. The gate's exit status
# counts UNREVIEWED candidates only, so a row here takes the gate from red to green --
# which is exactly why every row carries its reason as a preceding comment, naming the
# measurement the judgment rests on rather than a category label.
#
# THIS FILE ONLY EVER SHRINKS. A row grandfathers its candidate only while the file still
# carries the exact recorded stamp: editing any line of the `Authors:` block permanently
# un-grandfathers the row, after which the gate re-reports the candidate until it is
# reviewed again. Never add a row to quiet a new finding -- judge the finding, and if it
# meets the threshold, append the name to the header instead.
#
# Modelled on scripts/readme-date-baseline.txt, which already implements exactly this
# stamp-based un-grandfathering. Rows are sorted by path.
