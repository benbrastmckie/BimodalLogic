# Known-unreachable live modules (C6 rot guard).
#
# A module listed here is NOT reachable from any Lake target root
# (`lean_lib FormalSystem`, `lean_lib BimodalTest`, or any `lean_exe` root), so
# `lake build` never compiles it and a broken import inside it would go
# unnoticed. C6 compile-checks each entry in isolation with `lake env lean`.
#
# Rules:
#   - C6 FAILS if an unreachable live module is missing from this file.
#   - C6 FAILS if an entry names a module that no longer exists.
#   - Wiring a module into the build graph means DELETING its line here.
# One module path per line; `#` starts a comment.
#
# THE MANIFEST IS EMPTY, and that is the intended resting state: every live module is inside a
# build closure. The sections below are kept as the record of what used to be listed and why
# each line went. An entry added here in future is a regression to be justified, not routine.

# --- Root ------------------------------------------------------------------
# FormalSystem.Init used to be listed here as unreachable, with a note to delete
# the line once the import adoption landed and something in the build graph
# imported it. That has happened: the eleven minimal elements of the internal
# import DAG now import it directly and every other live module inherits it, so
# the root is reachable and C24 (`lake exe checkInitImports`) asserts that the
# property holds tree-wide. Nothing belongs in this section.

# --- Tooling (BimodalTools) ------------------------------------------------
# `BimodalTools.ProofFirstBenchmark` used to stand here. It no longer does: the
# `BimodalTools.lean` aggregator imports every non-`Main` tooling module, so the
# benchmark harness is reachable from a Lake target root and `lake build BimodalTools`
# compiles it. C6 fails if an entry names a reachable module, so the line was deleted in
# the same commit as the split rather than renamed to the new module path.

# --- Metalogic -------------------------------------------------------------
# Nine modules used to stand here: the three importer-less sibling aggregators
# `FormalSystem.Metalogic.{Core,Bundle,SoundnessLemmas}`; `SoundnessLemmas.CoValidity`, reached
# only through one of them; the orphan `Kamp.NfMultiAnchorBridge.OuterGateFaithful`; and the
# effective-periodic-extension cluster `Decidability.BiLasso.{Extend,Successor,Orbit,Agreement}`.
# None does now. The library root `FormalSystem.lean` is generated by
# `lake exe mk_all --lib FormalSystem` and imports EVERY module under `FormalSystem/` directly, so
# all nine are reachable and `lake build` compiles them. The lines were deleted in the same
# commit as the root collapse, because C6 fails if an entry names a reachable module.
#
# The three aggregators still have no importer among CONTENT modules, which is what keeps them
# from closing a module-level cycle; nothing imports the root, so the root importing them is
# safe. No module under `FormalSystem/` can be unreachable again while the generated root is
# current, and the generated-root invariant in scripts/check-module-invariants.sh asserts that
# it is. Nothing belongs in this section.

# The finite-carrier periodic extension theorem, additive over Semantics/Extension/, WAS listed
# here with the note "DELETE this line when it is registered". It is now registered in
# FormalSystem/Semantics.lean -- alongside LexCarrier and BLSchemaValidity, the other two
# modules that aggregator was missing -- so the line is gone and `lake build` guards it.

# --- Tests -----------------------------------------------------------------
# Five test modules used to stand here. None does now.
#
# `BimodalTest.ProofSystem.DerivationBenchmark` was excluded because its trailing top-level
# `#eval` printed the whole benchmark table on every `lake test`. The `#eval` was deleted (the
# benchmark definitions stay callable; the module docstring says how to run them by hand) and
# Tests/BimodalTest.lean imports the module. Its former sibling, the semantic-evaluation
# benchmark, was not repaired but retired to Boneyard/SemanticBenchmarkToyEvaluator/: it never
# called `TruthAt`, so it measured nothing the library defines.
#
# `BimodalToolsTest.FormulaMutatorTest` and `BimodalToolsTest.ProofFirstTests` were excluded
# because each imported an executable root that defines `main`, colliding with the `main` from
# BimodalTools.DatasetValidatorMain already in that environment. Both roots were split into a
# library module plus a thin `main`; the tests import the library halves and
# Tests/BimodalToolsTest.lean imports the tests.
#
# `BimodalTest.Metalogic.PeriodicExtensionAxiomTest` and
# `BimodalTest.Metalogic.Decidability.BiLassoSuccessorTest` were excluded only so that importing
# them from Tests/BimodalTest.lean would not make `BiLasso.Orbit` / `BiLasso.Successor`
# reachable. The generated library root reaches both regardless, so Tests/BimodalTest.lean
# imports the two tests.
