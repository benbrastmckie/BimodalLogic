# Known-unreachable live modules (C6 rot guard).
#
# A module listed here is NOT reachable from any Lake target root
# (`lean_lib FormalSystem`, `lean_lib BimodalTest`, or any `lean_exe` root), so
# `lake build` never compiles it and a broken import inside it would go
# unnoticed. C6 compile-checks each entry in isolation with `lake env lean`.
#
# Rules:
#   - C6 FAILS if an unreachable live module is missing from this file.
#   - C6 FAILS if an entry names a module that no longer exists.
#   - Wiring a module into the build graph means DELETING its line here.
# One module path per line; `#` starts a comment.

# --- Automation ------------------------------------------------------------
# Benchmark harness. Its only importer is BimodalTest.Automation.ProofFirstTests,
# which cannot be wired into the test root (see the Tests section below), so this
# module stays outside the build graph too.
FormalSystem.Automation.ProofFirstBenchmark

# --- Metalogic -------------------------------------------------------------
# Sibling aggregators for directories whose contents are reached directly rather
# than through the aggregator. They exist so every Metalogic/ subdirectory has
# one, and deliberately have no importer: an aggregator imported by a file that
# its own contents already reach is how a module-level cycle gets introduced.
# Being unreachable, `lake build` never compiles them, so C6 does it here --
# which is what keeps a stale import inside one of them from going unnoticed.
FormalSystem.Metalogic.Core
FormalSystem.Metalogic.Bundle
FormalSystem.Metalogic.Algebraic
FormalSystem.Metalogic.SoundnessLemmas
