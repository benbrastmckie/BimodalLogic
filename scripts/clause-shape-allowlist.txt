# Clause-shape allowlist -- the companion file C37 (CLAUSE-SHAPE CHECK) reads.
#
# SHAPE (S), precisely. A definition contains Shape (S) when it has a subterm
#     ∀ x, R a x → (P ↔ Ψ(x))
# in which R is REFLEXIVE at the instantiated argument and P does NOT mention the bound x. Then
# the instance x := a makes the right side collapse to a function of a alone, and the whole
# biconditional degenerates: a clause of that shape quantifies over a relation and asserts
# nothing the reflexive instance did not already assert. That collapse was once landed and
# exploited in this tree -- a certificate condition type-checked for months while certifying
# nothing -- and it is why this file exists. The sliced class's two-regime liveness condition is
# a Finset equality, not a biconditional, and its box conditions' right-hand sides mention no
# bound position; both are listed below so their shape is re-affirmed on every run.
#
# WHAT THE MECHANICAL CHECK ASSERTS, AND WHAT IT DOES NOT. C37 enumerates every def/abbrev/
# structure/class under the three certificate roots (PlusWitnessFamily/, PlusSlicedCertificate/,
# WitnessFamily/) whose COMMENT-MASKED body contains a biconditional, so a `↔` in prose is not a
# hit. It asserts that every hit has a row here, that every row has a hit (a stale row is a
# FAIL), and that every row's anchor still resolves on the tree. It does NOT decide Shape-(S)
# membership: the VERDICT column is the recorded human judgement, made per clause, and the check
# never infers one. An unlisted hit therefore FAILS as "unreviewed biconditional clause", and the
# remedy is a reviewed row with a verdict and an anchor, never an exemption.
#
# VERDICTS.
#   INTENDED      the biconditional is the intended congruence or faithfulness clause: either both
#                 sides mention the bound variable (it IS the congruence), or the relation sits on
#                 the RIGHT side rather than as a guard, or the guard is total and the right side
#                 mentions no bound position
#   RESIDUAL      Shape (S) is LIVE here: a biconditional under a reflexive guard whose left side
#                 does not mention the bound variable. The row records a defect under separate
#                 repair. Flipping a RESIDUAL row to INTENDED requires the residue declarations
#                 named in its anchors to be GONE from the tree, and the anchors below are written
#                 so that removing either the reflexivity or the residue makes the row stale --
#                 a visible FAIL to update, never a silent pass
#   OUT-OF-SHAPE  the biconditional has no relational guard at all, or its guard mentions the
#                 formula on both sides; not an instance of (S)
#
# ADMISSION BAR. A new row needs a REASON ANCHOR that is a declaration name, a structure field
# name, a file-qualified name (`<path>#<name>`, resolved inside that file only), or a file path --
# never a task number or a specs/ path. Several anchors may be listed, comma-separated; ALL must
# resolve. The reason column is prose for the reader; the check does not parse it.
#
# ROW GRAMMAR, `|`-separated:
#   <path> | <declaration> | <clause, or -> | INTENDED|RESIDUAL|OUT-OF-SHAPE | <guard relation, or -> | <anchor(s)> | <reason>
