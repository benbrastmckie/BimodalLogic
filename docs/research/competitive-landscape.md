# BMLogic Competitive Landscape Report

**Dataset**: BMLogic (bmlogic-bench, bmlogic-c5, bmlogic-c7, proof_steps)  
**Prepared**: 2026-05-29  
**Version**: 1.0  
**Scope**: Formal logic, modal/temporal logic, and theorem proving benchmarks as of 2026-05

---

## Executive Summary

BMLogic datasets occupy a **unique niche** with no direct competitor: formal provability classification for a decidable **bimodal logic combining S5 modal and linear temporal operators**, with machine-verified labels, dual certificates (proof traces and countermodels), and six formula representations per record.

The closest competitor is LTLBench (2024), which covers only the temporal fragment (LTL) without S5 modal operators, provides no countermodel certificates, and is 27 times smaller by record count. NLP-oriented benchmarks (FOLIO, ProofWriter, PrOntoQA) target natural-language entailment and do not produce verified countermodels. Formal theorem-proving datasets (LeanDojo, miniF2F) target general mathematics rather than decidable logic classification.

**Primary strengths** (relative to field): only dataset with bimodal S5+LTL coverage; only dataset with machine-verified countermodels as negative certificates; only dataset with exhaustive complexity-bounded enumeration; six-representation schema enabling diverse training objectives.

**Primary gaps** (relative to field): smaller scale than ProofWriter/LeanDojo; no natural-language paraphrase layer; missing Croissant metadata and HuggingFace leaderboard scaffolding; no published LLM baseline calibration.

**Top enhancement priorities** (ordered): (R1) natural-language paraphrase augmentation, (R2) complexity tier extension to c9/c11, (R3) Croissant metadata and HuggingFace leaderboard Space, (R4) difficulty calibration against LLM baselines, (R5) cross-logic transfer splits.

## 2. BMLogic Dataset Characterization

### 2.1 Logic Domain

BMLogic covers **TM bimodal logic**, a decidable combination of:
- **S5 modal logic**: `□` (necessity), `◇` (possibility), with equivalence-class accessibility (reflexive, symmetric, transitive frame conditions)
- **LTL temporal logic**: `U` (Until), `S` (Since), with linear-order accessibility

This combination is decidable and has a complete Hilbert-style axiomatization verified in Lean 4. The bimodal language allows 12 operators: `atom`, `bot`, `top`, `neg`, `conj`, `disj`, `imp`, `box`, `dia`, `untl`, `snce`, and derived forms.

### 2.2 Task Format

**Binary provability classification**: each record is either `valid` (provable in TM) or `invalid` (has a countermodel). Both directions are certified:
- **Valid formulas**: JSON proof trace recording axioms, rule applications, and proof height
- **Invalid formulas**: JSON countermodel specifying `trueAtoms`, `falseAtoms`, and witness formula

Decision procedure is implemented in Lean 4 using verified algorithms. Labels are machine-generated by the Lean oracle and subsequently verified.

### 2.3 Formula Distribution

**Training data (c7, representative sample)**:
- Complexity 3–4: ~3.6% (simple)
- Complexity 5: ~26.2% (moderate)
- Complexity 6: ~70.2% (primary difficulty tier)
- Modal depth 0: 21%, modal depth 1: 72%, modal depth 2: 7%
- Temporal depth 0: 11%, temporal depth 1: 49%, temporal depth 2: 40%
- Valid fraction: 3.4% (accurate; bimodal formula space dominated by invalids)

**Benchmark (bmlogic-bench)**:
- Easy: 50 records (6.9%) — avg valid rate 6%
- Medium: 300 records (41.3%) — avg valid rate ~50%
- Hard: 262 records (36.0%) — avg valid rate ~50%
- Very Hard: 115 records (15.8%) — avg valid rate ~49%
- Valid fraction: 46.8% (stratified sampling; targeted inclusion of axiom instances)

**Anchor coverage**: 14 of 42 axiom constructors (33%) represented in benchmark anchors.

### 2.4 Multi-Representation Schema

The c5 and c7 training datasets use a 14-field schema providing six formula representations per record:

| Representation | Field | Format | Primary use |
|----------------|-------|--------|-------------|
| Human-readable | `formula_str` | Unicode string | Reading/display |
| JSON AST | `formula_ast` | Recursive JSON | Tree-based models |
| S-expression | `formula_sexpr` | Canonical prefix | Symbolic computation |
| Token list | `formula_tokens` | Array of strings | Transformer models |
| Pattern key | `pattern_key` | JSON object with named fields | Structural feature engineering |
| Feature vector | `pattern_features` | Numeric array (5 dims) | Value estimators, regression |

The benchmark dataset (bmlogic-bench) uses a 13-field schema (no `formula_sexpr`, `formula_tokens`, `pattern_features`, or `augmentation`).

## 4. Novelty Assessment

### 4.1 High-Novelty Dimensions

**1. S5 + LTL bimodal coverage**

No other benchmark covers the S5-modal + linear-temporal combination. This bimodal logic TM arises naturally in temporal epistemic reasoning (what is necessarily true at some point in time) and in computer-science verification (model checking with both modal and temporal properties). The gap is not covered by LTLBench (temporal fragment only), FOLIO/ProofWriter (propositional/FOL, no modal operators), or formal theorem-proving datasets (general mathematics). BMLogic fills a documented gap in the formal reasoning benchmark landscape.

**Evidence**: Survey of 13 benchmarks found zero with both `□`/`◇` (S5) and `U`/`S` (LTL) operators. FOLIO, ProofWriter, LogicNLI, PrOntoQA, FLUTE, ReClor, AR-LSAT, NaturalProofs, miniF2F, and INT contain no modal operators whatsoever. LeanDojo contains modal operators only as part of Lean's type theory (not as object-level logic operators). LTLBench covers `U`/`G`/`F`/`X` but no modal operators.

**2. Machine-verified dual certificates**

The combination of Lean 4-verified proof traces (for valid formulas) and machine-generated countermodels (for invalid formulas) is unique among evaluated benchmarks. Other datasets provide either proof traces or entailment labels, but not witnessed refutations with explicit counterstructures.

- ProofWriter provides proof chains in natural language (not machine-verified).
- LeanDojo provides Lean 4 tactic scripts (verified, but only for proofs, not counterexamples).
- miniF2F provides formal proofs where solved, but the dataset is unsolved problems — no countermodels.
- LTLBench uses NuSMV to verify labels externally but does not embed counterexamples in the dataset records.
- PrOntoQA provides chain-of-thought reasoning, not machine-verified proofs.

BMLogic is the only dataset where every negative record includes an explicit counterstructure (trueAtoms, falseAtoms, witness formula) embedded in the record JSON.

**3. Multi-representation schema (6 fields)**

Six representations per record (formula\_str, formula\_ast, formula\_sexpr, formula\_tokens, pattern\_key, pattern\_features) enables diverse training objectives from a single dataset without preprocessing: string processing, tree-based neural architectures, symbolic computation, transformer tokenization, feature engineering, and regression models. No competitor provides more than two formula representations (LeanDojo provides AST + tactic state).

**4. Exhaustive enumeration through complexity bound**

The c5 and c7 datasets achieve complete coverage of all bimodal formulas up to complexity 5 and 7 respectively. This provides statistical guarantees about the training distribution: no formula in the domain is systematically excluded. ProofWriter is sampled/synthetic; FOLIO is expert-curated samples; LeanDojo is the Mathlib corpus (whatever exists). Exhaustive coverage enables distribution-theoretic statements about model learning: a model trained to 100% accuracy on c7 has learned the complete decision procedure for all formulas up to complexity 7.

### 4.2 Moderate Novelty / Parity Dimensions

**Provability classification task (binary)**: Parity with LTLBench (satisfiability classification), but LTLBench covers only LTL and is 27x smaller by record count. FOLIO is 3-class (True/False/Unknown) entailment. No other benchmark uses binary provability classification in a modal-temporal logic.

**Stratified difficulty tiers**: Comparable to ProofWriter depth stratification (Depth 0–5) and INT operator-count tiers. BMLogic tiers use a richer metric — a combination of complexity, modal depth, temporal depth, and operator signature — which is more informative than single-axis depth. INT uses a 15-level scale based on operator count alone.

### 4.3 Gaps Relative to Competitors

**Scale**: 52K training records is modest compared to ProofWriter (500K), LeanDojo (122K+), and INT (generator-based, effectively unlimited). The exhaustive generation approach has inherent limits at higher complexity (c9 is feasible; c11 would require sampling).

**NLP accessibility**: No natural-language paraphrase layer means BMLogic is inaccessible to NLP/LLM pipelines that expect text input. All major NLP benchmarks (FOLIO, ReClor, AR-LSAT, FLUTE) and several formal benchmarks (ProofWriter, NaturalProofs, PrOntoQA) include natural language. This excludes BMLogic from the largest segment of the LLM evaluation ecosystem.

**LLM baseline calibration**: No published LLM accuracy figures on bmlogic-bench, so the community cannot gauge difficulty relative to current models. INT, LeanDojo, miniF2F, and ReClor all have published baselines.

**Discoverability**: No Croissant metadata, no HuggingFace leaderboard Space. The HF README uses `task_categories: text-classification` and `task_ids: multi-class-classification` which do not accurately describe formal logic provability. No benchmark in the comparison set has Croissant metadata (as of 2026-05), but this is changing rapidly as MLCommons adoption accelerates.

**Proof step coverage**: The proof\_steps dataset covers only 36 theorems, with a rule distribution dominated by axiom application (1,220 steps) and modus\_ponens (1,184 steps). Temporal rules are underrepresented: only 12 necessitation steps, 7 temporal\_duality steps, and 1 temporal\_necessitation step. This suggests the current theorem selection is biased toward propositional provability.

## 5. Enhancement Roadmap

### Overview

Seven enhancement recommendations are organized into three tiers by priority. All recommendations are additive and backward-compatible with existing datasets.

| ID | Recommendation | Priority | Effort | Impact |
|----|---------------|----------|--------|--------|
| R1 | Natural-language paraphrase augmentation | High | Large | Very High |
| R2 | Complexity tier extension to c9/c11 | High | Large | High |
| R3 | Croissant metadata + HF leaderboard Space | High | Small | High |
| R4 | LLM baseline difficulty calibration | Medium | Medium | High |
| R5 | Cross-logic transfer splits | Medium | Small | Medium |
| R6 | Anchor coverage expansion | Low–Medium | Medium | Medium |
| R7 | Proof step dataset expansion | Low | Large | Medium |

### R1: Natural-Language Paraphrase Augmentation

**Priority**: High  
**Effort**: Large (estimated 2–4 weeks, includes human review)  
**Impact**: Very High (opens dataset to NLP/LLM evaluation ecosystem)  
**Dependencies**: None (additive `nl_paraphrase` field)

**Description**: Add an `nl_paraphrase` field to bmlogic-bench and a target subset of c7 records containing a natural-language rendering of each formula. Examples:
- `□(p → q)` → "It is necessary that if p then q"
- `U(p, q)` → "p is true until q becomes true"
- `□(p → ◇q) → (p → □◇q)` → "If it is necessary that p implies possibly q, then if p holds then necessarily p will possibly become q"

**Acceptance criteria**:
- All 727 bmlogic-bench records have a non-null `nl_paraphrase` field
- Paraphrases are grammatically correct for depth ≤2 (rule-based) and human-spot-checked for depth ≥3
- A separate `nl_paraphrase_method` field records generation method (`rule_based` or `llm_assisted`)
- Backward compatibility: `nl_paraphrase` is an optional field; parsers reading existing fields are unaffected

**Suggested approach**: Rule-based generation for formulas with `modalDepth + temporalDepth ≤ 2` (covers ~75% of benchmark by depth distribution); GPT-assisted with human verification for complex nesting (depth ≥3).

**Risk**: Systematic errors in rule-based NL generation (e.g., scope ambiguity in nested operators). Mitigated by: separate `nl_paraphrase_method` field, spot-checking, and publishing generation code.

### R2: Complexity Tier Extension to c9/c11

**Priority**: High  
**Effort**: Large (requires Lean 4 oracle compute; c9 feasible; c11 requires sampling)  
**Impact**: High (creates harder benchmark for future LLM evaluation; addresses scale gap)  
**Dependencies**: Lean 4 environment and dataset generator (available in this repo)

**Description**: Extend exhaustive enumeration to complexity 9 and 11:
- `bmlogic-c9.jsonl`: Exhaustive (if feasible) or stratified-sampled coverage of complexity ≤9. Estimated ~300K–800K records.
- `bmlogic-c11.jsonl`: Stratified-sampled coverage of complexity ≤11. Estimated ~500K–2M records (sampling required).

**Acceptance criteria**:
- c9 dataset contains at least 50K records with complexity 8–9 formulas
- Formula schema is compatible with c5/c7 (14 fields)
- Benchmark slice "very_hard+" added with 100+ records at complexity 8–9
- `max_temporal_depth` and `max_modal_depth` added as first-class filter fields in benchmark schema

**Risk**: Exhaustive enumeration at c9 produces intractably large files. Mitigated by: stratified sampling with complexity-proportional rates; keeping exhaustive only for c9, sampling for c11.

### R3: Croissant Metadata and HuggingFace Leaderboard Space

**Priority**: High  
**Effort**: Small (estimated 2–4 hours for metadata; 1–3 days for Gradio Space)  
**Impact**: High (dramatically improves discoverability and community adoption)  
**Dependencies**: HuggingFace dataset repository access

**Description**: Two sub-components:

*3a. Croissant metadata*: Create `croissant.json` per the MLCommons 1.0 specification. Include:
- Dataset-level: name, description, URL, license (MIT), citation, creators
- Distribution entries for each JSONL file
- Record-level field descriptions with semantic types
- Task description (formal-provability-classification) with evaluation metrics (accuracy, F1)

*3b. HuggingFace README update*: Change `task_categories` to `["text-generation", "other"]` with `task_ids: ["formal-provability-classification"]`. This surfaces BMLogic in HF dataset search for formal reasoning.

*3c. HuggingFace Space (optional; separate task)*: Gradio app that accepts a formula string, calls the Lean oracle (via subprocess), and returns the label plus proof or countermodel. Serves as interactive demo and live leaderboard submission endpoint.

**Acceptance criteria (3a + 3b only)**:
- `data/croissant.json` is valid JSON and parseable by MLCommons tooling
- All four JSONL datasets are listed as distributions
- Field descriptions match actual schema
- HF README `task_categories` is updated

### R4: LLM Baseline Difficulty Calibration

**Priority**: Medium  
**Effort**: Medium (estimated 3–5 days including API costs and analysis)  
**Impact**: High (makes the benchmark actionable; enables community comparison)  
**Dependencies**: API access to GPT-4o, Claude Sonnet, Llama-3

**Description**: Run bmlogic-bench through several LLMs to establish baseline difficulty:
- Zero-shot accuracy per difficulty tier (easy / medium / hard / very\_hard)
- Chain-of-thought vs. direct label accuracy
- Error rate correlation with modal depth and temporal depth
- Publish results in a `baselines/` directory alongside the dataset

**Acceptance criteria**:
- At least 3 LLM baselines evaluated (recommended: GPT-4o, Claude Sonnet, a 7B open model)
- Results reported per tier and overall
- Random baseline included (50% for balanced benchmark)
- Results published in `data/baselines/README.md` with methodology

### R5: Cross-Logic Transfer Splits

**Priority**: Medium  
**Effort**: Small (estimated 2–4 hours)  
**Impact**: Medium (enables transfer experiments; enables comparison with FOLIO and LTLBench)  
**Dependencies**: None (metadata only; no new data generation)  
**Status**: Implemented — see `data/bmlogic-bench-splits.json` and `data/scripts/generate_splits.py`

**Description**: Define explicit sub-slices of bmlogic-bench by logic fragment:
- `propositional-only`: `modalDepth == 0 && temporalDepth == 0`
- `modal-only`: `temporalDepth == 0 && modalDepth > 0`
- `temporal-only`: `modalDepth == 0 && temporalDepth > 0`
- `bimodal`: `modalDepth > 0 && temporalDepth > 0`

These sub-slices enable:
- Cross-logic transfer experiments (train on propositional → test on bimodal)
- Direct comparison with FOLIO (propositional reasoning sub-slice)
- Direct comparison with LTLBench (temporal-only sub-slice)
- Fine-grained difficulty analysis by logical fragment

**Acceptance criteria**:
- All 727 bmlogic-bench records assigned to exactly one slice
- Each slice contains at least 10 records
- Split metadata published in `data/bmlogic-bench-splits.json`

### R6: Anchor Coverage Expansion

**Priority**: Low–Medium  
**Effort**: Medium (estimated 1–2 weeks; requires Lean oracle)  
**Impact**: Medium (improves semantic completeness of the benchmark)  
**Dependencies**: benchmark\_anchors executable in the Lean 4 project

**Description**: Current anchor coverage is 14 of 42 axiom constructors (33%). Expand to cover all 42 axiom constructors with at least 3 instances each (target: 126+ anchor records). This ensures all TM axiom patterns are explicitly evaluated in the benchmark.

**Acceptance criteria**:
- At least 3 instances of each of the 42 axiom constructors in bmlogic-bench
- Total anchor records: ≥126 (vs. current 78)
- Overall benchmark size may grow to 800–900 records
- No regression in existing record labels

### R7: Proof Step Dataset Expansion

**Priority**: Low  
**Effort**: Large (requires Lean proof authoring or extraction for 200+ theorems)  
**Impact**: Medium (enables step-level proof model training)  
**Dependencies**: Lean 4 `proof_extractor` executable

**Description**: Current proof\_steps covers 36 theorems with a rule distribution biased toward axiom application (50%) and modus\_ponens (49%). Expand to 200+ theorems to:
- Provide more varied proof structures
- Increase temporal rule coverage (necessitation, temporal\_duality, temporal\_necessitation)
- Enable training of step-level proof models for the bimodal fragment

**Acceptance criteria**:
- At least 200 unique theorems in proof\_steps
- Temporal rules (necessitation, temporal\_duality, temporal\_necessitation) represent at least 10% of steps
- Record format is backward-compatible with current 8-field schema

## 7. Positioning Statement

BMLogic occupies a structurally distinct position in the formal reasoning benchmark landscape: it is the first and only dataset targeting provability classification for a **decidable bimodal logic** combining S5 modal necessity and linear temporal Until/Since operators. While existing benchmarks have explored propositional logic (ProofWriter, PrOntoQA), first-order logic (FOLIO, LogicNLI), linear temporal logic (LTLBench), and formal mathematics (LeanDojo, miniF2F), none has addressed the S5+LTL combination that arises naturally in temporal epistemic reasoning and multi-agent verification. This combination is not a mere curiosity: it represents the logical core of many real-world specifications (e.g., "necessarily, if an agent knows a fact then eventually the fact will be publicly known").

The dual-certificate design — Lean 4-verified proof traces for valid formulas, machine-generated countermodels for invalid formulas — gives BMLogic a unique epistemological property: every label is witnessed, not just verified. A model trained on BMLogic that achieves high accuracy is not merely learning a statistical pattern; it is learning to classify inputs that have been independently certified as valid or invalid by a formal proof system. This has direct implications for using BMLogic as a training signal for formal verification tools, proof-search heuristics, and reasoning-capable large language models.

The six-representation schema (formula\_str, formula\_ast, formula\_sexpr, formula\_tokens, pattern\_key, pattern\_features) is designed to support the full research spectrum from symbolic AI to neural networks. Researchers working with tree-structured neural networks, graph networks, transformers, classical feature engineering, or hybrid neuro-symbolic architectures can all use the same dataset without preprocessing. The exhaustive enumeration property (complete coverage of all bimodal formulas up to a complexity bound) provides clean theoretical guarantees: a model trained to accuracy on c7 must generalize to unseen higher-complexity formulas to be considered truly capable, rather than having memorized the training distribution. For researchers seeking a benchmark where "solving" has a precise mathematical meaning, BMLogic provides a uniquely clean target.
